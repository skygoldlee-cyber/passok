# ADR-0010: 레거시 잔재는 기준선 래칫으로 관리 — 단조 감소만 허용

> **문서 ID**: DOC-ADR-10
> **범위**: platform · 판본: none
> **관련 SPEC ID**: 해당 없음 (게이트 정책 — WHEN_THINGS_BREAK §5)
> **상태**: accepted (2026-10-14 — 사후 백필)

## 상황 (Context)

신규 규약을 도입할 때 기존 코드에 위반이 수십~수백 건 잔존한다(예: 미이스케이프
싱크 78건, 정적 인라인 스타일 145건, U+FFFD 잔재). "전부 정리 후 게이트 도입"은
정리 완료 전까지 신규 유입을 막지 못하고, "경고만"은 무시된다.

## 결정 (Decision)

위반 잔재를 기준선 파일(`tools/state/*_baseline.json` 또는 체커 내 상수)로
스냅샷하고 **단조 감소만 허용**한다 — 신규 유입·개수 초과는 즉시 실패,
잔재는 `--update`/`--stamp` 계열로만 하향 갱신한다. 기준선이 0이 되면
하드 게이트가 된다 (check:escape 78→0, check:enc FFFD→0이 선례).

## 대안 (Alternatives considered)

- **일괄 정리 후 게이트 도입**: 기각 — 정리 기간 중 신규 유입 무방비
- **경고 수준 유지**: 기각 — 경고는 누적되고 무시됨 (`lint --max-warnings 0`
  채택도 같은 판단)
- **diff-스코프만 검사(변경 파일 한정)**: 병용 — `--ref`는 신규 유입 검사를
  변경 파일로 축소하지만, 잔재 상한은 여전히 기준선이 담당

## 결과 (Consequences)

- 기준선 상향(숫자가 커지는 diff)은 회귀 은폐의 전형 — WHEN_THINGS_BREAK §5가
  "정당한 리셋" 판정 순서를 규정
- 커버리지는 역방향 래칫(`ratchet:coverage` — 실측−0.8%p로 단조 증가 상향)
- 기준선 파일 변경 자체가 리뷰 단서가 되어 "조용한 완화"를 방지
