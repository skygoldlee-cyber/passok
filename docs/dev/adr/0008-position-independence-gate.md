# ADR-0008: 위치 좌표(라인·인덱스)의 식별자 사용 금지

> **문서 ID**: DOC-ADR-08
> **범위**: platform · 판본: none
> **관련 SPEC ID**: ID-05 (회귀 방지 대상: AN-10, TR-27)
> **상태**: accepted (2026-10-14 — 사후 백필, 게이트 신설일 2026-10-12)

## 상황 (Context)

교재 라인 번호·섹션 인덱스·스크롤 위치를 식별자나 영속 키로 쓰면 콘텐츠
편집 한 번에 참조가 대량 드리프트한다 — 인용 라인번호 어긋남으로
수백 건 단위 재동기화가 필요했던 사고가 반복됐다(CHANGES: 라인 갱신
655건+대상 재지정 129건 등). AN-10(§앵커)·TR-27(콘텐츠 북마크 키)으로
결함 유형을 제거했으나 재도입 통로가 열려 있었다.

## 결정 (Decision)

위치 좌표(라인 번호·`*Idx`/`index`·`lineNo`·`scrollTop` 변수)를 식별자·
키 lvalue·영속 저장 키 인자로 쓰는 패턴을 `check:posind`가 오류로 차단한다.
표시층 `#L` 링크·인용 텍스트·세션 캐시 등은 사유 기재 허용 목록으로만 면제.

## 대안 (Alternatives considered)

- **규약 문서 + 리뷰**: 기각 — 동일 결함이 문서화 후에도 재유입됨 (ADR-0009 패턴)
- **식별자를 content-hash로 전면 전환**: 기각 (사후 추론 — 이력 미기록). 콘텐츠 해시는
  내용 편집 한 번에 모든 해시가 바뀌어, 위치 좌표와 동일한 대량 드리프트를 식별자
  계층에서 재현한다. §앵커(섹션 경로·제목 기반 구조 좌표)는 문장 편집에는 불변이면서
  구조 재편 시에만 바뀌어, 드리프트를 "실제 의미 변경" 발생 시점으로 좁힌다
- **라인번호 동기화 도구로 사후 교정만**: 기각 — 교정 비용이 반복 누적됨.
  `sync:citations`은 표시층 교정으로 남기고 식별자 계층은 원천 차단으로 분리

## 결과 (Consequences)

- 콘텐츠 북마크·진도는 §앵커/콘텐츠 키 기반 — 교재 재편에도 식별자 불변
- `check:posind`는 pre-push·check:ci·CI 전 단계에 편입, `--ref` diff 스코프 지원
- 계층 방향 규칙(코어→views/ 역참조 차단, SHELL_MODULES 명단)도 같은 게이트가 담당
