# ADR-0009: 규약의 기계 강제 — 문서 규약은 게이트로 변환한다

> **문서 ID**: DOC-ADR-09
> **범위**: platform · 판본: none
> **관련 SPEC ID**: 해당 없음 (공학 방식 결정 — GATE_MAP §1, CODE_CONVENTIONS §8)
> **상태**: accepted (2026-10-14 — 사후 백필)

## 상황 (Context)

CODE_CONVENTIONS §4의 규약(인라인 스타일 금지·localStorage 직접 접근 금지 등)이
문서로만 존재할 때 위반이 반복 유입됐다. AI 에이전트·미래 기여자·본인 모두가
문서를 읽지 않고도 커밋할 수 있으므로, "읽어야 지켜지는 규약"은 구조적으로
부패한다.

## 결정 (Decision)

새 규약의 기본값은 **"체커로 만들 수 있는가"를 먼저 묻는다**: 가능하면
`tools/check/` 단계로 기계화하고, 불가능할 때만 ADR·문서로 남긴다.
실행 층은 4층 — pre-commit → pre-push(적응형 선별) → CI → deploy 가드
(`tools/check/run.js` 실행기 + `steps.js` 단계 레지스트리가 단일 선언부).

## 대안 (Alternatives considered)

- **리뷰 체크리스트·컨벤션 문서만**: 기각 — 위반 재유입 이력이 반복 근거
- **CI에서만 검사**: 기각 — 피드백이 푸시 이후로 늦어짐. pre-commit은 IDE 수준
  오류를 즉시 차단해야 리턴 비용이 최소
- **기존 린터 프리셋으로 통합**: 기각 — 도메인 규약(위치 좌표 식별자·feature flag
  정합·문서↔코드 동반·생성물 신선도)은 ESLint 규칙으로 표현 불가하며, 이 프로젝트는
  git 상태·파일시스템·생성물 비교를 넘나드는 게이트가 핵심이다. 범용 프레임워크에
  맞추면 규약 표현력이 도구의 표현력으로 축소된다 (결정 근거로부터의 정합 추론 —
  비교 검토 이력 미기록)

## 결과 (Consequences)

- 체커 60+개·`tools/` ~19k LOC — 게이트 유지 비용이 앱 코드의 절반 규모.
  이 비용이 이 결정의 대가이며, `WHEN_THINGS_BREAK.md` §4~5가 우회·기준선
  갱신의 규약을 별도 관리한다
- 신규 게이트 추가 규칙은 GATE_MAP §4 — "실패 가능성이 구체적일 때만"
- 우회구(SKIP_*·`[no-docs]`·`[no-test]`·라인 토큰)는 의도된 압력 밸브 —
  기록만 남으면 허용
