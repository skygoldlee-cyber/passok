## 1. 배경·목적

### 1.1 역할 분리 — FSRS와 다른 질문

FSRS는 "카드 하나가 언제 잊히는가"를 예측한다 (복습 **시점** 관리). 학습 진단의 "단원 취약·합격 갭"이 묻는 것은 다른 질문이다 — "이 단원의 개념을 얼마나 숙달했는가" (숙달 **정도** 추정). 현재 진단은 휴리스틱 집계에 의존한다.

### 1.2 현재 추정의 세 한계

- **정답 근거 부재**: `_aggregateChapterWrongs`는 오답 수만 센다 — 정답 시도를 세지 않으므로 "30회 중 5오답 단원"이 "1회 1오답 단원"보다 나쁘게 보인다. 정답률이 아니라 오답 빈도의 순위다.
- **소표본 노이즈**: 시도 1~2회 단원의 정답률은 0%·100% 극단으로 튄다 — 순위가 증거 없이 흔들린다.
- **찍기·실수 미분리**: 5지선다의 찍기 정답과 숙달 후 실수 오답이 같은 판정으로 섞인다.

### 1.3 추적 축 결정 — 단원(chapter)

`conceptId`는 개념 분류가 아니다 — 수작업 `combo_pilot`의 진짜 개념 그룹은 16개뿐이고, 자동 생성 `combo_subject*`의 `conceptId`는 `"q:subjectN_qNN"` 원문항 출처 ID다. 반면 **단원 귀속은 전 증거 경로가 커버**된다:

| 증거 경로 | 단원 귀속 |
|---|---|
| 퀴즈·모의고사 정오 (`quizResults`) | `QUESTION_CHAPTERS` / `resolveQuiz().quiz.category` |
| OX·ㄱㄴㄷ 진술 판정 (`statement_stats`) | `cid`(§앵커·레거시 L####→`CID_SECTION` 환산) → 단원명 |
| 시뮬 약점 카드 (`weak_sim_*`) | 문항id → `QUESTION_CHAPTERS` |

개념 분류 체계 확장(콘텐츠 생성기에 의미 개념 부여)은 콘텐츠 파이프라인 작업 — 선행 후 개념 단위 KT로 재검토한다 (§5).

### 1.4 목표·비목표

- **v1 (D-21)**: 단원별 정오 증거를 Beta 사후평균으로 추정해 소표본 노이즈를 제거 — 진단 카드의 순위 품질 개선.
- **v2 (D-22)**: 단원별 BKT로 숙달 확률 P(known) 추적 — slip/guess 분리로 v1의 잔여 한계 해소.
- **비목표**: FSRS 스케줄링 침범(시점 관리는 그대로) · 개인 파라미터 피팅(시험별 기본값, 단일 사용자 한계 명시) · conceptId 체계 확장(콘텐츠 파이프라인 후속) · 카드 자기평가를 숙달 증거로 사용(§2.1).

## 2. 증거 모델

### 2.1 증거 정의

단원 숙달 증거 = **채점 가능한 정오 판정**만 사용한다:

| 경로 | 증거 | 단원 귀속 | 비고 |
|---|---|---|---|
| 퀴즈 문항 정오 | `quizResults[id].correct` | `resolveQuiz`→`quiz.category` / `QUESTION_CHAPTERS` | 현재 마지막 판정만 저장 — v1은 충분, v2는 §3.2 |
| 진술 판정 | `statement_stats[sid].{j,w}` — j회 중 w회 오판 | `cid` → 단원 | OX·ㄱㄴㄷ 공용, 정답 근거(j−w) 존재 |
| 시뮬 약점 카드 | `weak_sim_*` 오답 | 문항 → `QUESTION_CHAPTERS` | 오답 증거만 (기존과 동일) |

**제외**: 카드 자기평가(외움/헷갈림) — 자기보고 이진값이라 채점 증거가 아니며 이미 FSRS가 소비. FSRS 스케줄 데이터(d·s)도 숙달 추정에 직접 사용하지 않는다 — 모델 독립성 유지.

### 2.2 증거 집계 계층

신규 순수 함수 `computeUnitEvidence(p)` (analysis-engine 또는 별도 모듈): 기존 `_aggregateChapterWrongs`의 귀속 로직(세 경로)을 확장해 **오답뿐 아니라 정오 건수 모두**를 단원 버킷으로 집계한다.

```js
// `${subj}|${chapter}` → { subject, chapter, attempts, corrects, wrongs }
```

- (a) `quizResults` 전건: correct=true도 카운트 (기존은 오답만)
- (b) `weak_sim_*`: 오답 증거로 카운트 (기존과 동일)
- (c) `statement_stats`: `attempts += j`, `corrects += j−w`, `wrongs += w` — 졸업 진술(`streak ≥ 3`)도 **과거 증거로는 유효**하므로 집계에 포함 (현행 약점 집계의 졸업 제외 규칙과 차이 — 숙달 추정에서는 졸업=강한 숙달 증거이므로 정답으로 반영하는 것이 정합)

## 3. 추정기

### 3.1 v1 — Beta 사후평균 (D-21)

단원별 정답률을 `Beta(α₀+corrects, β₀+wrongs)` 사후평균으로 추정한다:

```
P_unit = (α₀ + corrects) / (α₀ + β₀ + corrects + wrongs)
```

- **사전**: `α₀ = 4, β₀ = 3` (합격선 ~60%를 중심으로 한 약한 사전 — 약 7회 증거분의 무게. 시험별 조정은 manifest `study.kt.prior` 확장으로 유보)
- **효과**: 증거 1~2건 단원은 사전 쪽으로 당겨져 극단 0%·100% 순위를 방지, 증거 20+ 건은 실측에 수렴
- **소비자**: `computeSubjectWeakChapters`/`computeChapterWeakness`의 정렬 기준을 `wrongs` → `P_unit` 오름차순으로 교체(기존 `wrongs` 필드는 표시용 유지), `computePassGap` 퀴즈 폴백 경로의 과목 정답률도 동일 스무딩 적용 여부 검토
- **변경 폭**: 집계 확장 + 정렬 기준 교체 + 표시 문구("오답 N회" → "숙달 추정 M%") — 진단 카드의 **행동·위치 불변, 순위 품질만 개선**

### 3.2 v2 — BKT (D-22)

단원별 은닉 숙달 상태 `P(L)`를 관측 시퀀스로 갱신한다:

```
관측 후:  P(L|o) = P(L)·(1−S)/[P(L)·(1−S)+(1−P(L))·G]      (정답)
         P(L|o) = P(L)·S/[P(L)·S+(1−P(L))·(1−G)]           (오답)
전이:    P(L) ← P(L|o) + (1−P(L|o))·T                      (학습률)
```

- **파라미터** (시험별 기본값, `manifest.study.kt` 오버라이드 허용):
  - `P₀` 초기 숙달 = 0.30 (콜드스타트 중립)
  - `T` 기회당 학습률 = 0.08 (복습형 재노출 가정)
  - `G` 추측 = 0.15 (5지선다 근사; OX 진술은 0.30 — 이진 판정의 추측 여지 반영, 경로별 G 분리)
  - `S` 슬립 = 0.10
- **시퀀스 요구**: BKT는 관측 **순서**가 필요하다 — 현재 `quizResults`는 최종 판정만 보존해 시퀀스 불가. v2 선행 조건으로 **판정 로그를 확장**한다: D-18 리뷰 로그의 진술 레코드(`{c,r,e,t}`)는 시퀀스를 이미 보유하고, 퀴즈 판정은 별도 compact 로그(`fc_judgment_log` 또는 기존 로그에 `k:'q'` 타입 구분 확장)를 추가한다 — 스키마 결정은 구현 설계 시점에.
- **망각 비모델 명시**: BKT는 관측 간 학습률만 갱신하고 시간 감쇠가 없다 — "현재 숙달 스냅샷" 용도로 한정하고, 시점 관리는 계속 FSRS에 둔다 (역할 분리가 본 설계의 전제).
- **소비자**: 단원 `P(L)`을 취약 랭킹·합격 갭에 사용 (낮은 순). 표시는 "숙달 추정 M%". 졸업 기준 `P(L) ≥ 0.9`는 전통적 BKT 관례.
- **v1과의 관계**: v2는 v1의 대체가 아니라 정밀화 — v1의 증거 집계 계층(`computeUnitEvidence`+로그)을 그대로 입력으로 쓰며, 추정기만 Beta→BKT로 교체. v1이 데이터·소비자 통로를 먼저 만든다.

## 4. 구현 계획

### 4.1 v1 (D-21)

1. `computeUnitEvidence` 순수 함수 — 정오 건수 단원 집계 (§2.2)

3. 테스트: 소표본 스무딩(1오답 단원이 30시도 5오답 단원보다 나쁘게 보이지 않음)·졸업 진술 정답 반영·기존 랭킹 회귀
4. SPEC D-21 ✅·CHANGES·TRACE

### 4.2 v2 (D-22) — 착수 순서 (확정)

**① 판정 시퀀스 로그 확장** — BKT는 관측 순서가 필요한데 `quizResults`는 최종 판정만 보존한다. 두 안:

| 안 | 스키마 | 평가 |
|---|---|---|
| A. 기존 `fc_review_log` 확장 | `{c, r, e, t}`에 `k` 타입 필드 추가(`'s'` 진술·`'q'` 퀴즈·`'c'` 카드) | 단일 로그로 시퀀스 통합 — 복원·동기·FIFO 정합 자동 승계. 단 스키마 확장이므로 기존 레코드와의 후방 호환(k 없으면 기존 의미) 설계 필요 |
| B. 별도 `fc_judgment_log` | 퀴즈 판정 전용 `{q, ok, t}` 링버퍼 | 로그 분리로 기존 소비자 무영향 — 단 키·상한·백업 등록 중복 |

**기본 안은 A** — BKT 입력이 "시간순 정오 시퀀스"이므로 단일 시계열이 자연스럽고, 카드·진술 레이팅도 이미 같은 로그에 있어 혼합 시퀀스가 공짜다.

**①-a 스키마 확정 (2026-10-13, 안 A 채택)**:

```js
{c: 문항 id, k: 'q', ok: 1|0, t: unix ms}   // 퀴즈·시뮬 문항 판정 — recordQuizJudgment()
{c, r, e, t}                                // 스케줄 이벤트 (기존) — k 없음 = 레이팅 레코드
```

- 기입점: `views/quiz.js`의 `quizResults` 기록 2곳(텍스트·선택지 채점) + `exam-sim-arena.js` `submitExam` 루프(문항 단위 전건). ㄱㄴㄷ 진술 판정은 기존 경로(`recordStatementJudgments`→`updateCardSchedule`)로 이미 유입 — 문항·진술 이중 계수는 소비자가 `k` 필터로 선택
- 후방 호환: `k` 없는 레코드는 스케줄 이벤트로 해석 — `getReviewLog()`·FIFO·백업 무수정
- 비기입 영역: 시뮬 `weak_sim_*` 오답 카드는 별도 증거 경로로 유지 (§2.1)

**② `knowledge-tracing.js` 순수 모듈** — `bktUpdate(pL, correct, {T,G,S})` · `computeUnitMastery(sequence)` (단원 귀속은 D-21의 `computeUnitEvidence` 귀속 경로 재사용). DOM·저장 비의존 순수 함수.

**③ 파라미터·소비자 연결** — manifest `study.kt` `{P0, T, G:{mcq, ox}, S}` 오버라이드(기본값 §3.2), 취약 랭킹·합격 갭의 추정치를 Beta → `P(L)`로 교체(표시 문구 "숙달 M%" 유지), 졸업 기준 `P(L) ≥ 0.9`.

**④ 검증** — 골든 수열 테스트(정답 연속→P(L) 상승·오답→감소·T에 의한 점진 회복), 시퀀스 없을 때 v1 폴백, 감사 시나리오 추가.

**v2 전까지 병행 가능한 후속**: T4 계측 기반 목표 R 재판정(EXAM_DUE_CLAMP §5) — D-20 클램프의 시험일 R 회복 효과를 감사 시뮬로 계측해 목표 R 간격 단축 필요 여부를 종결한다.

## 5. 후속 (명시적 보류)

- **conceptId 개념 분류 확장**: 콘텐츠 생성기가 `q:...` provenance 외에 의미 개념을 부여하도록 확장 후 개념 단위 KT 재검토.
- **시간 감쇠 BKT 변형**: 관측 간 경과일을 전이 확률에 반영하는 변형 — 기본형 안정화 후 검토.
- **개인 파라미터 피팅**: 로그 축적 후 T·S 추정 — FSRS 피팅과 동일 선행 조건.
- **합격 갭 연동 심화**: 단원 P(L)을 과목 점수 추정에 가중 평균으로 반영 — v2 착지 후 SC-14 개정 검토.
