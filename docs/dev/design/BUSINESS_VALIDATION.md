## 0. 원칙

1. **구현됨 ≠ 검증됨** — 코드·게이트가 존재해도 사용자 데이터로 확인되기 전까지 모든 우위 주장은 **가설**로 표기한다.
2. **판정 기준은 실험 전에 확정한다** — 결과를 본 뒤 기준을 바꾸지 않는다. 미확정 수치는 `TBD`로 두되 **확정 기한**을 반드시 붙인다.
3. **진입 조건을 명시한다** — 각 단계는 앞 단계 결과에 의존한다. 조건 미충족 시 다음 단계로 넘어가지 않는다.
4. **구매 의향 ≠ 결제** — 설문·대기열 등록은 별도 지표로 분리한다.

## 5. 설계 결정 (ADR 필요)

### 5.1 이벤트 수집 — Local-First·의존성 0 원칙과의 충돌

이벤트 수집은 기존 원칙의 예외이므로 ADR로 결정·기록한다. 기존 `usage-telemetry.js`(실행당 `session_id`·영속 식별자 없음)를 확장하는 방향으로 위치를 정의하고, 아래 권장 사항을 적용한다:

- **1st-party 경량 엔드포인트**(Vercel/Supabase Function) — 서드파티 분석 SDK 미도입으로 런타임 의존성 0 유지
- **익명 설치 ID**(localStorage 난수) — 기존 세션 UUID와 병존: 설치 ID=고유 사용자 추정용, 세션 ID=실행 단위. 로그인 시 계정과 연결, 비회원은 기기 단위 식별 한계를 문서화
- **이벤트 화이트리스트** — 정의된 이벤트만 전송, 학습 내용·메모 등 콘텐츠 미전송
- **동의 UX** — 최초 실행 시 고지·거부 가능, 거부 시 기능 제한 없음
- 오프라인 시 로컬 큐 → 온라인 복귀 시 배치 전송

> **구현 현황 (2026-10-22, ADR-0019·UX-MET-06~08)**: opt-out 동의(`telemetry_opt_out` + 설정 토글 + 최초 고지 토스트)·설치 ID(기존 `device_id`를 `meta.install_id`로 전송 — 별도 ID 신설 대신 재사용)·화이트리스트(`ALLOWED_EVENTS`)·오프라인 큐(`telemetry_queue`, 상한 200)가 구현됐다. 퍼널 이벤트는 `session_start`(방문 분모)·`core_learning_action`(핵심 학습 행동 — VALUE_ACTIONS 액션 발생 시)로 확장됐다. 신규 결정 사항은 ADR-0019에 기록한다.

### 5.2 결제 — 실험 단계와 정식 단계 분리

| 단계 | 방식 | 권한 검증 |
|------|------|-----------|
| 실험 (P2) | 결제 링크 + 라이선스 코드 수동/반자동 발급 | 코드 → 서버 검증 1회 → 계정 귀속 |
| 정식 (P4 이후, H1 성공 시) | PG 연동 구독 | 서버 권한 · 웹훅 멱등 · 만료/해지/환불/결제실패 상태 구분 |

공통 원칙: `pro_entitled` 등 로컬 값은 표시용 참고만, 실제 권한은 서버. **Pro = 계정 동기화 포함**으로 묶어 유료 사용자의 로컬 유실 리스크를 제거하고, 학습 기록(로컬 중심)과 결제 권한(서버 중심)의 분리를 유지한다.
