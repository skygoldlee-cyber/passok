# 오답 원인 자동 분류 설계 — 임베딩 센트로이드 기반 추정기

> 상위 문서: [SPEC](../SPEC.md) §3.1.5(AN-07, AN-02, AN-09)
> **범위**: platform · 판본: none
> **상태**: 설계 검토 (미구현 — 본 문서의 경로·API는 제안이며 아직 존재하지 않는다)
> **관련 SPEC ID**: `AN-07`(오답 원인 분류) · `AN-02`(진단 요약) · `AN-09`(주간 리포트) · `DA-05`(로컬 저장) · `DA-08`(피처 플래그)
> **선행 의존**: DOC-DSN-18 (임베딩 벡터 번들 — 본 설계의 분류 입력)
> **문서 ID**: DOC-DSN-19

## 1. 배경·목적

`estimateUntaggedCauses`(src/analysis-engine.js)는 사용자가 원인을 태그하지 않은 오답에 정규식 기반으로 원인을 귀속한다:

1. manifest `wrongCauses[].autoPattern` 정규식 히트 → 선언된 확장 키
2. 정답이 수치 → `numeric`(선언 시) 또는 `calc`
3. 발문이 부정형("아닌/틀린/옳지 않은 것") → `concept`
4. 나머지 → `memorize`

한계가 구조적이다 — **문항의 "형식"으로 원인을 추정하지 사용자가 왜 틀렸는지를 보지 않는다**:

- 부정형 문항을 암기 부족으로 틀려도 무조건 `concept`으로 귀속 (규칙 3이 무조건 발동).
- 계산 문항인데 상수·공식 자체를 몰라 틀려도 `calc`로 귀속 — "암기해야 할 수치를 몰랐다"와 "계산 절차를 틀렸다"를 구분 못 함.
- 선택한 오답 선지·인용 근거 텍스트는 입력에 없다 — 같은 문항이라도 "비슷한 수치를 골랐는가, 무관한 개념을 골랐는가"가 원인의 핵심 단서인데 미사용.

사용자 수동 태그(`wrongCauses`)는 정확하지만 태깅률이 낮으면 오답 패턴 카드(AN-02)·주간 리포트(AN-09)가 추정값에 크게 의존한다.

**목표**: 미태깅 오답에 대해 규칙보다 정확한 추정 원인을 **확신도와 함께 제안**한다. 사용자 태그는 항상 우선(authoritative)이며, 본 기능은 추정 품질을 올리는 보조다.

## 2. 비목표

- **사용자 확인 없는 자동 태깅 확정** — 분류 결과는 "추정"으로만 표시한다. `wrongCauses` 기록은 사용자 행위로만 생성된다.
- **오답의 교육적 해설 생성** — 원인 라벨만 분류하고 해설은 만들지 않는다.
- **크로스유저 지도학습** — 단일 사용자 라벨로만 동작한다(데이터 규모상 딥러닝 미세조정 불가 — §3).
- **실시간 트랜스포머 인퍼런스** — 모델 자산을 앱에 싣지 않는다.

## 3. 접근 비교 — 데이터 규모에 맞는 방법 선정

| 접근 | 필요 라벨 | 자산 비용 | 정확도 기대 | 판단 |
|---|---|---|---|---|
| A. 규칙 개선 (autoPattern 확장) | 0 | 0 | 현행 유지 — 형식 휴리스틱 한계 동일 | 폴백으로 유지 |
| B. **임베딩 센트로이드 kNN** — 태깅된 오답의 벡터를 원인별로 평균해 미태깅 오답을 최근접 원인에 배정 | 수십~수백 건 (사용자 태그가 곧 라벨) | 모델 0 — D18 벡터 재사용 | 유사 오답은 유사 원인 경향 — 소량 라벨에서 가장 강건 | **Phase 1 채택** |
| C. 소형 트랜스포머 fine-tune (KoELECTRA-small 등) + ONNX | 원인당 ≥수백 건 + 평가셋 | 모델 수십 MB + 런타임 | 라벨 부족 시 과적합 — 단일 사용자는 한계 명확 | 라벨 임계량 도달 시 재평가 |
| D. LLM 분류 (BYOK 원격) | 0 (few-shot) | 0 | 높지만 네트워크·키·프라이버시·지연 비용 | 선택 경로로만 보류 |

**B를 채택하는 근거**: 단일 사용자의 누적 태그는 수십~수백 건 스케일이므로 지도학습보다 최근접 이웃 계열이 맞고, D18에서 이미 모든 문항·진술의 벡터가 번들로 존재해 **추가 자산·모델 없이 순수 계산으로 구현**된다. 센트로이드는 사용자 본인의 태그로만 구성되므로 개인화도 자연스럽다.

**솔직한 한계 명시**: 센트로이드는 "내가 비슷한 문항에서 이 원인으로 태그했다"의 일반화다. 태그 0건이면 작동하지 않고, 원인 간 의미 차이가 미세한 경우(memorize↔concept) 분리력이 낮을 수 있다 — 그래서 §5의 확신도 게이트와 §6의 기저선 비교가 필수다.

## 4. 입력·분류 체계

### 4.1 분류 입력 피처

오답 이벤트당 다음을 결합해 임베딩 대상 텍스트를 구성한다:

```
[stem] 발문 + [chosen] 선택한 오답 선지 + [correct] 정답 + [citation] 인용 근거 구절
```

- **`chosen`이 핵심 추가 신호**다 — 같은 문항이라도 어떤 오답을 골랐는지가 원인을 가른다(비슷한 수치 선택 → 수치 혼동; 무관 개념 선택 → 개념 오해). 현행 규칙은 stem만 본다.
- `chosen`이 없는 형식(단답형)은 stem+정답만.
- D18의 `question` 벡터는 stem+정답만이므로, `chosen`까지 반영된 임베딩은 빌드 산출물에 없다. **v1은 D18 문항 벡터(stem+answer)를 그대로 쓰고**, 선지 포함 임베딩은 D18 파이프라인 확장(선지별 벡터 `vectors_distractors`)으로 단계 2에서 추가한다 — 의존성 최소화 우선.

### 4.2 분류 체계 = 기존 taxonomy 재사용

원인 키 집합은 `getWrongCauseTaxonomy()`(AN-07)를 그대로 따른다 — 기본 3종(memorize/concept/calc) + manifest `analysis.wrongCauses` 확장 키. 시험별 taxonomy 추가는 별도 작업 없이 자동 호환되며, 새 키의 센트로이드도 사용자가 태그를 쌓으면 자연스럽게 형성된다.

## 5. 추정 절차·확신도

```
1. 사용자가 태그한 오답 집합 T = { item → cause }
2. 원인별 센트로이드: C[c] = normalize( mean( v(item) for item in T where cause=c ) )
   — D18 벡터 로드 후 평균, 수십 건 기준 ms 단위. 태그 변경 시점에만 재계산해 캐시.
3. 미태깅 오답 i에 대해: s_c = cosine(v(i), C[c]) for all c
4. best = argmax s_c, margin = s_best − s_second
5. 추정 채택 조건: |T| ≥ MIN_LABELS(기본 20) ∧ margin ≥ τ_margin(기본 0.05)
   ∧ s_best ≥ τ_sim(기본 0.5)
6. 채택 → { cause: best, confidence, suggested:true } / 미달 → 기존 규칙 추정 경로 유지
```

- **margin 게이트**: 두 원인이 근접하면 "분류기가 구분 못 함"으로 판단해 제안하지 않는다 — 잘못된 확신보다 침묵이 낫다(오답 원인은 학습 행동 권고로 이어지므로).
- **라벨 최소량**: `MIN_LABELS` 미만이면 센트로이드 자체를 만들지 않고 규칙 폴백만 — 콜드스타트에서 성능 악화를 막는다.
- 임계값(τ_margin·τ_sim·MIN_LABELS)은 `manifest.analysis.causeClassifier` 선언으로 시험별 조정 가능하게 하되, 미선언 시 위 기본값. 매직 넘버는 `src/config/` 규약대로 상수화.

### 5.1 제안 UI 연동

- 오답 원인 선택 UI에서 "추정: {라벨}"을 **기본 선택이 아닌 제안 칩**으로 표시 — 사용자가 탭하면 확정, 무시하면 미태깅 유지. 수락/거부를 계수해 §6의 수용률 지표로 사용한다.
- 오답 패턴 카드·주간 리포트의 분포에는 기존처럼 "추정" 표기를 유지하고, 센트로이드 추정분도 동일하게 추정 취급한다(태그와 구분 표기 — AN-07의 counts는 추정치로 이미 표기됨).

## 6. 평가

- **오프라인 검증(빌드/개발 단계)**: 사용자 태그 이력에 leave-one-out — 태그 1건을 숨기고 나머지로 센트로이드 구성 → 숨긴 태그 재현율 vs 규칙 기저선 재현율 비교. **목표: top-1 일치율 ≥ 규칙 기저선 +20%p**, 미달 시 기능을 활성화하지 않는다(롤아웃 게이트).
- **운영 지표(앱 내)**: 제안 수용률(추정 제안 → 사용자 수락 비율)을 카운터로 집계해 AN-09 주간 리포트에 포함. 수용률 <60%이면 τ 상향 또는 표시 빈도 하향.
- **회귀 방지**: 규칙 추정은 항상 계산해 두고 센트로이드 추정만 덮어쓰는 구조 — 센트로이드 경로 버그 시 규칙 결과로 자동 퇴행 가능하게 이중화한다.

## 7. 저장·프라이버시

- **신규 저장 키(제안)**: `wcclf:<examId>:centroids` — 원인별 센트로이드 벡터 캐시(태그 해시로 무효화). `storage.js` 추상화 경유·`<examId>:` 스코프 규약 준수. 백업/동기 포함 여부: **포함** — 사용자 디바이스별 재계산 가능하지만 이동 시 콜드스타트 방지 가치가 있고, 벡터 자체는 원문 비가역이라 프라이버시 민감도 낮음. 단, 사용자 태그 원본(`wrongCauses`)은 기존 정책 그대로.
- 외부 전송 없음 — 모든 계산 온디바이스. D(BYOK LLM) 경로는 채택 시 CSP·키 계약을 FO-BYOK 패턴으로 별도 설계.
- 추정 결과가 `wrongCauses`에 쓰이지 않으므로 저장 데이터 스키마 변경 없음 — 표시 계층만.

## 8. 구현 시 필요한 선행 등록

1. **DOC-DSN-18 선행** — `question` 벡터 번들 + `src/semantic-index.js` API 확보.
2. **SPEC**: AN-07 확장 또는 신규 WC-xx ID 등록 (제안: WC-01 센트로이드 추정기, WC-02 확신도 게이트, WC-03 제안 UI, WC-04 수용률 지표) → `@spec` 태그.
3. **exams.json**: `features.semantic` 게이트와 동일 플래그 공유 가능 — 별도 `features.causeClassifier`(제안)로 분리하면 D18 없이 규칙만 쓰는 시험과 공존 용이.
4. **domain-map**: `src/wrong-cause-classifier.js`(제안) → platform layer 선언.
5. **check:storage**: 신규 키는 storage.js 경유 — 직접 localStorage 접근 금지.
