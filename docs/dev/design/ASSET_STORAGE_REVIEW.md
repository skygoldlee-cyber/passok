## 2. `.git` 비대화의 실제 동인

- **해시명 생성 번들**: `data/exams/cosmetic/exams/subject4.<hash>.js` 등은 갱신마다 신규 blob을 남기고 구본은 이력에 영구 잔존 — SW 캐시버스팅 목적이라 명명 자체는 유지 필요
- **재생성 주기**: build:data·drills·embeddings 체인이 콘텐츠 편집마다 수십 MB급 diff를 생성
- **삭제된 대형 파일의 이력 잔존**: gitignore 이전 추적분 등

즉 트리 용량(~60MB 추적 바이너리)은 작고, 문제는 **이력 증가율**이다.

## 3. 선택지 평가

| 방안 | 효과 | 비용·리스크 | 판단 |
|---|---|---|---|
| git-filter-repo/BFG 이력 재작성 | .git 급감 | force-push·협업 이력 파괴·모든 클론 무효화 | **기각** — 단독 유지 저장소여도 CI/배포·로컬 사본 재구축 비용이 이득 초과 |
| git-lfs 전환 (PDF·PNG·생성번들) | 신규 blob 외부 저장 | 이력 축소 효과 없음(전향 적용) + LFS 쿼터·로컬 도구 의존·reffresh 해시 게이트가 LFS 포인터로 우회 위험 | **부분 채택** — 신규 대형(>5MB) 자산만 |
| `data/` 생성물 git 제외 + CI 빌드 | 번들 churn 제거 | 정적 Vercel 프리빌트 배포 구조라 번들은 배포 입력물 — Python 임베딩(17k문·HF 모델)은 Vercel 빌드 불가 | **기각** — 배포 모델과 충돌 |
| clone 최적화 (`--depth`/partial clone) 안내 | 신규 클론 비용 절감 | 없음 | **채택** — 문서화 수준 |
| 로컬 `git gc --aggressive` 주기 실행 | 팩 압축 최적화 | 로컬만, 원본 이력 불변 | **권장** — 유지보수 루틴 |

## 4. 결정

1. **추적 상태 유지** — PDF는 reffresh 해시 게이트의 검증 대상이고, 생성 번들은 정적 배포 입력물이라 외부화 시 무결성·배포 체인이 깨진다.
2. **이력 증가 억제는 "유입 관리"로** — 신규 대형 자산(기준: 5MB 초과)은 추가 전 LFS 편입 검토를 `CONTENT_WORKFLOW` 절차에 명기. 현재 6건 >1MB PDF·PNG는 재작성 없이는 손익분기가 없어 추적 유지.
3. **audiobook 선례를 표준으로 명문화** — 재생성 가능·CDN 대체 가능한 미디어는 git 외부화가 원칙 (이미 적용 중).
4. **재평가 트리거**: `.git` > 2GB 또는 clone 체감 > 3분 시 LFS 전면 전환 재검토.

## 5. 체크 항목 (신규 자산 추가 시)

- [ ] 재생성 가능 산출물인가? → 추적 금지 (`.gitignore` + 생성기 문서화)
- [ ] 게이트·배포가 파일 실체를 요구하는가? (reffresh·verify:assets·SW precache) → 추적
- [ ] 5MB 초과인가? → LFS 편입 검토 (단, 해시 게이트 대상이면 추적 유지하고 이력 비용 수용)
