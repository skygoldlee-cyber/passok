## 0. 전제 — 기존 자산과의 경계

| 구분 | 기존 `passok-ops` 서버 | 본 설계의 커뮤니티 서버 |
|------|----------------------|------------------------|
| 성격 | 비공개 운영 표면 | 공개 사용자 커뮤니티 |
| 내용 | 배포 알림(AD-10)·조회 봇(AD-11)·피드백 알림(FB-08) | 시험별 홍보·질문·오류제보·스터디 |
| 초대 | 절대 공개 금지 | 초대 링크 공개 유통 |

운영 서버와 커뮤니티 서버는 **반드시 분리**한다 — 조회 봇(ADMIN 노출 경로)·운영 알림이 섞이면 보안 경계가 깨진다. 커뮤니티는 신규 서버 1개(`PassOK`)를 만들고 Discord **Community 기능**(무료)을 활성화해 내장 Onboarding·Announcement·포럼 채널·멤버 검증을 사용한다.

## 1. 서버 구조 — 단일 서버 + 역할 게이트

권장: **서버 1개 + 시험별 카테고리 + 온보딩 역할 선택**. 시험별 별도 서버는 파일럿 시험의 교차 홍보 경로를 끊고 관리 부담만 커진다.

```
PassOK (공개 커뮤니티 서버)
│
├─ 👋 허브 (역할 무관, 전원 공개)
│   ├─ #환영·규칙           — 멤버 검증(rules screening) 게이트
│   ├─ #전체-공지           — Announcement 채널 (타 서버 팔로우 가능)
│   ├─ #시험-관심등록        — comingSoon 팩 소개 + 반응 투표 (수요 측정)
│   ├─ #자유-수다
│   └─ #버그·기능제보        — → 운영팀 트리아지
│
├─ 💄 맞춤형화장품 조제관리사  (@role: 수험생-조제관리사)
│   ├─ #조제-공지           — 릴리스·콘텐츠 갱신 (webhook 자동발송)
│   ├─ 💬 조제-질문포럼      — Forum 채널, 태그 = 과목(화장품법/제조/품질/안전)
│   ├─ #조제-오류제보        — 문항·교재 오탈자·인용 오류
│   ├─ #조제-스터디          — 스터디 모집·인증
│   └─ 🔊 조제-음성룸        — (선택) 그룹 스터디
│
├─ 🚜 손해평가사 (준비중)     (@role: 관심-손해평가사)
│   ├─ #손평-알림신청        — 승격·문항 증설 소식
│   └─ #손평-질문
│
├─ ⚖️ 손해사정사 (준비중)    …동일 축소 세트
├─ ⛑️ 산업안전기사 (준비중)   …동일
├─ 📄 일반행정사 (준비중)     …동일
│
└─ 🔒 운영 (staff-only)
    ├─ #트리아지            — 각 #오류제보에서 넘어온 건 정리
    └─ #자동화-로그          — AutoMod·webhook 로그
```

**핵심 설계 결정**

| 결정 | 이유 |
|---|---|
| 카테고리 가시성 = 역할 | 멤버가 본인 시험만 보도록 격리 → 스팸 채널 느낌 방지 |
| 과목별 Q&A는 **포럼 채널 + 태그** | 채널 남발 방지. 태그를 manifest `subjects`와 동기화하면 시험 구조와 자동 정합 |
| 파일럿은 채널 2개로 축소 | 24~52문 규모에 풀 카테고리는 과함. 승격(`comingSoon` 해제) 시 풀 세트로 확장 — `PILOT_EXAM_PROMOTION.md` 절차에 "Discord 확장" 단계 추가 |
| `#시험-관심등록` 반응 수 | = 시험별 수요 데이터 → 승격 우선순위 근거 (`BUSINESS_VALIDATION.md` 가설 검증과 연계) |

## 2. 역할 체계

| 역할 | 부여 방식 | 권한 |
|---|---|---|
| `@수험생-<시험>` | Onboarding 질문 자가선택 | 해당 카테고리 열람·발언 |
| `@관심-<파일럿>` | `#시험-관심등록` 반응 또는 Onboarding | 파일럿 채널 + 승격 알림 |

| `@모더레이터` / `@운영팀` | 수동 | 관리 |

## 3. 홍보(유입) 설계

Discord 자체는 검색 유입이 약함 — **외부 유입 → 서버 내 전환** 2단 구조:

1. **외부 유입원**: 수험생 네이버 카페/오픈채팅 게시, 블로그 SEO, 앱 내 링크
   - 시험별 **초대 링크 분리 생성**(채널 지정 초대) → 초대 통계로 유입 경로 추적
   - 앱 내 유입점: 설정/피드백 화면 + 홈 배너에 Discord 초대 버튼 — `exams.json`에 `discordInvite` 필드로 선언하면 시험 id 하드코딩 없이 렌더링 가능 (DA-15 정합)
2. **서버 내 전환**: Onboarding에서 시험 역할 선택 → 해당 카테고리 공지 자동 구독
3. **잔류 장치**: `#공지`를 Announcement 채널로 → 릴리스 노트·시험 일정·법 개정 소식 push (§4)

> **채널 적합도 메모**: 한국 자격시험 수험생 커뮤니티는 네이버 카페·오픈채팅이 지배적이다. 조제관리사(20~30대 화장품 업계)는 Discord 적합도가 있지만, 손해사정사·행정사는 연령대가 높아 오픈채팅 병행이 현실적 — Discord를 정본으로 하되 파일럿 시험은 카카오 채널/오픈채팅 링크를 `exams.json`에 나란히 선언하는 구조가 유연하다.

## 4. 자동화 — 기존 자산 재사용

| 흐름 | 기존 자산 | 확장 |
|---|---|---|
| 릴리스 → `#<시험>-공지` | `tools/lib/discord.js` (AD-10) | **구현됨 (AD-12)** — `DISCORD_ANNOUNCE`(전체-공지)·`DISCORD_ANNOUNCE_<EXAM>`(시험별) webhook 맵, 배포 성공·스모크 통과 시 `announceRelease()`가 릴리스 노트 fan-out |
| 앱 내 피드백 → Discord | `feedback-notify` Edge Fn (FB-08) | 현행 ops 서버 수신 유지 — 커뮤니티 `#버그·기능제보` 제보는 모더레이터가 ops로 이관 (양방향 연동은 과설계) |
| 조회 명령 | `admin-bot` (AD-11) | **ops 서버 전용 유지** — 커뮤니티에 두면 ADMIN 노출 경로가 생긴다 |
| 환영·역할·투표 | 없음 | Discord 내장 Onboarding + AutoMod로 커버 — 초기엔 커스텀 봇 불필요 |

## 5. 운영 정책

- **규칙 핵심**: 교재/문제은행 스크린샷·복사 공유 금지(콘텐츠 저작권 — 유료 전환 시 치명적), 타 수험앱·강의 광고 금지
- **AutoMod**: 스팸 링크 차단 + 키워드 필터 + 신규 멤버 `가입 후 N분 발언 제한`(인증 레벨 "중간")
- **모더레이션**: 초기 1인 운영 가정 — 신고는 `#버그·기능제보` 멘션 + AutoMod 로그로 커버

## 6. 도입 단계

| Phase | 범위 |
|---|---|
| 1 | 서버 개설·Community ON + 허브 카테고리 + **cosmetic 풀 카테고리** + 규칙·Onboarding |
| 2 | 앱 내 초대 링크 삽입 (`exams.json.discordInvite` + 설정 UI) + `#시험-관심등록`으로 파일럿 수요 측정 |
