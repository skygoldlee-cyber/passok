## 1. 배경·목표

교재 콘텐츠는 **파생 순서**를 가진다 — **표준형 → 이야기형 → 웹툰형**. 표준형(`*_표준형.md`)이 정본이고, 이야기형(`*_이야기형.md`)은 표준형 챕터에 `story:start~end` 서사 블록을 얹은 파생물이며, **웹툰형은 독립 콘텐츠 파일이 아니라 이야기형의 말풍선 렌더 모드**다(표준형 없는 이야기형·이야기형 없는 웹툰형은 존재할 수 없다).

시험별 커버리지는 이 파생 사슬의 어느 단계까지 갔는지로 정해진다 — 표준형은 전 시험 보유, 이야기형은 cosmetic·carework만, 웹툰 캐스팅(`webtoon.json`)은 carework만 존재한다. **이야기형이 없는 시험에는 웹툰형도 있을 수 없고, 이야기형이 있어도 캐스팅 미등록이면 화자 표현이 제네릭 폴백으로 저하**된다.

웹툰 표면은 두 진입점이 있다 — 리더의 "웹툰형" 형식 모드(연속 스트립, 전 시험)와 carework 독립 뷰 `care-webtoon`(씬 단위 페이저). 콘텐츠는 이미 충분하다: cosmetic 263슬롯(4과목)·carework 58슬롯(2과목).

그러나 현재 구현은 carework 단일 캐스팅에 맞춰 성장한 상태로, **cosmetic에서 웹툰 모드를 켜면 화자 추정이 전부 오동작**한다(민수·지연 캐스팅에 carework 규칙 적용 — "선임님" 호칭 규칙 하나도 매칭되지 않아 모든 대사가 직전 화자 교대 폴백으로 배정). 이야기형이 없는 21개 시험에서도 "웹툰형" 옵션이 항상 노출된다. 본 문서는 파생 사슬의 각 단계가 시험별로 존재·부재할 수 있음을 전제로, 이야기형·웹툰형 공통 기반의 구조 개선과 표면 정리를 확정한다.

## 4. 화자 모델 일반화 (WT-01)

### 4.1 webtoon.json v2 스키마

```jsonc
{
  "chars": {                                        // v1의 평탄 맵을 chars로 이동
    "miyoung": { "name": "미영", "side": "right", "img": "assets/characters/miyoung.svg" },
    "mentor":  { "name": "박은정 선임", "side": "left", "img": "assets/characters/park-eunjung.svg" },
    "choiboksun": { "name": "최복순 어르신", "side": "left", "tone": "elder",
                    "img": "assets/characters/choi-boksun.svg" }
  },
  "speakers": {
    "names": [                                      // 화자명 단독 줄 → 화자 키 (v1 SPEAKER_NAMES 이식)
      ["박은정|선임|선생님", "mentor"],
      ["미영", "miyoung"],
      ["어르신|최복순|어머니|아버지|할아버지|할머니", "choiboksun"]
    ],
    "hints": [                                      // 대사 내 호칭 힌트 (v1 whoSays 규칙 이식)
      { "match": "선임님", "who": "miyoung" },
      { "match": "미영|교육생", "who": "mentor" }
    ],
    "defaultPair": ["mentor", "miyoung"]            // 교대 폴백의 두 축
  }
}
```

- **하위 호환**: 평탄 맵(v1)은 `chars`로 해석하고 `speakers`는 제네릭 기본값 적용 — 기존 carework 파일을 v2로 마이그레이션하되 구 파서는 계속 동작.
- **제네릭 기본값**(webtoon.json 부재·speakers 부재 시): 화자 키 `learner`(우)·`guide`(좌) 2인, 이름 라벨·힌트 없이 "직전 화자와 defaultPair 교대"만 — 현재 `DEFAULT_CHARS`의 `어르신` 등 시험 잔재 제거.
- **elder 확장**: `tone` 필드는 표현 힌트(버블 색조) — 화자 키와 표현 클래스를 분리해 개별 어르신 등록 가능.
- **파서 시그니처**: `whoSays(text, prev)` → `makeSpeakerResolver(speakers)` 생성 함수로 교체 — `(text, prev) => who` 반환. `renderSlotHtml(slot, chars, resolver)`는 resolver를 선택 인자로 받고, `webtoon.json`의 `speakers`가 있으면 그 규칙으로 생성한다.
- **cosmetic 캐스팅**(동 파일 신규, WT-08): `minsu`(우)·`jiyeon`(좌) — hints `지연 씨→minsu`, `민수 대표님|민수 씨→jiyeon` 등. 인물명 정본은 `인물 설정표.md`(CS-13)에서 취득.
- **빌드타임 공용화 경로**: DOC-DSN-60 SO-02의 화자 태깅 파이프라인은 동일 규칙을 빌드타임으로 이식한다 — 규칙 원본을 `webtoon.json`에 두면 런타임·빌드타임이 단일 원본을 공유해 드리프트를 차단한다.

## 5. 형식 옵션 무표시 계약 (WT-02)

파생 사슬(표준→이야기→웹툰)상 **이야기형이 없는 시험은 웹툰형도 불가**이므로 두 옵션의 게이트는 단일 입력으로 충분하다 — 별도의 "웹툰 보유" 신호를 요구하지 않는다. `webtoon.json` 부재는 웹툰 표시 자체를 막는 조건이 아니라 화자 표현의 품질 등급(제네릭 폴백)이다.

- **게이트 입력**: `features.story_textbook`(exams.json — cosmetic·carework만 `true`)으로 이야기형·웹툰형 옵션을 동시 게이트한다. `storyFile` 과목 선언은 콘텐츠 상세이므로 게이트는 플래그 단일 기준(과목별 부분 서사는 콘텐츠 책임).
- **구현 지점**: `renderTextbookReader()`의 형식 셀렉트 채움 시 `hasFeature('story_textbook')` 거짓이면 두 옵션을 DOM에서 제거(표준형만) — `syncFmtPro` 배지 래퍼도 함께 비표시. 검색 이동(`openSubjectSection` story 강제)은 플래그 거짓 시 story 옵션을 무시해 표준형으로 착지.
- **독립 뷰 진입**: `care-webtoon` 뷰 자체는 `data-feature="careWebtoon"` 게이트가 이미 존재 — 변경 없음.
- **폴백 동작 보존**: 플래그 참인데 스토리 로드 실패 시의 표준형 폴백·토스트는 현행 유지.
- **신규 시험 온보딩 경로**: 표준형만 있는 팩 → 서사 콘텐츠 작성·`storyFile` 선언·`story_textbook` 플래그 참 설정 → 이야기형·웹툰형 동시 개방(제네릭 화자) → `webtoon.json` 캐스팅 등록으로 화자 품질 상향(WT-08) — 파생 사슬을 따라 단계적 확장이 자연 발생한다.

## 6. 슬롯 ID·씬 주소 체계 (WT-03)

- **파싱**: `parseStorySlots` 정규식을 `story:slot:(id)` 대안으로 확장 — 슬롯 마커를 읽어 다음 `story:start` 블록에 `id` 부여. 마커 없는 블록은 `null` — 인덱스 폴백 경로 유지.
- **씬 선택·저장**: 독립 뷰 씬 셀렉트 value를 id로 전환(`Option(title, id)`), 진행 저장 키 `scopedKey('webtoonPos')`에 `{subject, slotId, index}` 저장 — 복원 시 id 우선 매칭, 없으면 index 폴백.
- **씬 라벨**: 리더 웹툰 목차·독립 뷰 셀렉트 라벨을 `s16 · <첫 비트 20자>` 형태로 정규화 — 현재 절단 문장 라벨 개선(번호는 콘텐츠 안정 식별자라 위치 무관).
- **검색·딥링크 착지**: 씬 카드에 `data-slot-id` 부여 — `openSubjectSection` 계열이 `slotId` 옵션을 받으면 카드로 직행. story:true 강제 외에 webtoon 모드 착지 경로(`opts.mode`)를 허용해 통합 검색의 웹툰 결과 매칭을 지원.
- **무표시**: id 없는 콘텐츠(마커 미부여 슬롯)는 기존 동작 그대로 — 콘텐츠 보강은 별도 배치.

## 7. 두 표면 역할 정리 (WT-04)

| 표면 | 역할 | 보유 기능 | 개선 |
|------|------|-----------|------|
| 리더 "웹툰형" | **연속 읽기 정본** — 챕터 전체를 말풍선 스트립으로 읽는 경로 | 씬 목차·스크롤스파이·읽기 진도바 | 씬 카드에 북마크·검색 착지(WT-06), `data-slot-id` 딥링크 |
| `care-webtoon` 뷰 | **씬 플레이어** — 한 컷 집중 보기·앞뒤 탐색·자동진행, 향후 보이스 웹툰(SO-06)의 재생 호스트 | 씬 단위 페이저·화살표 키 | 진행 이어보기(id)·챕터 optgroup·자동진행 토글(WT-07) |

- **통합 기각**: 두 표면 병합은 씬 플레이어의 고유 가치(집중·재생 호스트)를 소거 — 역할 문서화로 중복을 자산으로 전환한다. 리더 스트립의 각 씬 카드에 "▶ 이 씬 재생" 버튼으로 플레이어 진입을 연결하는 연결고리는 WT-06에 포함.
- **자동진행**(무음): 씬 표시 후 N초(문자량 비례, ~40ms/자 + 최소 2.5s) 뒤 다음 씬 — SO-06 음성 동기 시 클립 `ended` 이벤트로 자연 교체될 전이 경로로 두되, 오디오 없이도 프레젠테이션 가치가 있어 독립 구현.

## 8. 오답→컷 연동 (WT-05)

- **조회 경로**: `concepts.json` 항목의 `storySlot`(예 `s16`) → 해당 과목 이야기형 MD → `parseStorySlots`로 id 매칭 슬롯 추출 → `renderSlotHtml`로 버블 렌더.
- **표시 지점**: 훈련소·퀴즈 오답 피드백(개념 태그가 있는 문항)에 "📺 상황 다시 보기" 접힘 블록 — 개념→슬롯 조회는 시험의 `concepts.json` 존재 시에만 활성(무표시 계약).
- **비트 세분 후속**: `cutOnWrong{optionIndex: cutId}`의 비트 단위 매핑(`s01-b2`)은 가이드라인 §1 예고 사양 — 슬롯 전체 표시로 시작하고, 비트 id 체계는 콘텐츠 규약 확정 시 도입.
- **로드 비용**: 슬롯 파싱은 과목 이야기형 로드와 동일 — `DataLoader._getMd` 캐시 경유, 오답 피드백 시점 지연 로드.

## 9. 생성형 컷 삽화 파이프라인 (WT-10)

웹툰형은 이야기형의 렌더 모드이므로, 컷 삽화는 콘텐츠 MD를 수정하지 않고 **슬롯 id 주소에 매니페스트로 매다는 자산 계층**으로 추가한다 — 표준형/이야기형 원문은 건드리지 않으며, 자산이 없는 슬롯은 현행 텍스트 버블로 폴백(무표시 계약).

### 9.1 방식 선택

| 방안 | 캐릭터 일관성 | 비용 | 리스크 | 판정 |
|------|--------------|------|--------|------|
| A. 완전 생성 컷(인물 포함 일러스트) | 낮음~중 — 참조 이미지 지원 모델 필요 | 슬롯당 1컷 | 얼굴·체형 붕괴, 이미지 내 한글 텍스트 오류, 검수 비용 | 조건부 (참조 지원 모델 한정, Phase C) |
| **B. 생성 배경 + 시험 팩 고유 SVG 캐릭터 합성** | **확정** — 인물은 팩별 고정 SVG 아트라 생성 대상 아님 | 슬롯당 배경 1컷 | 배경-캐릭터 광원·원근 어색함 (프롬프트·배치 규약으로 완화) | **채택 (Phase A)** |
| C. 정경·소품 컷(인물 없음) | 해당 없음 | 최저 | 정보 밀도 낮음 | 보조 — 인물 연출 불필요 슬롯 |
| D. 런타임 생성 | — | — | 지연·과금·오프라인 불가·캐시 불가 | 기각 — 자산 1회 생성 원칙 |

- **B 채택 근거**: 생성형 삽화의 최대 리스크는 캐릭터 붕괴인데, 등장인물은 **시험 팩이 정의하는 고유 캐스트**(carework: 미영·선임님·어르신 / cosmetic: 민수·지연 / 신규 시험: 팩 자체 인물 설정)이고 그 SVG 고정 아트가 팩 자산(`assets/characters/`)으로 이미 존재한다 — **인물을 생성 대상에서 제외**하면 일관성 문제가 소거된다. 배경만 생성하고 캐릭터는 런타임에 올려 "페이퍼돌 합성"한다.
- **런타임 합성 선택**: 빌드타임 래스터 합성(배경+SVG→단일 이미지)은 신규 의존성이 필요하다. 배경 webp 위에 캐릭터 SVG를 CSS 레이어로 올리는 런타임 합성은 의존성 0이고, 캐릭터 위치·인원을 슬롯별로 조정할 수 있다 — 배경 자산만 생성하면 된다.
- **캐스트는 팩 스코프**: `compose[].char`는 전역 캐릭터 풀이 아니라 **같은 시험 팩의 `webtoon.json` chars 키**를 참조한다(WT-01 v2 스키마와 동일 소스). 팩마다 등장인물·아바타 아트가 다르므로 매니페스트·프롬프트·검수 전부 시험 팩 경로 아래에서 닫힌다(DA-15 준용 — 공용 코드에 시험 인물 리터럴 없음). SVG 아트 미보유 팩은 `compose` 생략(배경 단독 컷) 또는 제네릭 스탠디로 시작한다.

### 9.2 자산·매니페스트 스키마

```
content/exams/<id>/assets/webtoon/<subj>/<slotId>.webp   # 서빙 배경 컷 (webp 강제)
content/exams/<id>/assets/webtoon_art.json               # 컷 매니페스트
```

```jsonc
{
  "s16": {
    "bg": "assets/webtoon/careprac/s16.webp",
    "compose": [
      { "char": "mentor",  "pos": "left"  },
      { "char": "miyoung", "pos": "right" }
    ],
    "prompt": "<생성에 사용한 프롬프트 전문 — 재현성·검수용>",
    "model": "gpt-image-1", "seed": 12345,
    "reviewed": true, "reviewedAt": "2026-11-29"
  }
}
```

- **주소는 슬롯 id** — WT-03의 `story:slot` 파싱이 전제. 인덱스 기반이면 콘텐츠 편집 시 컷이 어긋난다(ID-05).
- **`compose` 생략 가능** — 인물 없는 정경 컷(C 방안)도 같은 스키마.
- **`char` 참조 계약** — `compose[].char` 값은 이 매니페스트가 속한 시험 팩의 `webtoon.json` `chars` 키와 매칭(해석은 런타임 — `img`/`side`/`name`은 거기서 가져옴). 미등록 키는 경고 후 해당 인물 미렌더(배경+나머지 인물로 폴백).
- **`prompt`·`model`·`seed` 보존** — 재현성과 검수 추적(CQ-07 프로비넌스 계약).

### 9.3 제작 파이프라인 (ai:* 관례)

```
parseStorySlots → 슬롯별 프롬프트 초안(지문 비트 + 인물 설정표 톤 + 시리즈 성 규약)
  → LLM 프롬프트 다듬기 초안 → tmp/ai_drafts/webtoon/<exam>/<subj>/<slotId>.md
  → 사람 검수·확정 → 생성 실행(AI_PROVIDER) → 배경 webp
  → webtoon_art.json 갱신 → content/ 편입
```

- **기존 AI 저작 경로 재사용** — `AI_PROVIDER`/`AI_API_KEY`·`tmp/ai_drafts/`→사람 리뷰→`content/` 편입의 ai:* 패턴 그대로 (CQ-07 게이트 적용).
- **프롬프트 규약**: 지문(scene) 비트에서 장소·소품·분위기 추출 + "무텍스트 삽화" 네거티브(이미지 내 한글·말풍선·숫자 금지 — 생성 모델의 한글 렌더링 불안정 대응) + **해당 팩의 인물 정본**(CS-13 — 시험마다 자체 인물 설정표/톤 문서)의 시리즈 톤 고정문 + 수치·조문 묘사 금지(슬롯 규약 준용). 배경 프롬프트에 인물 묘사는 넣지 않는다 — 인물 연출은 `compose`의 몫이고 이미지는 항상 빈 무대다.
- **자산 정책**: webp만 서빙(check:webp 게이트), 슬롯당 1컷·~720px·예산 ~150KB(500KB+ 차단 게이트 여유), 생성 원본 마스터는 DOC-RBK-12 관례로 외부화·gitignore.
- **검수표(DOC-USR-26 연장)**: ①이미지 내 텍스트 없음 ②캐릭터 미포함 확인(B 방안 — 인물이 생성됐으면 기각·재생성) ③장소·소품이 지문과 일치 ④수치·조문 시각화 없음 ⑤시리즈 톤(조도·색감) 인접 컷과 연속.

### 9.4 런타임 렌더

- `webtoon_art.json`은 `webtoon.json`과 같은 지연 로드 경로(`contentPath` fetch, 시험 부재 시 폴백).
- 씬 카드 상단에 `<figure class="wb-panel">` — 배경 webp + `compose` 배치의 캐릭터 스탠디(팩 `webtoon.json` chars의 `img` SVG를 `pos`로 배치)·선택적 캡션(씬 번호 `sNN`). 엔트리 없는 슬롯은 패널 미렌더(무표시 계약)로 현행과 동일.
- **버블과의 관계**: 패널은 장면 설명(상황 비트)의 시각 대체 — 대사 버블 구조는 그대로 유지. 지문(`wb-scene`)은 패널 하단 캡션으로 흡수 가능(UX 결정 사항).
- **계측**: 컷 노출률·플레이어 체류 (SO-08 계측 표에 `webtoon_art` 이벤트 추가).

### 9.5 외부 LLM 교환 파일 계약 (수동 워크플로)

API 키 없이 GPT·Claude 등 외부 채팅에 붙여넣는 수동 경로를 1급 경로로 — ai:* 자동 경로와 같은 `tmp/ai_drafts/` 리뷰 게이트를 공유한다.

**내보내기 (job 파일)** — `ai:webtoon-art --export <exam> <subj> [--range a-b]`:

```
tmp/ai_drafts/webtoon/<exam>_<subj>_job.md
  ├─ 작업 지시 헤더 — 역할(웹툰 배경 디렉터)·응답 스키마·금지 규약(무텍스트·무수치·인물 묘사 금지)
  ├─ 캐스트 표 — 팩 webtoon.json chars: 키·표시명·side·톤 메모(인물 정본 CS-13 인용)
  └─ 슬롯 표 — slotId·챕터·지문(scene)·대사 비트 요약 (한 파일 = 한 과목 배치, --range로 분할)
```

**응답 계약 — 임베딩 가능 형식**: LLM은 단일 JSON 블록으로 응답한다 — 프리텍스트 금지, 이 스키마가 그대로 매니페스트 엔트리가 된다:

```jsonc
[
  { "slotId": "s16",
    "prompt": "<빈 무대 배경 프롬프트 — 인물·텍스트 묘사 없음>",
    "compose": [ { "char": "mentor", "pos": "left" }, { "char": "miyoung", "pos": "right" } ] }
]
```

- **인제스트** — `ai:webtoon-art --ingest <file>`: slotId 화이트리스트(job에 실린 슬롯만), `char`는 팩 chars 화이트리스트, `pos` enum(left|right|center), 프롬프트 길이·금지어(인물명·수치·조문어) 검사 → 통과분만 `webtoon_art.json`에 `reviewed:false` 초안으로 병합, 실패 슬롯은 사유와 함께 잔여 목록 출력(재시도 배치 가능).

**이미지 수급 두 경로**:

| 경로 | 흐름 | 산출 |
|------|------|------|
| A. 프롬프트 수급 | 텍스트 LLM이 `prompt`만 작성 → 검수 후 이미지 생성기(API·외부 도구 무관)로 배경 생성 | 배경 webp |
| B. 이미지 직생성 | 이미지 생성 가능 LLM(GPT 이미지·Gemini 등)에 job 파일을 통째로 제공해 컷 직접 생성 → 결과 이미지를 `tmp/ai_drafts/webtoon/inbox/`에 배치 | 인제스트가 webp 변환·`<slotId>.webp` 리네임·매니페스트 갱신 |

- 공통: 검수표(§9.3) 동일 적용 — `reviewed:true` 전환은 사람 검수 후. 경로 B에서 인물이 생성돼 들어오면 기각·재생성(빈 무대 규약).

### 9.6 장소 정본 (로케이션 바이블)

슬롯 수십 개가 도는 장소는 한정된다(carework 58슬롯 ≈ 10곳 — 최복순 댁 거실·부엌·침실, 교육원 강의실, 재가센터, 한정수 부부 댁 등). 슬롯마다 배경을 독립 생성하면 **같은 집이 컷마다 다르게** 나온다 — 인물 정본(CS-13)과 같은 이유로 장소에도 정본이 필요하다.

- **팩 문서**: 시험 팩에 `장소 설정표` 추가(인물 설정표 형제 문서) — `locId`·고정 묘사문(구조·소품·채광 방향)·마스터 컷 경로. 장소 정본 미보유 팩은 슬롯 단독 묘사로 시작하되 장소가 3회 이상 반복되면 등록 의무.
- **마스터 컷 선행**: 장소당 대표 배경 1장을 먼저 검수·확정(장소 마스터) — 나머지 슬롯 배경은 "마스터 참조 + 변형(앵글·시간대·소품 상태)" 생성이라 일관성·비용 모두 유리. 마스터도 같은 `webtoon/` 자산 규약(`master_<locId>.webp`).
- **job 파일 연동**: 슬롯 표의 장소 열은 `locId`로 표기하고 캐스트 표 뒤에 장소 표(묘사문 + 마스터 컷 참조)를 실어 LLM이 정본을 본다.
- **매니페스트 확장**: 슬롯 엔트리에 `"loc": "locId"` 추가 — 인제스트 검증 항목에 장소 화이트리스트 포함.
- **검수표 추가 행**: ⑥장소 정본 묘사·마스터 컷과 구조 일치(문 위치·창 방향 등).

| WT-04 | **웹툰 표면 역할 분리** — 리더 웹툰 모드=연속 읽기 정본, `care-webtoon` 뷰=씬 플레이어(집중 보기·자동진행·보이스 웹툰 호스트)로 경계 명문화 |
| WT-05 | **오답→컷 연동** — `concepts.json` `storySlot`/`cuts[]` 런타임 조회로 오답 피드백에 컷 버블 삽입, `cutOnWrong` 비트 세분은 콘텐츠 규약 확정 후 후속 |
| WT-06 | **웹툰 스트립 기능 균등** — 씬 카드 북마크·검색어 착지·`openSubjectSection` 웹툰 모드 지원, 씬→플레이어 진입 버튼 |
| WT-07 | **씬 플레이어 개선** — id 기반 진행 이어보기, 챕터 optgroup 그룹핑, 문자량 비례 자동진행 토글, 다화자 등록(elder 하위 화자) |
| WT-08 | **시험별 웹툰 온보딩** — `webtoon.json` v2 + 캐스팅 규칙 신규 등록 절차(cosmetic: minsu·jiyeon), 인물 정본은 `인물 설정표.md`(CS-13) 참조, 검수표는 DOC-USR-26 연장 |
| WT-09 | **웹툰 접근성** — 버블 행에 화자-대사 의미(role/aria-label), 장면 지문 구분 표기, `prefers-reduced-motion`에서 자동진행 비활성 기본값 |
| WT-10 | **생성형 컷 삽화** — 슬롯 id 주소에 `webtoon_art.json` 매니페스트로 배경 webp·캐릭터 합성 정보를 매달고, 캐릭터는 **시험 팩 고유 캐스트**(팩 `webtoon.json` chars의 SVG 고정 아트)의 런타임 합성으로 생성 대상에서 제외 — `compose[].char`는 팩 chars 키 참조(전역 풀 없음). 배경 일관성은 **장소 정본**(팩 장소 설정표 + 장소당 마스터 컷 선행 — 슬롯 배경은 마스터 참조 변형)으로 확보. 프롬프트 초안→사람 검수→생성→편입의 ai:* 경로(CQ-07) + **외부 LLM 교환 파일 계약**(job 내보내기 → JSON 응답 직접 인제스트 — 수동 채팅 워크플로 지원) + 무텍스트·무수치 검수표 + 엔트리 부재 슬롯 텍스트 폴백(무표시) + webp·크기 예산 정책 |

## 11. 단계별 작업·검증

**Phase 1 (구조 결함 해소)**: ① `makeSpeakerResolver` + webtoon.json v2 + carework 파일 마이그레이션 → ② 형식 옵션 게이트(WT-02) → ③ 슬롯 id 파싱 + 씬 라벨 정규화(WT-03 파싱부). 순서 의존: ①은 cosmetic 온보딩(WT-08)의 전제.

**Phase 2 (표면 개선)**: ④ 독립 뷰 진행 저장·챕터 optgroup·자동진행(WT-07) → ⑤ 리더 스트립 북마크·검색 착지·플레이어 진입 버튼(WT-06) → ⑥ 접근성 마크업(WT-09).

**Phase 3 (연동·확장)**: ⑦ 오답→컷(WT-05) → ⑧ cosmetic `webtoon.json` 온보딩(WT-08) → ⑨ SO-06 보이스 웹툰 착수 시 본 설계의 씬 플레이어를 재생 호스트로 사용.

**Phase 4 (생성형 컷 삽화, WT-10)**: ⑩ carework **장소 설정표** 작성 + 장소 마스터 컷(~10장) 선행 검수 → ⑪ 스파이크 — 서로 다른 장소·캐스트 조합 5슬롯 파일럿으로 품질·검수표·비용 검증 → ⑫ 매니페스트·런타임 패널 + carework 전 슬롯(58) 배경 컷(마스터 참조 변형) → ⑬ cosmetic 슬롯(263) 확장 → ⑭ (조건부) 참조 이미지 지원 모델로 인물 포함 완전 생성 컷 평가. 선행 의존: WT-03(슬롯 id) — 컷 주소 체계의 전제. 부수 전제: 한정수 어르신 캐스트 등록(WT-07 다화자 세분 또는 char 키 추가 — 그의 집 장면의 `compose` 정확도).

**검증**:
- 유닛: `makeSpeakerResolver` 규칙 테이블(이름 라벨·힌트·교대 폴백·제네릭 2인), 슬롯 id 파싱(마커 유·무 혼재), v1/v2 스키마 양방향 해석 — `care-webtoon.test.js`·`reader-webtoon.test.js` 케이스 확장
- DOM: 형식 셀렉트 게이트(플래그 on/off), 씬 셀렉트 id 저장·복원, 자동진행 토글·reduced-motion 비활성, 오답 컷 블록 표시/비표시
- E2E: cosmetic 웹툰 모드 화자 버블 할당 스냅샷, 오답 피드백 컷 진입
- 게이트: `check:imports`·DA-15 정적 탐지(시험 리터럴 제거 확인)·`check:terms`·무표시 계약 시나리오

## 12. 범위 경계

- **제외 — 보이스 웹툰 본체**: 음성 합성·클립 동기는 SO-01~10(DOC-DSN-60) 범위 — 본 문서는 재생 호스트(씬 플레이어·화자 키·`voiceId` 수용 가능한 v2 스키마)만 제공
- **제외 — 비트 단위 컷(`sNN-bN`)**: 컷 삽화(WT-10)는 슬롯당 1컷(슬롯 주소) — 비트 단위 다중 컷은 슬롯 컷 검증 후 평가
- **제외 — 비트 단위 cutId(`s01-b2`)**: 슬롯 내부 비트 주소는 콘텐츠 규약(DOC-USR-26) 확정 후 도입 — WT-05는 슬롯 단위로 착수
- **제외 — 서사 콘텐츠 자체 보강**: 슬롯 미부여 마커·씬 제목 메타 등 콘텐츠 수정은 별도 배치 — 파서는 마커 부재를 정상 폴백으로 처리
- **제외 — 이야기형 모드의 웹툰 인라인 렌더**: story 모드 본문 내 슬롯을 말풍선으로 교체 렌더하는 혼합 표면은 보류 — 형식 전환(표준/이야기/웹툰) 3분기 구조 유지
