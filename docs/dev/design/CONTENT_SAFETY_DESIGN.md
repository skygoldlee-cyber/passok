## 1. 배경·목적

`content/exams/`의 교재·문제은행은 `tmp/ai_drafts` 초안 → 사람 리뷰 → `ai:apply` 편입 경로로 AI가 대량 생산한다(DOC-DSN-33). 학습 콘텐츠는 **내용의 정확성이 제1 품질**인데, 현재 안전망은 인용 구조·정합성 중심이라 "구조는 맞지만 내용이 틀린/오염된" 산출물을 놓친다.

본 문서는 실제 발생한 신뢰성 사고(CHANGES.md 결함 이력)를 실패 모드로 분류하고, 재발을 차단하는 **4개 안전장치**(CQ-07·AI-45·AI-46·CQ-08)를 설계한다. 전제는 AI_AUTHORING_DESIGN.md와 동일 — LLM은 초안만 생산하고, 정본 편입은 사람 리뷰 + 기존 게이트 통과를 전제로 한다. 본 안전장치들은 그 게이트에 **의미 수준 검증 층**을 추가한다.

## 4. 안전장치 상세

### 4.1 CQ-07 — `check:aifacts` AI 잔재 패턴 게이트

**목적**: FM-1·FM-3의 재발 차단 — 정본 `content/`에 AI 생성 산출물의 잔재가 남으면 차단.

**구성**: `tools/check/check_ai_facts.js` (신규, 비LLM — 순수 패턴). `content/exams/<id>/교재`·`문제은행`·`피드백` md 전수 스캔, `exam_targets.js` 순회로 멀티시험 중립(AI-13 준수).

**탐지 패턴**(닫힌 사전 — 신규 패턴은 코드 리뷰로만 추가):

| 카테고리 | 예시 패턴 | 판정 |
|---|---|---|
| 거절·회피 문구 | `작성할 수 없습니다`, `제공된 참조자료(로만|으로는)?`, `답변할 수 없`, `오류가 발생했` | ERROR |
| 플레이스홀더 미치환 | `(LNN~LNN)`, `LNN` 리터럴, `고정폭 창` 표식, `<!-- 작성:` 슬롯 잔류, `XXX`·`???`·`TODO` 본문 | ERROR |
| 생성 메타 잔류 | `ai-draft`, `sha=[0-9a-f]{8}`, `[폐기 후보]` 라벨, `<!-- ai:` 주석 | ERROR |
| 영어 잔재 | 한국어 콘텐츠 내 비인용 영문장(허용: 코드 블록·인용 블록·고유명사 목록) | WARN(기준선) |
| 과목 표식 불일치 | 파일 경로 과목 ↔ 본문의 타 과목 키워드 과밀(KOCW 블록 유형) | WARN — 임계값 튜닝 후 ERROR 승격 |

**게이트**: P1 차단, 기준선 래칫(`ai_facts_baseline.json`) — ERROR는 0건 강제, WARN은 기존 잔여분만 허용(감소만). check preset `content`에 편입 → `check:all`·CI 자동 연동. 복구 명령은 실패 메시지에 해당 파일·행을 출력(수동 정리 대상이라 자동 fix 없음).

**오탐 방지**: 인용 블록(`>` 인용문·`📌출처` 블록 내부 원문)은 스캔 면제 — 법령 원문의 어조가 거절 문구와 충돌 가능. 코드 블록·테이블 헤더도 면제.

### 4.2 AI-45 — `ai:verify` LLM 팩트체크 도구

**목적**: FM-2·FM-3의 **유일한 검증 수단** — 토큰 매칭으로 불가능한 "인용이 정답을 의미적으로 지지하는가" 판정. 일회성 `tmp/_qreview` 실적(1,531문 검수, 실 결함 2건)을 반복 가능한 도구로 정규화.

**구성**: `tools/ai/ai_verify.js` (신규, `AI_PROVIDER`/`AI_API_KEY` 기존 llm_client 재사용). `--dry-run` 시 스캔·프롬프트 골격만 출력(AI-02 계약).

**대상·판정**:

| 대상 | 입력 | 판정 |
|---|---|---|
| 문제은행 문항 | 발문·선지·표기 정답·해설 + 인용 ref_md 구절 | `supported` / `contradicted` / `unverifiable`(인용 부족·범위 밖) + 사유 1문장 |
| 교재 섹션 | 본문 + 해당 📌출처 ref_md 구절 | 동일 판정 + 주장별(수치·정의·절차) 지지 여부 |

**비용 제어**(필수 — 전수 LLM 호출 비용 큼):
- `--exam <id>`·`--subject` 필터, `--sample N` 랜덤 표본, `--since <sha>` 증분(본문 해시 변경분만 — AI-46 로그 참조)
- 배치 리포트를 `tools/ai/verify_log.jsonl`에 append(모델·날짜·판정 분포) — 배치별 오류율 추이로 모델 상관 분석(AI-23 adoption_log와 동형)
- 전수 검수는 신규 팩 온보딩·대량 편입 시에만; 일상 CI는 미실행(P2 advisory 스텝으로 수동 트리거)

**출력**: `[폐기 후보]`·`[검토 요청]` 라벨 + 사유 — 사람 리뷰 대기열로, 자동 수정 없음(DOC-DSN-33 리뷰 계층 준수).

### 4.3 AI-46 — AI 프로비넌스 (항목 단위 추적)

**목적**: FM-4 해소 — 편입 후에도 "어떤 문항·섹션이 어느 AI 배치 산출인가"를 영구 식별.

**구성**: `tools/ai/provenance_log.jsonl` (신규, git 추적 append-only — adoption_log.jsonl 동형). `ai_apply --write`가 편입 시점에 항목별 행 추가:

```jsonl
{"ts":"2026-11-27T…","exam":"eleceng","kind":"qbank|textbook|explain","item":"circuit/문제은행/ch02.md#Q26","draft_sha":"…","batch":"explain_2026-11-20","model":"gemini-…","applied_by":"human","edits":"none|modified"}
```

- `item`은 정본 내 안정 식별자(파일 상대경로 + `### Q{n}` 또는 교재 섹션 앵커) — 파일 이동 시 `sync_textbook_files --rename`가 동일하게 전파
- `draft_sha`는 writeDraft 메타의 `sha=`와 연결해 초안↔정본 대응
- 기존 AI 편입분은 소급 불가 — 커밋 이력 기반 부분 복원 스크립트를 1회 제공(`--backfill`, 추정 표시 `inferred:true`)

**용도**: ① 배치 롤백 스코프(`ai:rollback --batch` 후속 도구의 입력) ② `ai:stale` 재검증 타겟팅(개정 영향 AI 문항만 재검증) ③ 모델별 오류율 상관(verify_log와 batch·model 키 결합) ④ CQ-08의 스코프 식별 기반.

### 4.4 CQ-08 — 신규 AI분 zero-tolerance 게이트

**목적**: FM-5 해소 — 기준선 래칫("증가 금지")이 놓치는 "기준선 안 흡수"를 차단.

**구성**: `tools/check/check_ai_zero.js` (신규, 비LLM — 프로비넌스 + 기존 체커 조합). 로직:

1. AI-46 로그에서 지정 기간(`--since <date>` 기본 최근 배치) 편입 항목 목록 추출
2. 그 항목들에 한해 `check_answer_overlap`·`ai_dupcheck`·`check_ai_facts`를 스코프 실행
3. 스코프 내 결함 **0건** 요구 — 기존 기준선 잔여분(199건 등)과 무관하게 신규 AI분은 항상 청정

**게이트**: P1 차단. pre-push·CI에서 실행 — 단 프로비넌스 로그가 비어 있으면(구 편입분만 존재) 스킵. 소급 불가분은 `inferred:true` 항목도 동일 적용.

**의존**: AI-46 선행 필수(스코프 식별 수단). AI-46 없이는 대상을 알 수 없어 단독 구현 불가.

## 5. 도입 단계

| 단계 | 장치 | 이유 |
|---|---|---|
| Phase 1 | **CQ-07** check:aifacts | 비LLM·구현 최소·즉효 — 기록된 사고(FM-1)의 재발을 바로 차단. 기준선 초기 책정으로 기존 잔여 오염도 정량화 |
| Phase 2 | **AI-46** provenance | 후속 장치(CQ-08·ai:verify 증분)의 기반 데이터 — 늦을수록 소급 불가 구간이 늘어나 조기 도입이 유리 |
| Phase 3 | **CQ-08** zero-tolerance | AI-46 의존 — 스코프 게이트 |
| Phase 4 | **AI-45** ai:verify | LLM 비용·오탐 튜닝이 가장 큼 — 샘플링으로 시작해 오류율 실측 후 기준선 설정 |

각 Phase는 독립 머지 가능 — Phase 순서는 의존 관계(4.4→4.3)와 비용, 리스크 역산(즉효 우선)으로 정함.

## 6. 비용·리스크

- **CQ-07 오탐**: 법령 원문 인용이 거절 문구 패턴과 충돌 가능 → 인용 블록 면제로 설계 반영. 잔여 오탐은 패턴 예외 등록(코드 내 allowlist 사유 주석)
- **AI-45 비용**: 전수 LLM 검수는 팩당 수백 호출 — `--sample`·`--since` 증분 기본값으로 일상 비용 억제. 모델 교체 시 verify_log의 batch·model 키로 품질 회귀 감지
- **AI-46 로그 증가**: append-only JSONL이라 장기적으로 커짐 — 연 단위 아카이브(기존 stats 파일 관례)로 관리. item 식별자는 파일 리네임 전파를 sync 도구에 위임해 드리프트 방지
- **게이트 연쇄 실패**: CQ-08이 check:answers 스코프를 재실행하므로 기존 게이트 버그가 새 게이트에서도 발화 가능 — 스코프 실행은 동일 함수 재사용(판정 로직 복제 금지)으로 일관성 유지

## 7. 미결 사항

- CQ-07의 "영어 잔재" 판정 기준(고유명사 화이트리스트 범위 — ISO·KCS 규격명 등)은 패턴 초안 구현 후 잔여분 실측으로 확정
- AI-45의 `unverifiable` 처리 정책(인용 부족 문항을 check:answers 쪽으로 돌려 인용 보강 요구할지, 별도 대기열로 둘지) — 도구 구현 시 판정 분포 보고 결정
- AI-46 `--backfill`의 커밋 이력 추정 정확도 — 대량 편입 커밋이 항목 단위로 분리 불가한 경우 스킵하고 신규분만 추적하는 것을 원칙으로 함
- CQ-08의 `--since` 기본값(최근 배치 vs 최근 30일) — provenance 로그 적재 패턴 관찰 후 고정
