### 1. 배경·목적

#### 1.1 현행 SM-2의 한계

- **이진 품질**: "외움"(5점)/"헷갈림"(2점)만 기록 — "비슷하지만 애매했던 카드"와 "완전히 몰랐던 카드"를 구분하지 못해 간격이 과소·과대 추정된다.
- **고정 간격 공식**: `1일 → 3일 → EF×누적` — 카드별 난이도·사용자별 기억 특성을 반영하지 못한다. easiness는 갱신되지만 어려운 카드/쉬운 카드의 초기 간격이 동일하다.
- **망각 곡선 부재**: nextReview만 저장하고 "지금 기억할 확률"을 추정하지 않는다 — due 판정이 경계값 비교로만 이뤄진다.
- **검증 실측**: `audit_study_quality.js` T3 시뮬(30일·60장·결정론)에서 SM-2는 302회 복습·기한 6일 분산 — 간격이 전 카드 동일 궤적을 따라 클러스터링된다.

#### 1.2 목표

- FSRS-4.5의 DSR(Difficulty·Stability·Retrievability) 모델로 카드별·사용자별 망각 곡선을 추정한다.
- 공개 API(`updateCardSchedule`·`getDueCards`·`getDueCount`)와 저장 키(`fc_spaced_repetition`)를 유지해 호출부·동기화·백업을 무수정으로 보존한다.
- T3 시뮬을 SM-2/FSRS 비교 계측기로 확장해 개선 폭(복습 총량·기한 분산·예측 정확도)을 정량 입증한다.

#### 1.3 비목표

- 4단계 레이팅 UI(Again/Hard/Good/Easy 버튼) — 1차는 이진 입력 유지, 별도 개정으로 분리 (§8).
- 사용자별 파라미터 최적화 — 리뷰 로그 스토리지가 선행되어야 함 (§8).
- FSRS-5/6/7 — 당일 복습 반영·소수 간격 등은 추가 복잡도 대비 이득 미미. 4.5가 안정 균형점 (Anki 통합 버전의 바로 상위 마이너).

### 2. FSRS-4.5 모델 명세

#### 2.1 카드 상태

| 필드 | 의미 | 범위 |
|---|---|---|
| `d` | Difficulty 난이도 | 1~10 |
| `s` | Stability 안정도 (일) | >0, 망각 확률이 90%가 되는 간격 |
| `due` | 다음 복습 기한 | YYYY-MM-DD |
| `lastReview` | 마지막 복습일 | YYYY-MM-DD |
| `reps` | 누적 복습 수 | ≥0 |
| `lapses` | 망각(Again) 누적 수 | ≥0 |

#### 2.2 망각 곡선·간격

```
R(t, s) = (1 + FACTOR · t / s) ^ DECAY        # DECAY = -0.5, FACTOR = 19/81
I(r, s) = s · FACTOR⁻¹ · (r^(1/DECAY) - 1)    # 목표 기억률 r=0.9 해의 간격
```

복습 시점의 경과일 `t`로 기억 확률 `R`을 계산하고, 성공/실패 각각 안정도 갱신식에 입력한다. 간격 `I`는 갱신된 `s`와 목표 기억률 0.9에서 산출한다.

#### 2.3 갱신식 (기본 파라미터 w[0..16])

- **최초 학습**: `d = w[4] - (rating-3)·w[5]`(1~10 절단), `s = w[rating-1]`(레이팅별 초기 안정도)
- **성공 (G≥3)**: `s' = s·(1 + e^{w8}·(11-d)·s^{-w9}·(e^{w10·(1-R)}-1)·hardPenalty·easyBonus)`
- **실패 (Again)**: `s' = w11·d^{-w12}·((s+1)^{w13}-1)·e^{w14·(1-R)}`, `d` 상승 갱신 후 절단
- **난이도 갱신**: `d' = w7·initD(4) + (1-w7)·(d - w6·(rating-3))`, 1~10 절단

기본 파라미터(FSRS-4.5, 17개 w0~w16)는 `src/study/fsrs.js`에 상수로 내장한다 — 개인 최적화는 후속 단계 (§8). w17~18(FSRS-5의 당일 복습 스텝)은 현행 이진 UI에 불필요해 미포함.

#### 2.4 레이팅 매핑 (1차 — 이진 입력 유지)

| UI 입력 | FSRS Rating | 근거 |
|---|---|---|
| "헷갈림" | Again (1) | SM-2의 rep=0 리셋에 대응 — 망각으로 간주 |
| "외움" | Good (3) | 중립 성공 — Hard(2)/Easy(4)는 2차 UI 개정에서 개방 |

이진 입력에서도 FSRS는 SM-2 대비 ① 카드별 초기 안정도 차별화, ② 누적 난이도 d의 상태 추적, ③ 망각 확률 R 기반 간격 산출의 이점을 갖는다. 4단계 레이팅은 개선을 키우지만 UI·핸들러·툴팁 개정이 별도 범위다.

### 3. 저장소·마이그레이션

#### 3.1 저장 스키마

`fc_spaced_repetition` 키 유지 — 시험별 접두사·백업·동기화 경로 무수정. 레코드만 교체:

```js
// 구 (SM-2)
{ repetition, easiness, nextReview, lastReview }
// 신 (FSRS)
{ v: 2, d, s, due, lastReview, reps, lapses }
```

`v: 2` 마커로 구 레코드와 구분한다.

#### 3.2 구 레코드 → FSRS 변환 (지연 마이그레이션)

전면 일괄 변환 대신 **레코드 단위 지연 변환**: 스케줄 로드 시 `v` 없는 레코드를 접할 때 변환한다. 일괄 쓰기 없이 다음 복습에 자연 흡수되어 대규모 덮어쓰기·동기화 충돌 위험이 없다.

| SM-2 필드 | → FSRS 근사 |
|---|---|
| `repetition` | `reps` 그대로 계승 |
| `easiness` | `d` 역산: `d = clamp(11 - easiness·4, 1, 10)` — EF 1.3→d≈10(어려움), 2.5→d≈1(쉬움) |
| `nextReview - lastReview` | 경과 간격을 `s` 근사: `s = max(interval, 0.4)` — 간격이 곧 안정도 근사치 |
| `nextReview` | `due` 그대로 계승 — 기존 복습 일정 보존 |

- `lapses`: `repetition === 0` && `lastReview` 있으면 1로 추정, 아니면 0.
- 변환 함수 `migrateSm2Record(rec)`는 순수 함수로 분리해 단위 테스트 대상으로 한다.

#### 3.3 초기화·백업 정합

- `F-09` 진도 초기화는 키 삭제 경로라 무수정.
- `state.js` 백업 키 목록·`sync.js` 스냅샷은 키 단위라 레코드 형식 변경과 무관.
- Supabase 동기화는 불투명 blob 전송 — 스키마 변경 전파 없음.

### 4. 공용 API 계약 (무수정 유지)

```js
updateCardSchedule(cardId, knew)  // knew → Rating.Again : Rating.Good
getDueCards()                   // due <= 오늘 필터 — 필드명만 nextReview→due
getDueCount()
```

호출부 영향 0:

- `listeners-flashcard.js` (2곳 호출) · `statement-tracker.js`(위임) · `flashcard.js`·`analysis-view.js`·`study-calendar.js`(due 조회) — 전부 무수정.
- 진술 트래커(DR-03)는 동일 키·동일 함수 경유 — 자동으로 FSRS 적용.
- `recommendations.js` due 요약(`오늘 복습할 카드 N장`) — `getDueCards` 경유라 무수정.

### 5. 배분·분석 연동

- `computeSubjectAllocInputs(dueCardIds)`는 `getDueCards()` 결과를 사용 — 출력 형식 동일이라 `dueBoost`(SC-13) 로직 무수정.
- **후속 확장(별도 검토)**: FSRS의 `R(due-오늘)` 값을 dueBoost 입력으로 쓰면 "기한 지남" 이진 대신 "망각 임박도" 연속값으로 정교화 가능. 1차 범위 아님.

### 6. 품질 게이트·검증 계획

#### 6.1 감사 시나리오 확장 (SQ-03)

- **T3 이중 계측**: 동일 30일 시뮬을 SM-2/FSRS 두 엔진으로 실행 → `reviews 총량·medRep/medStability·distinctDueDates` 병기. 기대: FSRS는 난이도 차별화로 기한 분산 ↑, 실패 카드는 국소 리셋.
- **T4 신설(감사 시나리오)**: 예측 정확도 — 가상 시계로 카드를 due 경계 ±1일에 복습할 때 FSRS의 R 추정이 실제 레이팅 결과와 단조 정합(간격 ↑ → R ↓).
- 회귀 기준선 `--update` 갱신 후 `--check` 게이트 편입은 기존 구조 그대로.

#### 6.2 단위 테스트

- `migrateSm2Record`: rep/EF/간격 → d·s 매핑 경계값·null 방어.
- `updateCardSchedule`(FSRS): 최초 학습 초기 s·d, 성공 시 s 단조 증가·due 전진, Again 시 s 하락·lapses 증가, 목표 기억률 기반 간격 상한.
- 저장 스키마: `v:2` 마커 부여·구 레코드 읽기 호환.
- 기존 `D5` 시나리오 검사(SM-2 단조성)를 FSRS 불변식으로 개정 — 시나리오 이름·검사 id는 유지해 기준선 키 안정.

#### 6.3 리스크·완화

| 리스크 | 완화 |
|---|---|
| 마이그레이션 근사 오차로 간격 왜곡 | `due`는 계승하므로 단기 일정 보존 — 첫 복습부터 FSRS 궤적으로 수렴 |

- **4단계 레이팅 UI**: `fc-easy/hard` 2버튼 → Again/Hard/Good/Easy 4버튼. FSRS-4.5의 효과 극대화에는 필수적이나 키보드 단축키·접근성·모바일 배치 재설계 필요.
- **개인 파라미터 최적화**: 리뷰 로그(`{cardId, rating, elapsedDays}` 링버퍼) 영속화 선행 → 사용자별 `w` 피팅. FSRS-rs/optimizer 포팅 또는 요약 통계 근사.

- **FSRS-6+ 검토**: 당일 복습·소수 간격 — 도입 근거 데이터 축적 후 재평가.

### 9. 시험일 리드타임 근거 (D-17 `minExamLeadDays` = 90일)

FSRS의 스케줄링 효과는 누적 데이터 없이 즉시 발휘된다 — 기본 파라미터(w0~w16)는 사용자 학습 없이 첫 복습부터 적용된다. "누적 며칠이 필요한가"의 실질 변수는 알고리즘이 아니라 **콘텐츠 커버리지**다.

#### 9.1 카드별 기억률 시뮬레이션 (본 문서 구현체 실측)

카드 최초 학습 시점별 시험일 기억률 — 전부 "외움(Good)" 응답, 목표 기억률 0.9:

| 최초 학습 | 복습 | 최종 안정도 | 시험일 R |
|---|---|---|---|
| D-1 | 1회 | 2.4일 | 95.4% |
| D-7 | 2회 | 7.2일 | 92.7% |
| D-14 | 3회 | 21.4일 | 97.4% |
| D-30 | 4회 | 57.9일 | ~100% |
| D-90 | 5회 | 145.7일 | 99.8% |

카드 1장은 전날 학습해도 목표 기억률을 넘지만, **2~3회 복습으로 안정도가 3주 이상** 커지려면 최초 학습이 D-14 이전이어야 한다.

#### 9.2 총량 관점 — 90일의 구성 (학습일 기준)

- **1회전**: 1,123장 ÷ 학습일당 50장 ≈ 23학습일 → ×7/5 ≈ 33달력일
- **안정화 마진**: 마지막 주차 카드가 2~3회 복습될 최소 14일 — 병행 시 1회전에 흡수되나 상한 안전분으로 ×1.5 → ~48달력일
- **퀴즈 1회전**: 1,937문 ÷ 학습일당 ~30문 ≈ 64학습일 → ×7/5 ≈ **90달력일** (병행 제약)
- `max(카드, 퀴즈)` 중 큰 쪽 = **90일** — cosmetic 선언값과 일치
- ※ 역사적 참고: 구 선언값 63일은 문제은행 445문 시절 산출(45학습일×7/5). 문제은행 확충(1,937문)으로 90일로 상향 — 학습일당 페이스를 10문에서 ~30문으로 조정한 선언값이며, 10문 페이스 엄밀 적용 시 ~271일이 된다

#### 9.3 후속: 개인 최적화 누적 요건 (§8)

개인 파라미터 피팅은 리뷰 로그 `{cardId, rating, elapsedDays}` 수백~수천 건이 필요하다 (Anki 최적화기 실질 하한 ~1,000리뷰). 일 60~80장 복습 기준 **4~6주 누적** — 90일 리드타임 안에서 자연 충족된다.

### 1. 배경·목적

FSRS-6은 현행 프로덕션 버전(Anki 24.11+·fsrs-rs 6.x·ts-fsrs 기본). 4.5 대비 변경이 세 갈래이며 모두 이 앱에 직접 실익이 있다:

- **학습 가능한 망각 곡선 지수 `w20`** — 곡선 쇄도가 고정 상수(-0.5)에서 피팅 가능 파라미터로 승격. 공식 벤치 RMSE(bins) −6%. D-18 리뷰 로그의 첫 피팅 대상.
- **당일 복습 수식** `S' = S·e^{w17(G-3+w18)}·S^{-w19}` — 4.5에서는 `elapsed=0`이면 r=1이라 성공 복습의 안정도 증분이 0이었다. FSRS-6은 저안정도 카드의 당일 성공을 실질 성장(`sinc` 하한 1, 성숙 카드는 비감소)으로, 당일 실패를 전용 단기 감소로 모델링한다.
- **난이도 선형 감쇠 + 지수 초기 난이도 + 랩스 하한** — d 포화 보정, 실패 시 단기 하한 적용.

**비목표**: 서브일 learning steps(당일 시간 단계) 도입, ts-fsrs 의존성(수식 포팅으로 충분, ~150줄), 퍼즈(fuzz) 적용, 4버튼 UI, 개인 파라미터 피팅.

### 2. 수식 델타 (fsrs-rs 6.x / ts-fsrs 정본 기준)

파라미터 벡터 `w0..w20` — 공개 기본값:

```
[0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001, 1.8722, 0.1666,
 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014, 1.8729, 0.5425, 0.0912, 0.0658, 0.1542]
```

`S_MIN` 0.1→0.01, `S_MAX`·`MAX_INTERVAL` 36500 유지.

| 함수 | FSRS-4.5 | FSRS-6 |
|---|---|---|
| `initStability(G)` | `w[G-1]`, 하한 0.1 | 동형, 하한 0.01 (신규 기본값) |
| `initDifficulty(G)` | `w4 − w5·(G−3)` 선형 | **`w4 − e^{w5·(G−1)} + 1`** 지수형, clamp[1,10] |
| `retrievability(t,s)` | `(1 + 19/81·t/s)^{-0.5}` | `(1 + FACTOR·t/s)^{-w20}`, `FACTOR = 0.9^{-1/w20} − 1 ≈ 0.98035`. `R(s,s)=0.9` 불변식은 파라미터 무관 유지 |
| `nextInterval(s)` | `s/19·81·(0.9^{-2}−1)` | `s/FACTOR·(r^{-1/w20} − 1)` — 목표 0.9면 **정확히 `s`**로 환산 (반올림·하한1·상한 동일) |
| `nextDifficulty(d,G)` | `d − w6(G−3)` → 평균 회귀 | `Δd = −w6(G−3)`, **`Δd' = Δd·(10−d)/9`**(선형 감쇠), `d' = w7·D0(4) + (1−w7)·(d+Δd')` |
| `recallStability` | `s·(1 + e^{w8}(11−d)s^{-w9}(e^{w10(1−r)}−1)·hard·easy)` | **무수정** |
| `forgetStability` | `min(w11·d^{-w12}((s+1)^{w13}−1)e^{w14(1−r)}, s)` | `min(max(s_f, S_MIN), s·e^{−w17·w18})` — 랩스 시 안정도가 반드시 당일-Again 계수만큼 이하로 감소하는 상한 (단기 하한 아닌 상한) |

### 3. 어댑터 라우팅 결정

| 조건 | 안정도 갱신 | 난이도 | due |
|---|---|---|---|

### 1. 배경·목적

#### 1.1 현재 구조의 두 한계

- **관측 불가**: FSRS는 카드별 `s`·`d`를 추적하지만 레이팅 이력을 보존하지 않는다 — 모델 예측 R과 실제 응답의 대조(효능 실측), 개인 파라미터 피팅(LEARNING_ALGORITHM_DESIGN §8), 이진 레이팅의 손실 정량화가 전부 불가능하다.
- **목표 불일치**: FSRS의 목적 함수는 장기 유지(간격 극대화 하의 R=0.9 유지)다. 시험 대비의 실제 목적 함수는 **시험일 시점의 R 최대화**다 — 기한 미도래 카드 중 시험일까지 망각이 진행될 카드는 현재 큐 어디에도 표면화되지 않는다.

#### 1.2 목표

- `updateCardSchedule`의 단일 funnel에 리뷰 로그 링버퍼를 부착해 레이팅 이력을 영속화한다 (D-18).
- 저장된 `s`·`lastReview`만으로 계산 가능한 `R_exam`을 이용해, 시험 임박 구간에서 "시험일까지 잊을 카드"를 추가 인출 세션으로 표면화한다 (D-19). **간격 재작성이 아닌 추가 세션** — 스케줄 왜곡 없음.

#### 1.3 비목표

- **4단계 레이팅 UI** (Again/Hard/Good/Easy): LEARNING_ALGORITHM_DESIGN §8의 별도 개정. 로그로 이진 레이팅의 실측 손실을 먼저 정량화한 뒤 재평가한다.
- **개인 파라미터 피팅**: 로그 누적 후 후속 단계. 본 설계는 수집 계층만 만든다.
- **스케줄 알고리즘 자체 변경**: `fsrs.js` 갱신식·간격 함수 무수정.
- **시험일 목표 R의 진술 드릴 적용**: 진술 트래커는 동일 스케줄 키를 공유하지만, 최종 인출 세션은 카드 세션으로 범위를 한정한다 (진술 확장은 후속).

`storage-keys.js`에 키 추가 — 다른 학습 이력과 동일하게 `scopedKey()` 시험 접두사:

```js
FC_REVIEW_LOG: 'fc_review_log', // [{c, r, e, t}...] — 최대 2,000건 FIFO
```

레코드 (compact 키 — `statement_stats`의 `{j,w,cid,t}` 관례 준용):

| 필드 | 의미 |
|---|---|
| `c` | 카드·진술 id |
| `r` | FSRS 레이팅 — 이진 입력이라 `1`(Again)·`3`(Good)만 발생 |
| `e` | 직전 복습 이후 경과일(실수) — 최초 학습은 `0` |
| `t` | 복습 시각 unix ms |

- **상한 2,000건 FIFO**: Anki 최적화기 실질 하한 ~1,000리뷰(LEARNING_ALGORITHM_DESIGN §9.3)의 2배 여유. 약 120KB — localStorage·백업 부담 이내.
- **진술 공용 경로 자동 포함**: DR-03이 동일 `updateCardSchedule`을 경유하므로 진술 레이팅도 함께 쌓인다 — 피팅 시 카드/진술 분리는 id 접두사로 판별 가능.

#### 2.2 기입점·API

`spaced-repetition.js` 내부에 append — `updateCardSchedule`이 카드·진술 공용의 유일한 스케줄 갱신 통로이므로 호출부 추가 없음:

```js
appendReviewLog({ c: cardId, r: rating, e: elapsedDays, t: nowMs() });
```

- 읽기는 `getReviewLog()` (후속 피팅·진단용, 이번 범위는 테스트에서만 사용).
- 쓰기 비용: 카드 뒤집기 1회당 localStorage 쓰기 1건 추가 — 기존 스케줄 쓰기와 동일 주기, 성능 영향 없음.

#### 2.3 백업·동기화·초기화 정합

- `BACKUP_KEYS` 추가 — 학습 이력(`quiz_results`·`statement_stats`)과 동일 성격이며 복원 시 피팅 데이터 손실 방지. `RESET_KEYS`는 `...BACKUP_KEYS` 전개로 자동 포함.
- `SYNC_EXCLUDE` 미포함 — 동기화는 다른 학습 데이터와 동일 정책 (불투명 blob, 스키마 변경 전파 없음).
- 카드 id·시각만 담아 학습 내용 비포함 — `내 사용 통계`와 동일한 프라이버시 등급.

### 3. 시험일 목표 R 최종 인출 (D-19)

#### 3.1 위험 카드 선별

저장된 스케줄 레코드 `{s, due, lastReview}`로 시험일 기억률을 추정:

```
R_exam(card) = retrievability(examDate − lastReview, s)   // fsrs.js 기존 함수 재사용
risk = { card | due > examDate ∧ R_exam < EXAM_R_THRESHOLD }
```

- **`due > examDate` 조건**: 다음 예정 복습이 시험일 이후인 카드만이 "스케줄 사각지대"다. 기한 도래 카드(due ≤ today)는 due 큐가 소유해 중복 노출·CTA 이원화 차단 (EXP-1), 기한이 시험일 전인 카드는 예정 복습으로 R이 회복되므로 제외한다.
- **`EXAM_TARGET_R = 0.95`**: 시험일 목표 기억률 미달 카드 (원안 0.85는 `due > exam`이면 R>0.9인 불변식으로 공집합 — 헤더 정정 노트 참조). 기한 내 복습이 예정된 카드는 제외되므로 남은 것은 "다음 복습이 시험 후이거나 없는" 카드다.
- 상수는 모듈 내 상수 — 시험별 조정 필요 시 manifest `study` 확장은 후속으로 유보.

#### 3.2 큐 항목

`buildTodayQueue`에 `kind: 'examr'` 항목 — 위치는 ④ 취약 진술 직후 (취약 인출 계열의 연장), ⑤ 일일 챌린지·⑥ 개인화 추천 앞:

```js
if (dday !== null && 0 <= dday && dday <= EXAM_R_WINDOW_DAYS && risk.length) {
    title: `시험 전 최종 인출 ${n}장`,
    reason: `시험일까지 기억률 ${threshold}% 미만 예상 — 지금 한 번 더 인출`,
    actions: [{ click: 'startExamRiskReview', label: '인출 세션', ... }]
}
```

- **`EXAM_R_WINDOW_DAYS = 14`**: D-5 플랜의 "최종 인출" 구간을 약간 넓게 커버. dday 부호·null 방어 필수 (미설정·D+ 경과 시 비표시).
- **`EXAM_R_SESSION_CAP = 60`**: 세션 상한 — risk 정렬(R_exam 오름차순) 상위만. 대량 누적 시 크램 벽 방지.

#### 3.3 세션 동선 — `onlyIds` 일반화

현재 `startDueReview`는 `state.flashcards.dueOnly`(1회성 플래그)로 due 집합을 넘긴다. 시험 위험 카드는 임의 id 집합이라 동일 패턴을 일반화:

```js
state.flashcards.onlyIds = riskSortedIds;   // 1회 적용 후 자동 해제 (dueOnly와 동형)
```

- `loadFlashcards()`는 `onlyIds` 우선 확인 — `dueOnly`는 기존 호출부 호환으로 유지, 신규 경로는 `onlyIds` 사용.
- 세션 시작은 `startExamRiskReview`(analysis-view.js, `startDueReview`와 동형): 과목 로드 → `onlyIds` 설정 → flashcard-view.

#### 3.4 순서 정합

R_exam 오름차순 정렬로 "가장 잊을 카드"를 먼저 출제 — 세션 도중 이탈해도 고위험분부터 소화된다.

## 시험일 due 클램프 설계 — D-20

> 상위 문서: [`SPEC.md`](../SPEC.md) D-20 · [`LEARNING_ALGORITHM_DESIGN.md`](LEARNING_ALGORITHM_DESIGN.md) (D-18·D-19) · [`LEARNING_ALGORITHM_DESIGN.md`](LEARNING_ALGORITHM_DESIGN.md)
> 범위: FSRS 스케줄 갱신 경로(`updateCardSchedule`)에 시험일 상한 정책을 얹는 어댑터 계층 변경
> 상태: ✅ 구현됨 (2026-10-13) — 임계값은 구현 전 검증에서 발견된 공집합 결함을 반영해 0.85→목표 R 0.95로 확정
> **관련 SPEC ID**: `D-20`(시험일 due 클램프) · `D-19`(시험일 목표 R 최종 인출 큐) · `F-07`(간격 반복 스케줄링)
> 원본 문서: `EXAM_DUE_CLAMP_DESIGN.md` — 구 DOC-DSN-28 (2026-10-17 본 문서로 통합)
> **범위**: platform · 판본: none

### 1. 배경·목적

#### 1.1 남은 목표 불일치

D-19는 시험일 기억률 미달 카드를 **추가 세션**으로 표면화하지만, 카드의 `due` 자체는 건드리지 않는다 — 사용자가 최종 인출 세션을 실행하지 않으면 그 카드는 시험 전에 복습되지 않는다. FSRS의 목적 함수(장기 유지)상 `interval > 잔여 일수`는 정상이나, 시험 대비 앱에서는 **"시험 전 복습 0회인 위험 카드"**로 직결된다.

#### 1.2 구현 전 검증에서 발견된 결함 — 0.85 임계는 공집합

FSRS(4.5·6 공통)에서 `nextInterval(s) ≈ round(s)` — due는 항상 **R=0.9가 되는 시점**으로 잡힌다. 따라서:

- `due > examDate` ⟹ 예정 간격 > 잔여일 ⟹ 시험일까지 경과 < `s` ⟹ `R_exam` 하한 ≈0.90
- `due > exam ∧ R_exam < 0.85`는 **실데이터에서 불가능** — D-19 원 설계의 위험 집합은 진짜 레코드에서 비어 있고(테스트는 불가능한 픽스처로만 통과), 같은 조건의 클램프도 데드 코드가 된다

**실제 위험대는 (0.90, 0.95) 밴드**다: `due > exam`인 카드는 시험 전 복습 0회인 채 시험일에 R이 0.90~0.95 근처로 미끄러진다. 시험일 목표 기억률을 0.95로 두면(사용자 문서의 "하루 전 95%"와 일치) 비어있지 않은 위험 집합이 정의된다.

#### 1.3 목표

`updateCardSchedule`의 산출 `due`에 **조건부 시험일 상한**을 적용한다:

- 새 `due > examDate` **이고** 갱신 후 `s`로 예측한 `R_exam < 0.95`인 카드 → `due`를 `examDate − 1`로 당긴다.
- `R_exam ≥ 0.95`인 카드(시험일까지 목표 수준 유지 예정) → 클램프하지 않는다 — 무조건 상한의 크램 벽 차단.
- D-19 위험 선별 임계도 동일 상수(`EXAM_TARGET_R = 0.95`)로 교정 — 두 경로가 같은 위험 정의를 공유한다.

#### 1.4 비목표

- **`fsrs.js` 수식 변경**: 순수 함수 계층 무수정 — 정책은 어댑터 계층에 둔다.
- **목표 기억률 상향 스케줄링(0.90→0.95 간격 단축)**: T4 감사로 클램프 효과를 계측한 뒤 필요 여부를 판정한다 (§5 후속).
- **D-19 큐 제거**: 클램프는 재스케줄, D-19는 조기 노출 — 역할이 다르므로 유지한다 (§2.3).
- **진술 드릴 적용·미복습 카드 일괄 스윕**: 카드 복습 갱신 경로에 한정한다 (§2.5).
- **개념 숙달도 추정(BKT)**: 별도 후속 — 우선 베이지안 스무딩 정답률 등 경량 대안을 검토한다.

### 2. 클램프 정책

#### 2.1 적용 위치·조건

`updateCardSchedule`에서 `fsrsReview` + `nextInterval` 산출 직후, `due` 확정 전에 적용한다:

```js
const examStr = _examDateStr();             // STORAGE_KEYS.EXAM_DATE, 미설정 null
let due = todayKey(nextDate);               // 기존 산출
if (examStr && examStr > todayStr && due > examStr) {
    const rExam = retrievability(_daysBetween(examStr, todayStr), next.s);
    if (rExam < EXAM_TARGET_R) due = _shiftDateStr(examStr, -1);
}
```

- **시험일 소스**: `STORAGE_KEYS.EXAM_DATE`를 어댑터가 직접 읽는다 — 계층 방향 규칙(코어 모듈 간 역참조 최소화)과 순환 import 회피. 시험 스코프 키이므로 시험 전환 시 자연 분리된다.
- **클램프 대상일**: `examDate − 1` — 시험 직전 인출로 시험일 R을 최대화한다. D-1은 학습안내서가 "최종 인출 세션"으로 규정한 날과 일치한다.
- **R 판정 기준**: 갱신 후 `next.s`와 `elapsedAtExam = examDate − today`(방금 복습했으므로 lastReview=오늘)로 계산 — D-19의 `R_exam`과 동일 의미·동일 임계(`EXAM_TARGET_R = 0.95`) 공유.
- **발동 대역**: `due > exam`이려면 `s_new > dday`, `R < 0.95`이려면 `s_new < ~2.5·dday` — 즉 `s_new ∈ (dday, 2.5·dday)` 밴드의 카드만 당긴다.

#### 2.2 반복 당김 안전성

당겨진 카드를 D-19 세션 등으로 시험 전에 먼저 복습하면 재계산된다 — 새 `s`가 커져도 `R_exam < 0.95`·`due > examDate`면 다시 `examDate − 1`로 당겨진다. 이는 **결함이 아니라 의도된 재노출**: 목표 미달 카드는 시험 전날 정식 due로 다시 표면화된다. 무한 루프는 없다 — 클램프는 스케줄 갱신 1회당 due 1회 확정일 뿐이며, exam−1 복습 후 `s`가 자라면 `R_exam ≥ 0.95`로 자연 탈출한다.

#### 2.3 D-19와의 역할 분담

| 계층 | 동작 | 효과 |
|---|---|---|
| D-20 클램프 | `due` 재작성 (exam−1) | 복습 경로를 거친 위험 카드가 시험 전에 **정식 due 큐**로 확정 소화 |
| D-19 최종 인출 | `due` 무수정, 추가 세션 제안 (D-14 창) | **미복습 상태로 남은** 위험 카드의 조기 노출 — 클램프가 못 잡는 집합 |

클램프 후 `due = examDate − 1 ≤ examDate`이므로 해당 카드는 D-19 위험 집합(`due > examDate`)에서 자동 제외된다 — 두 경로의 카드 소유권 충돌은 없다.

#### 2.4 경계 조건

| 조건 | 동작 |
|---|---|
| `EXAM_DATE` 미설정·비정형 | 클램프 없음 (기존 동작) |
| `examDate ≤ today` (당일·지남) | 클램프 없음 — 방어 조건 명시 (`examStr > todayStr` 가드) |
| `due ≤ examDate` | 클램프 없음 — 시험 전 예정 복습 존재 |
| `due > examDate` ∧ `R_exam ≥ 0.95` | 클램프 없음 — 시험일 목표 유지 예정 |
| `due > examDate` ∧ `R_exam < 0.95` | `due = examDate − 1` |
| Again 평가 | `s` 하락 → 산출 간격이 짧아 `due ≤ examDate`가 되는 것이 일반 — 예외적으로만 발동 |

#### 2.5 스케줄 벽 크기

클램프는 **일괄 스윕이 아니라 복습 갱신 경로에서만 발동**한다 — 미복습 상태로 `due > exam`인 카드는 D-19(추가 세션)의 관할로 남는다. exam−1로 몰리는 상한은 창 내 실제 복습량으로 자연 제한되며, D-19가 D-14 창에서 선분산을 유도한다. 실측으로 벽이 문제가 될 경우 `examDate − 1` 대신 잔여 일수 비례 분산(예: `examStr − ceil(dday/k)`)을 후속으로 검토한다.

### 3. 구현 결과

### 1. 배경·목적

#### 1.1 역할 분리 — FSRS와 다른 질문

FSRS는 "카드 하나가 언제 잊히는가"를 예측한다 (복습 **시점** 관리). 학습 진단의 "단원 취약·합격 갭"이 묻는 것은 다른 질문이다 — "이 단원의 개념을 얼마나 숙달했는가" (숙달 **정도** 추정). 현재 진단은 휴리스틱 집계에 의존한다.

#### 1.2 현재 추정의 세 한계

- **정답 근거 부재**: `_aggregateChapterWrongs`는 오답 수만 센다 — 정답 시도를 세지 않으므로 "30회 중 5오답 단원"이 "1회 1오답 단원"보다 나쁘게 보인다. 정답률이 아니라 오답 빈도의 순위다.
- **소표본 노이즈**: 시도 1~2회 단원의 정답률은 0%·100% 극단으로 튄다 — 순위가 증거 없이 흔들린다.
- **찍기·실수 미분리**: 5지선다의 찍기 정답과 숙달 후 실수 오답이 같은 판정으로 섞인다.

#### 1.3 추적 축 결정 — 단원(chapter)

`conceptId`는 개념 분류가 아니다 — 수작업 `combo_pilot`의 진짜 개념 그룹은 16개뿐이고, 자동 생성 `combo_subject*`의 `conceptId`는 `"q:subjectN_qNN"` 원문항 출처 ID다. 반면 **단원 귀속은 전 증거 경로가 커버**된다:

| 증거 경로 | 단원 귀속 |
|---|---|
| 퀴즈·모의고사 정오 (`quizResults`) | `QUESTION_CHAPTERS` / `resolveQuiz().quiz.category` |
| OX·ㄱㄴㄷ 진술 판정 (`statement_stats`) | `cid`(§앵커·레거시 L####→`CID_SECTION` 환산) → 단원명 |
| 시뮬 약점 카드 (`weak_sim_*`) | 문항id → `QUESTION_CHAPTERS` |

개념 분류 체계 확장(콘텐츠 생성기에 의미 개념 부여)은 콘텐츠 파이프라인 작업 — 선행 후 개념 단위 KT로 재검토한다 (§5).

#### 1.4 목표·비목표

- **v1 (D-21)**: 단원별 정오 증거를 Beta 사후평균으로 추정해 소표본 노이즈를 제거 — 진단 카드의 순위 품질 개선.
- **v2 (D-22)**: 단원별 BKT로 숙달 확률 P(known) 추적 — slip/guess 분리로 v1의 잔여 한계 해소.
- **비목표**: FSRS 스케줄링 침범(시점 관리는 그대로) · 개인 파라미터 피팅(시험별 기본값, 단일 사용자 한계 명시) · conceptId 체계 확장(콘텐츠 파이프라인 후속) · 카드 자기평가를 숙달 증거로 사용(§2.1).

### 2. 증거 모델

#### 2.1 증거 정의

단원 숙달 증거 = **채점 가능한 정오 판정**만 사용한다:

| 경로 | 증거 | 단원 귀속 | 비고 |
|---|---|---|---|
| 퀴즈 문항 정오 | `quizResults[id].correct` | `resolveQuiz`→`quiz.category` / `QUESTION_CHAPTERS` | 현재 마지막 판정만 저장 — v1은 충분, v2는 §3.2 |
| 진술 판정 | `statement_stats[sid].{j,w}` — j회 중 w회 오판 | `cid` → 단원 | OX·ㄱㄴㄷ 공용, 정답 근거(j−w) 존재 |
| 시뮬 약점 카드 | `weak_sim_*` 오답 | 문항 → `QUESTION_CHAPTERS` | 오답 증거만 (기존과 동일) |

**제외**: 카드 자기평가(외움/헷갈림) — 자기보고 이진값이라 채점 증거가 아니며 이미 FSRS가 소비. FSRS 스케줄 데이터(d·s)도 숙달 추정에 직접 사용하지 않는다 — 모델 독립성 유지.

#### 2.2 증거 집계 계층

신규 순수 함수 `computeUnitEvidence(p)` (analysis-engine 또는 별도 모듈): 기존 `_aggregateChapterWrongs`의 귀속 로직(세 경로)을 확장해 **오답뿐 아니라 정오 건수 모두**를 단원 버킷으로 집계한다.

```js
// `${subj}|${chapter}` → { subject, chapter, attempts, corrects, wrongs }
```

- (a) `quizResults` 전건: correct=true도 카운트 (기존은 오답만)
- (b) `weak_sim_*`: 오답 증거로 카운트 (기존과 동일)
- (c) `statement_stats`: `attempts += j`, `corrects += j−w`, `wrongs += w` — 졸업 진술(`streak ≥ 3`)도 **과거 증거로는 유효**하므로 집계에 포함 (현행 약점 집계의 졸업 제외 규칙과 차이 — 숙달 추정에서는 졸업=강한 숙달 증거이므로 정답으로 반영하는 것이 정합)

### 3. 추정기

#### 3.1 v1 — Beta 사후평균 (D-21)

단원별 정답률을 `Beta(α₀+corrects, β₀+wrongs)` 사후평균으로 추정한다:

```
P_unit = (α₀ + corrects) / (α₀ + β₀ + corrects + wrongs)
```

- **사전**: `α₀ = 4, β₀ = 3` (합격선 ~60%를 중심으로 한 약한 사전 — 약 7회 증거분의 무게. 시험별 조정은 manifest `study.kt.prior` 확장으로 유보)
- **효과**: 증거 1~2건 단원은 사전 쪽으로 당겨져 극단 0%·100% 순위를 방지, 증거 20+ 건은 실측에 수렴
- **소비자**: `computeSubjectWeakChapters`/`computeChapterWeakness`의 정렬 기준을 `wrongs` → `P_unit` 오름차순으로 교체(기존 `wrongs` 필드는 표시용 유지), `computePassGap` 퀴즈 폴백 경로의 과목 정답률도 동일 스무딩 적용 여부 검토
- **변경 폭**: 집계 확장 + 정렬 기준 교체 + 표시 문구("오답 N회" → "숙달 추정 M%") — 진단 카드의 **행동·위치 불변, 순위 품질만 개선**

#### 3.2 v2 — BKT (D-22)

단원별 은닉 숙달 상태 `P(L)`를 관측 시퀀스로 갱신한다:

```
관측 후:  P(L|o) = P(L)·(1−S)/[P(L)·(1−S)+(1−P(L))·G]      (정답)
         P(L|o) = P(L)·S/[P(L)·S+(1−P(L))·(1−G)]           (오답)
전이:    P(L) ← P(L|o) + (1−P(L|o))·T                      (학습률)
```

- **파라미터** (시험별 기본값, `manifest.study.kt` 오버라이드 허용):
  - `P₀` 초기 숙달 = 0.30 (콜드스타트 중립)
  - `T` 기회당 학습률 = 0.08 (복습형 재노출 가정)
  - `G` 추측 = 0.15 (5지선다 근사; OX 진술은 0.30 — 이진 판정의 추측 여지 반영, 경로별 G 분리)
  - `S` 슬립 = 0.10
- **시퀀스 요구**: BKT는 관측 **순서**가 필요하다 — 현재 `quizResults`는 최종 판정만 보존해 시퀀스 불가. v2 선행 조건으로 **판정 로그를 확장**한다: D-18 리뷰 로그의 진술 레코드(`{c,r,e,t}`)는 시퀀스를 이미 보유하고, 퀴즈 판정은 별도 compact 로그(`fc_judgment_log` 또는 기존 로그에 `k:'q'` 타입 구분 확장)를 추가한다 — 스키마 결정은 구현 설계 시점에.
- **망각 비모델 명시**: BKT는 관측 간 학습률만 갱신하고 시간 감쇠가 없다 — "현재 숙달 스냅샷" 용도로 한정하고, 시점 관리는 계속 FSRS에 둔다 (역할 분리가 본 설계의 전제).
- **소비자**: 단원 `P(L)`을 취약 랭킹·합격 갭에 사용 (낮은 순). 표시는 "숙달 추정 M%". 졸업 기준 `P(L) ≥ 0.9`는 전통적 BKT 관례.
- **v1과의 관계**: v2는 v1의 대체가 아니라 정밀화 — v1의 증거 집계 계층(`computeUnitEvidence`+로그)을 그대로 입력으로 쓰며, 추정기만 Beta→BKT로 교체. v1이 데이터·소비자 통로를 먼저 만든다.

```js
{c: 문항 id, k: 'q', ok: 1|0, t: unix ms}   // 퀴즈·시뮬 문항 판정 — recordQuizJudgment()
{c, r, e, t}                                // 스케줄 이벤트 (기존) — k 없음 = 레이팅 레코드
```

- 기입점: `views/quiz.js`의 `quizResults` 기록 2곳(텍스트·선택지 채점) + `exam-sim-arena.js` `submitExam` 루프(문항 단위 전건 — **약점 집중 오답 모의고사(`exam-sim-weak`)도 동일 세션을 공유해 자동 포함**, 로그 id는 `weak_quiz_*`·`weak_exam_*` 접두사라 소비자가 원문항으로 정규화). ㄱㄴㄷ 진술 판정은 기존 경로(`recordStatementJudgments`→`updateCardSchedule`)로 이미 유입 — 문항·진술 이중 계수는 소비자가 `k` 필터로 선택

- **conceptId 개념 분류 확장**: 콘텐츠 생성기가 `q:...` provenance 외에 의미 개념을 부여하도록 확장 후 개념 단위 KT 재검토.
