## 1. 서사 유형 5분류

이야기형 교재의 서사는 도입 형식에 따라 5유형으로 나뉜다. 한 과목은 **주 유형 1종 + 보조 유형**으로 설계하고, 유형 간 혼합은 전체 서사의 톤을 해치지 않는 범위로 제한한다.

| 유형 | 콘텐츠 방식 | 적합한 과목 | 서사의 문제해결 구조 |
|------|------------|------------|---------------------|
| **드라마형** | 인물과 사건을 통해 개념 학습 | 법령, 행정, 보험 | 인물의 실수·갈등 → 대화로 개념 정립 → 교훈 |
| **탐정형** | 단서를 찾아 정답을 추론 | 손해사정, 산업안전 | 사건 제시 → 단서 수집 → 독자 추론 유도 → 정답·근거 공개 |
| **모험형** | 단계별 임무를 수행하며 지식 습득 | 화장품 제조, 품질관리 | 임무 부여 → 절차·기준 습득 → 임무 완수 |
| **시뮬레이션형** | 실제 업무 상황을 체험 | 손해평가, 감정평가 | 실무 상황 재현 → 판단 요구 → 피드백 |
| **캐릭터 성장형** | 주인공의 성장과 함께 학습 | 전 과목 공통 | 무지 → 시행착오 → 숙련 → 전문가 (과목 전체 아크) |

## 2. PassOK 권장 조합: 드라마형 + 탐정형 + 캐릭터 성장형

PassOK의 이야기형은 **주 유형(드라마 또는 탐정) + 캐릭터 성장형을 배경 아크**로 하는 조합을 권장한다.

**근거:**

- **기존 스펙이 이미 이 구조** — ST-01(주인공 실수 경험)·ST-04(실수→교훈 🔖 기억 태그)·ST-05(에필로그+예고)·ST-07(통합 에필로그)는 드라마형+성장형 문법이다. cosmetic 팩(민수·현우·수진 주인공 + 지연 멘토, PASSMULA 세계관)이 실증 구현체.
- **시험 특성과의 정합** — 등록 시험 대부분이 법령·판단 기준 암기+사례 추론형이라, 인물 사건으로 맥락을 주는 드라마형과 단서 추론을 훈련하는 탐정형이 직접 부합.
- **모험형은 성장형에 흡수** — "단계별 임무"는 성장 아크의 챕터 구조로 표현 가능 (현재 cosmetic의 과목별 여정 구조가 사실상 이에 해당).
- **시뮬레이션형은 텍스트 교재의 역할이 아님** — 실무 상황 체험은 주관식 연습·모의고사·Formula OS 같은 인터랙티브 기능이 담당한다. 이야기형에 억지로 넣으면 서사-본문 비중이 깨진다 (§5 비율 규칙).

## 3. 유형별 서사 패턴

### 3.1 드라마형 — 인물 사건으로 개념 체화

```
📖 ┈┈┈┈ **이야기** ┈┈┈┈

[상황 묘사 — 인물이 구체적 판단 지점에 놓임]
[대화 — 오해·혼란 노출 ("A면 되지 않나요?")]
[멘토/사건의 반전 — 본문 개념으로 해소 ("그게 흔한 함정이에요")]
[정리 — 🔖 기억 태그 또는 한 줄 교훈]

┈┈┈┈ **본문** ┈┈┈┈ 📘
```

- 서사 속 법령 용어·수치는 **반드시 인접 본문에 있는 것만** 사용 (BP-11 — 서사 속 `제N조`·`%·점·배` 토큰이 본문에 없으면 게이트 경고).
- 대화는 2인 구조(학습자+멘토)가 기본. 3인 이상은 발화 추적이 어려워 비권장.
- 예시: cosmetic 1과목 — "등록이 아니라 **신고**" 함정을 민수의 오해로 노출.

### 3.2 탐정형 — 단서 추론 훈련

```
📖 ┈┈┈┈ **이야기** ┈┈┈┈

[사건 제시 — 사고 보고·손해 접수·이상 징후]
[단서 나열 — 인물이 발견한 사실 2~4개 (하나는 오인 단서)]
[추론 유도 — "여기까지 보면 원인이 ○○로 보이지만…"]
[해답 공개 — 본문 기준으로 판정 + 오인 단서가 왜 함정인지]

┈┈┈┈ **본문** ┈┈┈┈ 📘
```

- **오답 선지를 단서로 배치** — 시험에서 자주 틀리는 구분(조문 유사조항·계산 착시)을 서사의 "그럴듯한 오답"으로 깔고, 본문에서 정답 근거를 제시.
- 정답은 서사 말미에 한 번만 명시 — 중간에 판정이 새면 추론 동기가 죽는다.
- 예시 적합: 손해사정(보험금 산정 사례)·산업안전(재해 원인 분석)·손해평가(평가액 추정).

### 3.3 캐릭터 성장형 — 과목 전체를 관통하는 아크

유형이라기보다 **서사의 배경 축**. 어떤 주 유형을 쓰든 아래 구조를 유지한다.

| 단계 | 챕터 위치 | 주인공 상태 | 서사 톤 |
|------|----------|------------|---------|
| 무지 | 과목 초입 | 업무/제도를 모름 — 독자 대리인 | 질문·실수 |
| 시행착오 | 과목 중반 | 배운 것을 적용하다 걸림 | 갈등·좌절 |
| 숙련 | 과목 후반 | 스스로 판단 가능 | 독립·복습 |
| 성장 완료 | 말미·통합 에필로그 | 다음 단계로 연결 | 예고·연결 |

- 챕터별 서사가 이 축 위에 놓이게 배치한다 — 매 챕터를 "같은 수준의 질문"으로 시작하면 성장감이 사라진다.
- 시험 팩 전체는 **통합 세계관 + 과목별 주인공 + 공통 멘토** 구조를 기본으로 한다 (cosmetic 선례: 민수=창업자·현우=생산·수진=상담 + 지연=품질 멘토, ST-07 통합 에필로그에서 조제대에 집결).

## 5. 콘텐츠 정합·비율 규칙 (게이트 연계)

| 규칙 | 내용 | 게이트 |
|------|------|--------|
| 서사 커버리지 | 과목당 서사 블록 ≥1 — storyFile 선언 패치에 서사 0개면 빌드 오류 | BP-10 |
| 서사-본문 정합 | 서사 속 `제N조/항/호/목`·`%·ppm·점·배·종` 토큰은 인접 본문에 실재해야 함 — **서사에서 사실을 창작하지 말 것** (상황·인물·대사만 창작) | BP-11 |
| 회상 연계 | 서사 속 본문 일치 토큰이 챕터 말미 빈칸 회상으로 자동 추출됨 — 핵심 수치·용어를 서사 대사에도 자연스럽게 포함하면 회상 항목이 늘어남 | BP-12 |
| 비중 가이드 | 서사는 장식이 아니라 학습 경로 — 챕터당 도입부 1블록 + 필요시 중간 1블록 수준. 서사가 본문 분량을 잠식하면 안 됨 | (수동) |
| 노출 금지 | 서사가 문제은행 특정 문항의 정답을 직접 노출하면 안 됨 — 개념만, 문항 정답 아님 | (수동) |

## 6. 작업 절차

1. **유형 선정** — §4 표에서 시험의 주 유형 확정. 신규 시험은 계열 선례 우선 복제.
2. **캐릭터 시트** — 주인공(독자 대리인)·멘토·세계관 1페이지. 기존 시험과 세계관을 공유할지 독립할지 결정 (같은 자격군이면 공유 권장).
3. **골격 생성** — `npm.cmd run build:story -- --scaffold <subjectKey>`로 패치 골격 생성.
4. **서사 배치** — 챕터 도입 슬롯에 성장 단계에 맞는 서사 배치. 프롤로그(`at="start"`)·에필로그(`at="end"`)·챕터 부제(`@suffix`) 활용.
5. **빌드·검증** — `npm.cmd run build:story` → `npm.cmd run check:story`(있으면) 또는 `check:fresh` — 서사 커버리지 리포트 확인.
6. **정합 자가점검** — 서사에 쓴 조문·수치가 본문에 실재하는지 BP-11 경고 확인. 경고는 오탈자·모순 신호.

## 7. 품질 체크리스트

- [ ] 주인공의 질문 수준이 성장 단계(무지→숙련)와 일치하는가
- [ ] 서사의 모든 조문·수치가 인접 본문에 존재하는가 (BP-11 무경고)
- [ ] 오답 함정이 단서/오해로 배치됐는가 (드라마·탐정 공통)
- [ ] 챕터 말미에 다음 장 예고가 있는가 (ST-05)
- [ ] 서사가 정답을 직접 노출하지 않는가
- [ ] 시험 통합 에필로그에서 과목 주인공들이 연결되는가 (ST-07 — 시험 전 과목 이야기형 완성 시)
