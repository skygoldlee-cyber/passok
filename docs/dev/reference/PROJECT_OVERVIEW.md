## 한 줄 정의

**PassOK** — 한국 자격시험 대비 **멀티시험 학습 PWA**. 시험은 콘텐츠 팩 단위로 온보딩되며, 기본 팩은 맞춤형화장품 조제관리사(`cosmetic`, 앱명 Passmula + Formula OS 실무 배합).

- 프로덕션: https://passok.vercel.app
- 저장소: github.com/skygoldlee-cyber/passok

## 무엇을 하는가

| 영역 | 내용 |
|------|------|
| 학습 | 교재 리더(검색·북마크·메모·이어보기), 플래시카드(FSRS-6 간격반복), OX·4지선다·복수정답 드릴, 통합 모의고사 |
| 분석 | 학습 진단(BKT 단원 숙달 추적)·취약 단원 분석·D-day 추적·주간 배분, 사용 통계 대시보드 |
| 실무 | cosmetic 전용 Formula OS — 처방 배합·안정성·규제 컴플라이언스·원료 DB (`features` 플래그로 시험별 게이트) |
| 계정 | 선택적 Supabase 동기화 — 미로그인도 localStorage로 전 기능 사용 가능 |
| PWA | 오프라인 캐시·홈화면 설치·시험별 독립 manifest·업데이트 배너 |

## 멀티시험 구조 (현재 5개 팩)

```
content/exams/<id>/   ← 콘텐츠 팩 (교재·문제은행·참조자료·manifest.json)
content/exams.json    ← 시험 레지스트리 (features·comingSoon·브랜딩)
src/exams/<id>/       ← 시험 전용 런타임 (DA-13 격리)
data/exams/<id>/      ← 빌드 산출 번들 (build:data)
```

| 시험 | 상태 | 문항 |
|------|------|------|
| cosmetic 맞춤형화장품 조제관리사 | 정식 | 1,979 |
| lossadj 손해평가사 · insadj 손해사정사 · indsafe 산업안전기사 · admagent 일반행정사 | 파일럿 (`comingSoon`) | 24~52 |

파일럿 승격 기준·잔여 작업은 `runbooks/PILOT_EXAM_PROMOTION.md`(DOC-RBK-16). 신규 시험 추가는 `runbooks/NEW_EXAM_RUNBOOK.md`(DOC-RBK-10) + `npm run scaffold:exam`.

## 기술 스택 원칙

- **Vanilla ES Modules** — 프레임워크 없음, 런타임 의존성 0개 (공급망 공격면 최소화, vendor는 해시 매니페스트 검증)
- **Local-First** — localStorage가 1차 저장소, Supabase는 opt-in 증강
- **콘텐츠=SSOT** — `content/*.md`가 정본, `data/` 번들은 전부 빌드 산출물 (수동 편집 금지, 신선도 게이트가 차단)
- **시험 독립** — 플랫폼 코드에 시험 id·과목 키 하드코딩 금지 (`check:contentind`, DA-15)

## 배포

`npm run deploy` 하나로 완결 — 가드(clean tree·CI success 확인) → 버전 스탬프 → `vercel --prod` → `deploy/<버전>` 태그 + 스탬프 확정 커밋 → 프로덕션 스모크(sw CACHE_VERSION·APP_VERSION 정합). `vercel --prod` 직접 실행 금지.

## 기존 인강·교재 대비 강점 분석

### 구조적으로 우위에 설 수 있는 지점

| 강점 | 기존 매체의 한계 | 이 플랫폼의 근거 |
|------|------------------|------------------|
| 개인화 스케줄링 | 인강·교재는 "누구나 같은 순서·같은 속도" | FSRS-6이 카드별 망각 곡선을 추적해 "잊기 직전 시점"에만 복습 배정 — 같은 시간 대비 회수 효율이 구조적으로 높음 |
| 약점 측정의 정밀도 | 교재는 스스로 약한 부분을 '느낌'으로 판단 | BKT가 단원별 숙달 확률 P(L)을 정오답 시퀀스로 추정 → "모르는 것을 모른다"는 메타인지 갭을 데이터로 해소 |
| 능동 회수 강제 | 인강은 수동 시청, 교재는 수동 독해 — '이해했음 착각'에 취약 | 모든 루프가 회수(플래시카드·OX·복수정답·모의고사) 중심 — 테스트 효과가 학습 효율에서 가장 잘 입증된 기제 |
| 법령 개정 추적 | 종이 교재는 개정되면 폐기/증보판 | ref_md 원문 해시·인용 라인 추적 — 법령 고시가 바뀌면 영향받는 문항·교재 문단을 기계적으로 추적 (`ai:stale`) |
| 오프라인·세션 조각화 | 인강은 스트리밍·40분 단위 | PWA 완전 오프라인 — 출퇴근 10분 단위 세션으로 쪼개짐. 학습 앱의 실사용 패턴과 정합 |
| 콘텐츠 증산 비용 | 인강 제작은 강사·스튜디오 비용 | `ai:draft` 파이프라인으로 문항 초안을 저비용 생산 → 리뷰 게이트 후 확장. 교재 제작 주기의 수십 배 속도 가능 |

### 정직한 한계

- **설명의 깊이** — 인강 강사의 직관적 비유·맥락 설명은 텍스트+카드가 대체 못 함. 이 플랫폼은 "개념 이해" 단계가 아니라 "기억·적용" 단계에 강함
- **동기부여 구조** — 인강의 진도율·학습 조언 같은 강제력 있는 커리큘럼은 없음. 자기주도 학습 의존
- **콘텐츠 신뢰** — 기존 교재는 출판 검증 프로세스가 있고, AI 생성 문항은 리뷰 게이트가 있으나 검증 이력이 얕음
- **완성 시험 1개** — cosmetic만 성숙, 나머지 4개는 파일럿. 멀티시험 가치는 아직 구조 수준

### 실질 포지셔닝

"인강/교재의 대체재가 아니라 **보완재**" — 개념은 교재·인강으로 배우고, **암기·약점 교정·복습 스케줄링**을 이 플랫폼에 맡기는 구조. 차별화 축은 **법령 개정 ↔ 문항 추적성 + 개인 망각 모델** — 둘 다 종이 교재와 영상 강의가 물리적으로 불가능한 영역이다.

### 미검증/미구현 (사업 가설 단계)

| 항목 | 현황 | 리스크 |
|------|------|--------|
| **결제·유료 권한** | 결제 인프라 없음 — `pro_entitled` 로컬 플래그만. 서버 검증·웹훅·환불 전무 | 유료화 시점 전체 경로를 새로 설계해야 함 |

| **Local-First 운영 한계** | 비회원 데이터 손실(브라우저 삭제·기기 변경) 위험 — 백업 안내는 있으나 복구 유도 UX는 미흡 | 유료 전환 시 기록 유실 클레임 가능성 |
| **Formula OS 사업성** | 합격 후 실무 활용 가치는 유일한 churn 해소 축이나 실제 지속 사용 검증 안 됨 | 브랜드 분리·별도 제품화 여부도 미결정 |
