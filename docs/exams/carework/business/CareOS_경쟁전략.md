외부 초안 분석(케어포 중심 경쟁 검토)을 공식 출처로 교차 검증하고, 그 결과를 carework 실무도구(Care OS)의 설계·구현 개선 과제로 번역한 문서다. 수치·기능 주장은 1차 출처(공단 공시·각 사 공식 사이트)를 우선하며, 자사 마케팅 주장은 "미검증"으로 표기한다.

| 서비스 | 가격 | 출처 |
|--------|------|------|

| 케어포 시설·주야간 | 월 33,000원~ (수급자 수 구간제, 1개월 무료) | carefor.co.kr 요금표 |

- 시사: Care OS가 ERP 본체로 진입하면 수익구조 자체가 성립 불가. ERP 본체 가격(월 1~3만원)은 **기관 지불 심리의 기준점** — 그 이상의 과금은 "ERP가 하지 않는 가치"를 별도로 입증해야 성립한다 (§7-2 기관 Pro 가설 참조)

## 3. 전략 전제

1. **ERP(청구·급여·수급자관리) 직접 경쟁 금지** — 저가 공산품 + 롱텀 연동 장벽 + 공단 무료 앱 존재
2. **보완층 포지셔닝** — 케어포·이지케어·공단 앱을 쓰는 기관에도 병행 가능한 구조
3. **첫 진입 세그먼트 = 시설급여·주야간 종사자, 판매 채널은 세그먼트별 분리** — 인수인계·교대·추세·평가 증적이 시설의 고충. 단 세그먼트와 판매 채널은 별개 축이다: **시설은 기관 판매(B2B) 우선**(기관 태블릿·ERP 사용 관행이 있고 개인 기기 정책이 가장 엄격해 개인 채널이 가장 약함), **방문요양은 개인 채널 우선**(수험생→신규 종사자 퍼널의 유입 지점). 기능 적합성과 채널 적합성이 교차하므로 §5-0에 병기한다
4. **개인정보 최소화 계층 + 수탁 처리 전제** (수정 — 원칙을 데이터 계층과 법무 전제로 명문화):
   - L0 로컬 전용: 생년월일·진단·연락처·명부 메모(`care-client`) — 어떤 경로로도 서버·외부 전송 금지. **L0/L1 경계 누수 규칙**: 자유텍스트에 진단·가족명 등이 섞일 수 있으므로 서버로 올리는 페이로드는 코드화 필드(`obs`)와 구조화 요약만 허용하고 원문 자유텍스트는 제외한다
   - L1 기관 서버: 성명·호실 + 기관의 업무 기록(일지·사고·방문·인수인계 요약) — facility 워크스페이스 업로드 시점에 개인 도구 데이터가 **기관 기록**으로 전환되며 이용자에게 고지. 단 법적 성립에는 전제가 있다 — **서비스 운영자는 기관의 개인정보처리 수탁자**이므로: ①처리위탁 계약 또는 이용약관의 위탁 조항 ②개인정보처리방침의 위탁 고지 ③안전성 확보조치(접근통제·접속기록·암호화 범위 검토) ④건강정보(민감정보)에 대한 기관 측 처리 근거 확인.
     - **기존 경로 소급 조치 — 결정 확정(2026-11-04)**: `shift_handovers`·`family_visits`·`incident_reports` 등 facility 테이블 전수 조회 결과 **전 행 0건 — 사용 기관 없음 확인**. 규칙에 따라 `exams.json`의 `features.careFacilityJoin`·`careFacilityAdmin`을 `false`로 **즉시 비활성화**했다 (재개통은 0b 완료 후). 위탁 계약은 개인정보보호위원회 표준 위탁계약서 양식을 출발점으로 한다. 신규 서버 저장 기능은 준비 완료 전 개통 금지 (§6-0b·§7-1)
     - **작성자 검토 예외**: 자동 수집된 원문을 자동으로 첨부하는 것은 금지하되, 사용자가 직접 작성·검토·편집 후 제출하는 필드(memo 등)는 L1로 허용 — 다이제스트가 생성한 memo 초안도 제출 전 작성자 검토 필수
   - L2 외부 전송 금지 원칙: AI(BYOK) 등 제3자 처리는 **전송 직전 가명처리 필수** — 대상자명→코드("대상자 A") 치환, 호실·날짜·연락처 제거. 가명처리만으로는 자유텍스트 속 재식별 단서(가족명·지명·특이 사건)가 남으므로 ①전송 내용 미리보기로 사용자 확인 ②원문 대신 키워드·태그 입력을 기본값으로 둔다 (P1-5). 개인 키 사용이어도 수급자 정보의 관리 책임은 기관에 있어 국외이전·제3자 제공 논점이 남음 — 기관 모드에서 AI 사용은 기관 승인 정책을 따른다
5. **롱텀 연동 대신 왕복 파일 + 이중 입력 최소화** — 공식 API 부재이므로 CSV/Excel 왕복·서식 호환 출력이 공존 경로. 종사자의 기록은 이미 ERP·공단 앱에 입력되므로 **"또 적지 않아도 되는" 흐름**(가져오기·재사용·붙여넣기)이 채택의 전제조건

부가 자산: `care-roster`·`care-incident`·`care-audit`·`care-finder`(전국 기관 DB)·`facility-join/admin`(Supabase 워크스페이스)·CSV/Excel 왕복(xlsx-utils, CP949).

## 5. 개선 로드맵

### 5-0. 세그먼트별 기능 매핑 (전략의 축)

|----|------------|----------|
| 기능 적합성 | ★ 인수인계·교대·평가가 고충 | ○ 보조 기능 중심 |
| 판매 채널 | **기관 B2B 우선** — 개인 기기 정책 엄격, 기관 태블릿·ERP 관행 | **개인 채널 우선** — 수험생 퍼널 유입 지점 |

- **1차 세그먼트: 시설급여·주야간** — 핵심 기능 적합성 + 기관 Pro 경로 일치. 단 진입은 **기관 단위(B2B)** 가 유효할 가능성이 높음 — 개인 채널 해자는 시설에서 약하게 작동
- **2차 세그먼트: 방문요양** — 시장 최대·퍼널 유입 주체지만 ①공단 앱이 제공기록을 커버 ②1인 전담이라 인수인계 부재 ③개인 Pro 수익 기대 낮음 — **유입 채널 + 기관 연결 고리**로 가치를 둔다
- FREE_LIMIT 정책 재검토 필요: 세그먼트별 한도 도달률이 다르므로 "건수 한도"가 아닌 기능 게이트(내보내기·AI·기관 동기화) 중심으로 재설계 검토 (P2-9)

### P0 — 데이터 허브화

**P0-1. 대상자 참조 ID 정규화** (선행 — P0-3보다 먼저) → `CO-01·CO-02`
- 전 스토어 `client: string` 자유텍스트 → `clientId`(`cli_xxx`) 추가 + `client` 문자열은 표시 스냅샷 유지
- 서버(`shift_handovers` 등)는 `client text` 유지 — L1 범위 내
- 산출: 대상자 360° 카드 — `care-client` 상세에 일지·사고·방문·인수인계 통합

**P0-2. 관찰 시계열 + 추세 확인 알림** → `CO-03·CO-04`
- `care-log`에 코드화 관찰 필드 `log.obs {}` — **공단 급여제공기록지 항목 체계에 정렬**(식사·배설·수면·신체활동 등)해 P1-4 출력에서 그대로 재사용
- 신규 순수 모듈 `care-trend.js`: 최근 N일 추세 → `check` 신호
- **문구 원칙: 의료적 판단 표현 금지** — "위험·악화·경고"가 아니라 "최근 기록에서 확인 권장 항목" 수준의 기록 요약 표현 (예: "식사 기록이 3회 연속 '소'로 기록됨 — 확인 권장")

**P0-3. 인수인계 자동 집계** (시설 세그먼트 핵심 차별점 — 로컬/서버 분리) → `CO-05·CO-06`
- `shift_handovers.payload jsonb`는 이미 "이력 자동 요약"용으로 예약됨 (DOC-DSN-43)
- 신규 `handover-digest.js`: 근무 시간대 내 대상자 일지+사고+방문 수집 → 요약 페이로드 → memo 초안
- **로컬 다이제스트(개인 모드)**: 자기 기록 집계·초안 생성 — 즉시 구현 가능
- **서버 업로드(facility 모드)**: payload는 L1 기관 기록 범위 — 선행 조건 **법무 준비(§6-0b) + 관찰 필드 존재(P0-2)**. `obs`가 생기기 전에는 서버로 올릴 구조화 데이터가 없다
- **주의**: P0-1 이후 구현. 자유텍스트 매칭으로 먼저 만들면 동명이인 혼동으로 재작업 발생 — clientId 매칭 전제
- **누수 방지**: payload에는 코드화 필드(`obs`)·구조화 요약만 포함 — 일지·사고의 원문 자유텍스트는 업로드 제외 (§3-4 L0/L1 경계 규칙). 다이제스트 memo 초안도 제출 전 작성자 검토·편집 필수 (§3-4 L1 작성자 검토 예외)

### P1 — 이중 입력 해소·AI·출력물

**P1-4. 이중 입력 해소 (채택의 전제조건 — 우선순위 상향)** → `CO-07`

  ② **전송 미리보기** — 가명처리된 실제 전송 내용을 사용자가 확인 후 발송 (자유텍스트 속 재식별 단서 — 가족명·지명·특이 사건 — 는 치환으로 제거되지 않음)

### 7-1. 리스크 (중요도순)
