> 목적: `CareOS_경쟁전략.md`(DOC-BIZ-06) §5-0 세그먼트×채널 가설과 §6 로드맵 착수 여부를 판단하는 데이터를 수집한다. 결과가 아니라 **인터뷰 전에 기준을 확정**한 문서다 — 인터뷰 후 기준을 바꾸면 확증 편향. 판정에는 **이미 배포된 lite 기능의 유지·보강·정리**도 포함된다 (DOC-BIZ-06 §6 실행 동결 원칙).

ERP 직결 입력 1회만 하는 흐름은 Q4에서 이중 입력 '없음'. Q4는 마지막 근무일 되짚기이므로 "이번 주 다른 날도 같았나요?" 꼬리로 '최근 1주'를 근사한다. **미응답 분모 제외 후의 판정**: 분수 기준은 유효분모 대비 비율로 환산(4/5=80% — 유효 4명이면 4/4만 충족, 3/4=75%는 미달)·유효 n<3이면 해당 기준 판정 보류하고 표본 보강. **중단 ①·③ 동시 발동**: ERP 직결 기관 종사자는 Q4 '없음'+Q7b 'ERP로 함'으로 두 기준에 동시 카운트될 수 있음 — 의도된 겹침이며, 보고 시 발동 기준을 구분 기재 | — |

## 인터뷰어 사전 준비 (첫 인터뷰 전 1회)

- **경쟁 ERP 실물 숙지** — 응답자가 "프로그램에서 해요"라고 할 때 무엇을 말하는지 알아야 Q3b·Q7b를 코딩할 수 있다
  - 케어포: 1개월 무료 체험으로 직원앱(출퇴근·야간점검 NFC 등)·보호자앱 "가족돌봄"(건강정보·사진·식단·급여제공 내역·상담) 확인 — 인수인계·관찰 추세·평가 증적 기능 유무를 DOC-BIZ-06 §2-4에 "실측(날짜)"로 기록
  - 공단 스마트장기요양: 요양요원 기능 + **사회복지사·프로그램관리자 업무수행일지 모바일 입력·전자서명**(신규) 확인
  - 케어로그(요양일지·보호자 공유)·케어매니저 앱 스토어 설명 확인
- 실측 결과를 근거로 인터뷰 중 "그 기능 이미 있어요"를 **인터뷰어가 말하지 않는다** — 응답자가 쓰는지 여부만 기록

## 5. 사용·지불 의향 (5분)

> lite 도구가 이미 배포돼 있다 — Q11~Q12는 가상 질문으로 묻되, 시간이 남으면 **마지막에 시연으로 전환**: `care-log` 일지 → `care-handover` "오늘 기록으로 채우기" → `care-forms` 서식 출력 순서로 30초씩 보여주고 반응 관찰. 가상 응답과 시연 후 반응이 다르면 둘 다 기록한다 — 괴리 자체가 데이터.
> **시연은 "현 도구 대비 비교"로 진행** — 응답자가 Q3·Q3b에서 보여준 ERP 직원앱·공단 앱과 같은 작업을 나란히 놓고 "지금 쓰시는 것과 비교하면 뭐가 다르세요?"만 묻는다. 비교 축은 DOC-BIZ-06 §7-3의 3축(①기록 재사용 ②인수인계 ③기관 평가). Care OS가 나은 점을 인터뷰어가 설명하지 않는다.
