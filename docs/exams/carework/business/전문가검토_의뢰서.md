## 1. 의뢰 개요

요양원 등 장기요양기관을 고객(B2B)으로 하는 기록 워크스페이스 기능의 **개인정보처리 위탁계약서 초안과
관련 개인정보 문서에 대한 법률 검토**를 의뢰합니다.

의뢰인은 서비스 운영자로서 **수탁자** 지위에 있고, 기관(요양원)이 **위탁자·개인정보처리자**입니다.
기관 소속 종사자가 입력한 업무 기록을 서비스가 저장·열람 지원하는 구조입니다.

**요청하는 검토 결과물**: ①계약서 조항별 수정 의견 ②§4 질문에 대한 회신 ③처리방침·운영 절차의
법적 요건 충족 여부 ④누락된 필수 조치 지적.

## 2. 서비스·사실관계 요약 (전문가용 브리프)

### 2.1 서비스 개요

- **PassOK** — 자격시험 학습 PWA(웹 앱). carework 시험 팩에 "기관 워크스페이스" 기능이 있음
- 기관이 워크스페이스를 만들고 직원을 초대코드로 가입시키면, 직원이 입력한 업무 기록이
  기관 단위로 저장·공유됨 (manager/worker 역할 구분)
- 수익 모델: 개인 Pro 코드(기간권) + **기관 사이트 라이선스(월·기간 정액) 설계 중** — 미출시

### 2.2 데이터 흐름

```
기관 직원(브라우저) → 입력 → PassOK 서버 저장(Supabase, 서울 리전 ap-northeast-2)
                                        ↓ (기관이 설정한 경우에만)
                                   기관 자체 서버로 웹훅 전송
```

- 인프라: DB·인증 = Supabase(서울 리전, Management API 확인 완료), 호스팅 = Vercel
- 현재 기관 테이블 레코드 전수 **0건** — 기능 플래그 비활성 상태, 법무 준비 후 개통 예정

### 2.3 저장되는 개인정보 (위탁 범위 = L1 계층)

| 테이블 | 내용 | 개인정보 성격 |
|--------|------|--------------|
| `shift_handovers`, `handover_acks` | 인수인계 기록·확인 | 수급자 성명·호실, 종사자 계정 |
| `family_visits` | 면회·방문 기록 | 수급자 성명 + **보호자 성명·관계·연락처(제3자 정보)** |
| `incident_reports` | 사고·낙상 보고 | 수급자 성명 + 건강 상태 서술(**민감정보 가능**) |
| `facility_records`, `facility_form_templates` | 기관 자체 양식 기록 | 기관이 정의한 항목 (기관 책임) |
| `facilities`, `facility_members` | 기관·멤버십 | 종사자 이메일 계정·역할 |

**저장되지 않는 것(L0 계층 — 설계상 서버 미전송)**: 수급자 생년월일·진단명·연락처·명부 자유메모 —
이용자 기기 localStorage에만 존재. 스키마 원본: `tools/supabase/exams/carework/schema.sql`.

### 2.4 안전조치·운영 현황 (별지 2 요약)

- 접근통제: RLS(행 단위 보안) — 같은 기관 멤버만 열람, manager 권한 분리
- 암호화: TLS 전송 + 인프라 at-rest (추가 앱 레벨 암호화 없음 — 결정 사항)
- 접속기록: Supabase 인증 로그 (기록별 감사 테이블 없음 — 결정 사항)
- 운영자 접근: service key를 env로만 보관, 접근 목적·기록 규약 문서화 완료(DOC-RBK-24)
- 백업: Free 플랜으로 공급자 자동 백업 없음 → 운영자 덤프 도구(`admin:facility-backup`) 자체 구축,
  2026-11-13 실습으로 덤프→복원 주기 검증 완료

### 2.5 운영 주체·규모

- 운영자: 【개인/사업자 등록 여부】 — 소규모 서비스, 유료 사용자 소수
- 기관 고객: 파일럿 1~2곳부터 시작 예정, 상품은 월 정액 구독(소형 ≤20인 등 좌석 티어)

## 4. 검토 질문 (회신 요청)

| # | 질문 | 관련 |
|---|------|------|
| 1 | **전자 동의만으로 위탁계약 성립이 충분한가** — 기관 관리책임자가 앱에서 계약 확인+동의 버튼으로 체결하고, 서면은 요구 기관에만 예외 제공하는 구조 | §14 |
| 2 | **손해배상 상한("직전 12개월 지급 대금 합계")이 유효한가** — 월 수만원 구독 상품에 무제한 배상은 비대칭이라 캡을 둔 것인데, 약관규제법 제6조(부당하게 면책하는 조항 무효) 관점에서 수용 가능한 수준인지 | §11(2) |
| 3 | **기관 보증 조항만으로 민감정보·제3자 정보 리스크가 관리되는가** — 건강정보 처리 근거(§9(2))와 보호자 정보 고지·동의(§9(3))를 위탁자 보증으로 두었는데 수탁자에게 남는 리스크와 보완 필요 조항 | §9 |
| 4 | **재수탁자 사전 공개 + 계약 체결로 동의 갈음** — 별지 3에 Supabase·Vercel을 기재하고 신규 재수탁자는 통지 후 이용 계속 시 동의로 보는 구조의 유효성 | §5·별지3 |
| 5 | **인증 로그만으로 접속기록 보관 의무가 충족되는가** — 기록별 접근 감사 테이블 없이 인프라 인증 로그에 의존하는 것이 요양기관 개인정보 자율보호 기준 및 안전조치 기준에 부합하는지 | §6·별지2 |
| 6 | **문서 형태** — 별도 "위탁계약서"로 둘지, 서비스 이용약관의 위탁 조항으로 통합할지. B2B SaaS 온보딩(앱 내 전자 동의) 관점에서 적합한 형태 | 전체 |
| 7 | **보호자 연락처 필드 유지의 적절성** — 면회 기록 목적상 실용적이지만 수집 최소화 원칙 관점에서 필드 삭제·선택화 필요 여부 | 별지1·§9(3) |
| 8 | **수탁자 자격** — 무등록/개인 운영 상태에서 위탁 수탁에 법적 문제가 없는지, 사업자등록 등 전제 요건 유무 | 당사자 |
