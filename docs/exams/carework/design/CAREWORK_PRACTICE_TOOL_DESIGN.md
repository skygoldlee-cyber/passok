# 요양보호사 현장도구(Practice Tool) 설계 — 시험→실무 구독 전환

> **문서 ID**: DOC-DSN-42
> **범위**: exam:carework · 판본: none
> **관련 SPEC ID**: UM-01~04 (학습/실무 모드 전환·실무 랜딩) · PAY-01~08 (Pro 게이팅) · DA-13 (시험 격리) · DA-15 (콘텐츠 독립) · CO-13 (생성 문서 공유)
> **목적**: carework 팩에 "시험 합격 후 현장에서 매일 쓰는" 실무 피처를 추가해 구독 수익모델을 만드는 설계 — 시장분석(DOC-DSN-41)의 후속 실행 설계

## 1. 배경·문제

- 요양보호사 시장의 수익 구조는 **시험학습 일회성**이 아니라 **합격자의 현장 업무**에 있다 — 재가센터·요양원 근무자는 기록 작성·급여 계산·대처 판단을 매일 수행
- cosmetic은 Formula OS(배합·기록)로 같은 패턴이 검증됨 — 시험 콘텐츠는 무료 유지, **실무 생성·저장·출력을 Pro**로 게이팅
- 법적 근거 데이터는 이미 확보 — 장기요양급여 제공기준 고시·등급판정 고시·본인부담금 감경 고시·인권교육·평가방법 고시가 `ref_md`에 편입됨

## 2. 목표

| # | 목표 | 지표 |
|---|---|---|
| G1 | 합격자가 **매일** 쓰는 도구 (기록 생성) | 주간 활성 실무 사용자 |
| G2 | 시험→실무 전환 구독 | carework 실무 피처 Pro 전환율 |
| G3 | 기존 아키텍처 재사용 — 신규 개념 0 | formula-view 패턴 그대로, UM/PAY 기존 계약 유지 |

## 3. 기능 스펙 — 3단계 도구

### 3.1 Phase 1 — 장기요양 비용 계산기 (`careCalc`)

**가장 작고 즉효** — 데이터는 모두 수집됨.

- 입력: 급여종류(재가·시설), 등급(1~5·인지지원), 감경 여부(60%·40%), 서비스 월 이용량
- 계산: 월한도 적용 → 총급여 → 본인부담금 (재가 15%·시설 20%, 감경 반영)
- 근거: 노인장기요양보험법 §40·시행령 §27(본인부담), 본인부담금 감경 고시 — **법령 변경 시 ref_md만 갱신하면 수치 추적**
- 출력: 계산 근거 조문 링크 (ref_md 인용 — 학습 콘텐츠와 동일 패턴)

### 3.2 Phase 2 — 상황별 대처 카드 (`careCard`)

**현장 판단 지원** — 교재 15장 내용을 위기 상황용 플로우카드로 재구성.

- 카드 종류: BPSD(망상·배회·공격·불안), 낙상, 욕창, 응급(의식·호흡·가슴통증), 감염 의심
- 구조: `상황 인식 → 즉시 조치 → 보고 → 기록` 4단계 플로우 — 조문 근거 없는 판단 기준은 표준교재 기반(저작 내용)
- 구현: static JSON 콘텐츠로 충분 — `content/exams/carework/실무/care_cards.json` 데이터 번들로 생성

### 3.3 Phase 3 — 요양일지·서비스기록지 생성기 (`careLog`) ← **구독 핵심**

**매일 사용하는 기록 도구** — 리텐션 본체.

- 입력: 날짜, 대상자, 급여종류, 수행 서비스 체크(신체·가사·정서 지원 카테고리), 특이사항
- 생성: 장기요양급여 제공기준 고시의 기록 항목에 맞춘 표준 일지 텍스트 자동 조립 → 복사·PDF·저장
- 저장: `adverse-store.js`(cosmetic 유해사례 기록) 패턴 — `src/exams/carework/care-log-store.js`에서 로컬 저장 + Pro는 클라우드 동기화
- Pro 게이팅: **저장·내보내기만 Pro**, 생성 미리보기는 무료 — 시험→실무 전환 유도점

### 3.4 Phase 4 — 기관 평가 체크리스트 (`careAudit`)

**평가 대비 점검 도구** — 기관 평가 시즌 수요.

- 데이터: `content/exams/carework/실무/audit_checklist.json` — 평가방법 고시 기반 4영역(인권보장·기록관리·감염관리·안전응급) 20항목, 자체 저작
- 기능: 체크/해제·영역별 묶음·진행률 바·초기화 — 체크 상태 로컬 저장
- 게이팅: 무료 (현장 접근성 우선)

### 3.5 Phase 5 — 인수인계서 (`careHandover`)

**교대근무 핵심** — 주간·저녁·야간 조 간 정보 공유가 일상 업무.

- 입력: 일시·근무조·인계자·인수자·대상자·상태·미완료 작업·주의사항
- 생성: 표준 인수인계 포맷 자동 조립 + **당일 저장 일지 자동 병합** (수기 부담 제거)
- 공유: `navigator.share`(모바일 카톡 등) + 복사·인쇄·PDF — 기록 생성→전달 완결 (구현 계약은 §9)
- Pro 게이팅: 생성은 무료, **공유·인쇄만 Pro** — 공유 시점에서 업그레이드 안내
- 다기관 공유(L3)는 별도 — 계정·그룹·권한이 필요한 백엔드 작업, 본 설계 범위 외

## 9. 카톡 공유·내보내기 파이프라인 (CO-13) — 메뉴·제스처·페이로드 계약

구현: `src/exams/carework/care-share.js` — 출력 뷰의 `📤 공유·내보내기` 버튼(`data-click="careShare"`)이 진입점. 인쇄 버튼은 이 버튼에 통합되어 뷰당 출력 버튼이 하나다.

`data-arg` 스키마: `선택자|제목[|mask][|생성핸들러[|보조생성기[|인쇄핸들러[|pro키]]]]`
— mask 플래그 시 인명·연락처 가림, 생성핸들러는 미생성 시 자동 실행, 보조생성기(`*CsvExport`)는 Excel 소스, 인쇄핸들러는 메뉴의 인쇄 항목이 호출(미지정 시 생성 후 `window.print()`), pro키는 메뉴 항목 배지·`proFeatureNotice`에 사용.

### 9-1. 제스처 제약 — 왜 메뉴 + 2단계 탭인가

- `navigator.share()`는 **transient activation(수 초)** 안에만 열린다. xlsx(SheetJS 로드)·pdf(html2canvas) 생성은 수 초가 걸려 같은 클릭에서 양립 불가.
- `share()`는 제스처를 **소비**하므로 실패 후 같은 클릭에서 재시도 불가 — 재시도는 반드시 새 탭이 필요.
- 내보내기 메뉴(`_openMenu` — 하단 시트 + 스크림)의 각 항목 탭이 새 제스처다. 공유 항목은 생성 완료 후 **`"📤 공유하기" 플로팅 버튼의 새 제스처**로 `share()`를 호출한다 (`_shareBtn` — 탭하면 자기 제거, 30초 자동 소멸).

### 9-2. 플로우

```
📤 공유·내보내기 탭
  ├─ 텍스트 확보: 출력 요소 → 미생성 시 생성 핸들러 자동 실행 → 실패 시 폼 양식 폴백
  ├─ mask 플래그 시 인명·연락처 가림 + 기관 정책 안내 토스트
  └─ 내보내기 메뉴 시트 (항목은 해당되는 것만)
      ├─ 📤 카카오톡 등으로 공유 — 모바일 전용: 형식 선택 시트(pdf/docx/xlsx/전체) → 선택분만 생성 → 공유하기 버튼 → share({files})
      ├─ 🖨️ 인쇄·PDF 저장 — 인쇄핸들러 호출(없으면 생성+print) — 벡터 PDF·용지 출력
      ├─ 📋 본문 복사 — 클립보드 (mask 시 가림)
      ├─ 📄 PDF 파일 다운로드 — html2canvas 래스터 (카톡 첨부용)
      ├─ 📝 Word 파일 다운로드 — 미니멀 OOXML 직접 생성 (docx-utils, 편집용)
      └─ 📊 Excel 내보내기 — CsvExport 핸들러 그대로 호출
```

- **페이로드는 `files`만** — `text`를 병기하면 카톡 등 타겟이 파일 대신 텍스트만 수신한다.
- **txt 파일은 만들지 않는다** — 본문 텍스트는 클립보드 복사로 제공, 카톡·다운로드 이중 수신 방지.
- 외부화 액션(공유·복사·다운로드)은 감사 로그(`CARE_SHARE_AUDIT`, 최근 50건)에 기록된다 — 인쇄는 로컬 출력이라 제외.
- 텍스트가 없어도 `csvGen`이 있으면 메뉴는 열리고 텍스트 의존 항목만 비활성된다 (저장 목록만 있는 뷰의 Excel 경로 보존).

### 9-3. 플랫폼 분기·폴백

| 환경 | 동작 |
|---|---|
| 모바일(`pointer:coarse`) + share 지원 | 공유 항목 탭 → 복사 + 생성 완료 → 공유하기 버튼 → `share({title, files})` — 카톡에 PDF·xlsx 첨부 |
| 데스크톱(`pointer:fine`) | **공유 항목 숨김** — 카톡 PC판은 Windows 공유 대상에 미등록이고, `canShare`가 파일을 통과시켜도 `share({files})`가 OS 수준 `NotAllowedError` 거절(Chromium `canShare`는 파일 타입·OS 지원을 검증하지 않음). 메뉴에서 인쇄·복사·PDF·Excel 선택 |
| share 미지원(인앱 WebView 등) | 공유 항목 탭 시 복사 후 진단 배너("Chrome으로 열어주세요") |
| 시트 거절 | `AbortError`는 사용자 취소로 무시. 그 외는 진단 배너 + `downloadAll()` — `NotAllowedError`+파일 첨부 조합은 `_filesBlocked` 학습으로 이후 탭은 `{title, text}`만 탑재 |

- 진단은 토스트가 아닌 **탭-해제 상시 배너**(`diag`) — 다운로드 창에 가려지지 않고 캡처 가능 (네이티브 다이얼로그 규약 금지).
- 실패·미지원 경로에서도 항상 복사·다운로드로 결과가 손실되지 않는다 — "클릭 즉시 반응" 계약.
- PRO 배지는 통합 버튼이 아닌 **메뉴 항목**에 표시 — pro키 지정 뷰는 공유·복사·PDF·인쇄·Excel 전 항목에 배지 + 진입 시 `proFeatureNotice` (무료 경로 우회 없음 — §5 "생성은 무료, 공유·인쇄만 Pro"와 정합). pro키 미지정 뷰(본인부담금)는 배지 없이 무료.

## 10. 양식 커스터마이징 — 사본 오버라이드·기관 파일 업로드 (CO-18/CO-19)

### 10-1. 출력 서식 오버라이드 (CO-18)

- `TOOL_FORM_SEEDS`(form-seeds.js) — 6개 도구(요양일지·방문기록·인수인계서·사고보고서·평가점검표·근무표)의 `{{키}}` MD 골격 정본. 원본 불변.
- 연동 사본: `form_template_store` 로컬 양식에 `toolKey`가 있으면 `renderToolBody`가 도구 출력 본문을 사본 서식으로 치환 — docMdHead/docMdSign은 유지.
- 블록 키(`{{기록표}}`·`{{점검표}}` 등): 도구 구조화 데이터가 꽂히는 자리. 편집기 미리보기는 `toolBlockPreview(toolKey)`로 실데이터 치환(점검표=현재 체크 포함 20항목, 기록표=저장 기록), 없으면 자동 생성 영역 칩.
- 사본 생성 경로 2개: ① "사본 만들기"(시드 복사) ② "파일로 만들기"(.docx/.xlsx/.csv/.pdf 추출 → 편집기 로드 → 저장 시 toolKey 추론). xlsx/csv는 표를 MD 행으로 보존. 기존 연동 사본이 있으면 갱신 편집.

### 10-2. 점검표 콘텐츠 오버라이드 (CO-19)

- 평가 체크리스트 뷰 "기관 점검표 불러오기" → audit-import.js 순수 파서가 파일을 `{title, items:[{id,text,ref}]}` 섹션으로 정규화 (헤더 키워드 컬럼 매핑·무헤더 열 휴리스틱·병합 셀 계승·비표 텍스트 제목/항목 분리).
- 항목 id = sha256(섹션+텍스트+중복순번) — 같은 파일 재업로드 시 체크 상태 유지. 저장소 `carework_audit_custom`.
- `loadAuditSections`가 커스텀 우선 → 미리보기·내보내기·사본 미리보기까지 동일 적용. "기본 점검표 복원"으로 고시 기본 복귀.
- 서식(사본)과 항목(업로드)은 독립 축 — 둘 다 적용 가능.
