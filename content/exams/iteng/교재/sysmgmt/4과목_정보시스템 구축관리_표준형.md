## kocw_os_02

### 프로세스의 정의 및 구성 요소
프로세스는 실행(executing, running) 중인 프로그램이며, PCB(Process Control Block)와 프로그램 카운터(Program Counter)를 지닌 능동적 개체(entity)로서 순차적으로 수행된다. 프로세스 관리는 사용자 및 시스템 프로세스의 생성과 삭제, 일시 중지와 재수행, 프로세스 스케줄링, 동기화, 프로세스 간 통신, 교착상태 처리 등을 포함한다. 주기억장치 내 프로세스의 저장 영역은 4가지로 구분된다. 코드 영역은 실행 명령어 코드가 바이너리 형태로 저장되며, 데이터 영역은 전역 변수(global variable)와 정적 변수(static variable)가 할당된다. 힙(heap) 영역은 동적 할당을 위한 공간이며, 스택(stack) 영역은 지역 변수(local variable) 할당과 함수 호출 시 전달되는 인수(argument) 값을 저장하는 데 사용된다. 유닉스 환경에서 프로세스를 생성할 때는 `fork()` 명령어를 사용한다.

### 프로세스의 상태 및 상태 전이
프로세스는 실행 상태(running), 준비완료 상태(ready), 대기 상태(block)의 구분을 반복하면서 작업을 완료한다. 실행 상태는 CPU를 점유 중인 상태이고, 준비완료 상태는 CPU가 사용 가능해질 때 할당받을 수 있는 상태이며, 대기 상태는 CPU 점유 중 입출력 처리 등이 발생하여 CPU를 양도하고 처리가 끝날 때까지 기다리는 상태이다. 작업이 시스템에 장착(제시)되면 스풀러(SPOOLer)에 의해 디스크에 수록되어 보류 상태가 된 후, 작업 스케줄러(Job Scheduler)에 의해 준비완료 리스트의 가장 뒤에 삽입된다. 디스패치(dispatch)는 프로세스 스케줄러가 준비완료 프로세스를 실행 상태로 전환하는 것이다. 타임슬라이스(time quantum)를 초과하면 timer runout에 의해 실행에서 준비완료 상태로 변환되며, 할당시간 초과 전 입출력이 발생하면 block되어 대기 상태로 바뀐다. 입출력이 완료되면 wake-up에 의해 대기 상태에서 준비완료 상태로 전환된다. 이러한 프로세스 상태에 대한 조사와 통보는 트래픽 제어기(traffic controller)가 담당한다.

### 프로세스 제어 블록(PCB)
PCB(Process Control Block)는 특정 프로세스에 관한 모든 정보를 보유하는 블록으로, 모든 프로세스는 각기 고유한 PCB를 갖는다. PCB는 프로세스가 생성될 때 만들어지고 종료 시 제거되며, 상태 변화가 발생하면 트래픽 제어기에 의해 그 내용이 갱신된다. PCB의 구성 항목으로는 프로세스의 현재 상태(실행, 준비완료, 대기 등), 프로세스의 고유 이름(identifier), 우선순위, 적재된 기억장치 주소를 가리키는 포인터, 할당된 자원을 가리키는 포인터, 중앙처리장치의 각종 레지스터 상태를 저장하는 공간 등이 있다. PCB들은 대부분 상호 링크되어 관리되며, 준비완료 리스트나 대기 리스트는 FIFO 큐, 우선순위 큐, 트리 구조, 스택, 무순서 연결 리스트 형태로 PCB를 연결한다.

### 중앙처리장치 스케줄링의 목적 및 기준
중앙처리장치 스케줄링은 준비완료 상태의 프로세스들 중 어떤 프로세스에 CPU를 할당할지 결정하는 정책을 의미하며, 기본 목적은 처리율(throughput)의 최대화와 반환시간(turnaround time)의 최소화이다. 세부 목적으로는 공정성 확보, 처리능력 최대화, 대화식 사용자의 응답시간 최소화, 예측 가능성 유지, 오버헤드 최소화, 자원 사용의 균형 유지 등이 있다. 무한 대기 상태(무한 지연)를 방지하기 위해 프로세스가 오래 기다릴수록 우선순위를 높여주는 에이징(aging) 기법을 활용한다. 주요 자원을 점유한 프로세스는 해당 자원을 양보할 수 없다면 우선적으로 처리되도록 하고, 페이지 부재율이 낮은 프로세스처럼 바람직한 동작을 보이는 프로세스에게 더 좋은 서비스를 제공한다. 스케줄링 기법 결정 시 입출력 위주인지 연산 위주인지의 여부, 일괄처리형인지 대화형인지의 여부, 긴급한 응답 요구 여부, 우선순위, 페이지 부재 빈도, 선점 빈도, 기실행 시간 및 완료까지 남은 실행 시간 등을 종합적으로 고려해야 한다.

### 스케줄링의 단계별 분류
스케줄링은 처리 수준에 따라 상위, 중간, 하위 단계로 구분된다. 상위단계 스케줄링(작업 스케줄링, 승인 스케줄링)은 어떤 작업에게 시스템 자원을 차지하도록 승인할 것인가를 결정하는 단계이다. 중간단계 스케줄링은 어떤 프로세스에게 CPU를 차지하게 할 것인지 결정하며, 시스템 부하 내에서 일시적인 프로세스 활동 중단 및 재개를 수행하여 작업 승인과 CPU 할당 사이에서 버퍼(buffer) 역할을 담당한다. 하위단계 스케줄링은 CPU가 가용할 때 준비완료 프로세스 중 어떤 프로세스에 CPU를 할당할지 결정하며, 디스패처(dispatcher)에 의해 매초 여러 번 수행된다. 하위단계 스케줄링을 담당하는 디스패처는 항상 주기억장치 내에 적재되어 있어야 한다.

### 스케줄링의 방법 및 환경별 분류
스케줄링은 선점/비선점, 우선순위, 기한부 방식으로 분류된다. 비선점(non-preemptive) 스케줄링은 프로세스에 CPU가 할당되면 수행 종료 시까지 CPU를 강제로 회수할 수 없으며, 긴 작업 때문에 짧은 작업이 대기할 수 있으나 공정하고 응답시간 예측이 용이하다. 선점(preemptive) 스케줄링은 실행 중인 프로세스를 중지시키고 다른 프로세스가 CPU를 차지할 수 있는 방식으로, 실시간 시스템이나 시분할 시스템에서 빠른 응답을 보장하는 데 유용하지만 문맥 교환(context switching) 오버헤드가 발생한다. 우선순위(priority) 스케줄링은 정적 우선순위와 동적 우선순위로 나뉘며, 정적 방식은 순위가 불변하여 오버헤드가 적고, 동적 방식은 상황에 맞게 순위가 재조정되어 오버헤드는 크지만 처리 효율과 응답도를 개선한다. 기한부(deadline) 스케줄링은 실시간 시스템에서 작업이 명시된 기한 내 완료되도록 계획하는 기법으로, 사전 자원량 예측의 곤란, 지속적 신규 작업 진입 시의 복잡성, 집중적인 자원 운영에 따른 큰 오버헤드 등의 제약이 따른다.

### 실시간 시스템 스케줄링
실시간 시스템은 정해진 시간 제약의 엄격성에 따라 경성 실시간 시스템과 연성 실시간 시스템으로 구분된다. 경성 실시간 시스템(hard real-time system)은 중요한 태스크가 정한 시간 내에 반드시 완료되도록 보장하는 시스템으로, 데이터 검색부터 요청 완료까지의 모든 지연이 제한되어야 하므로 라운드로빈 스케줄링과 혼용될 수 없다. 반면 연성 실시간 시스템(soft real-time system)은 시간적 제한이 다소 약한 형태로, 중요한 실시간 태스크가 완료될 때까지 다른 태스크보다 높은 우선순위를 유지하며 다른 시스템과 혼용할 수 있도록 지원한다. 연성 실시간 시스템은 마감시간(deadline) 스케줄링을 지원하지 않아 산업용 제어나 로봇공학에는 부적합하지만 가상현실 및 해저 탐사 등의 분야에 활용된다. 스케줄링 방식으로는 태스크 집합이 미리 정의되어 주기적 연성 태스크에 적합한 정적 스케줄링과 태스크의 수와 특성이 실행 시 결정되는 동적 스케줄링이 있다. 대표적인 정적 방식인 RM(Rate Monotonic) 알고리즘은 태스크 주기가 짧을수록 높은 우선순위를 부여하며, 대표적인 동적 방식인 EDF(Earliest-Deadline First) 알고리즘은 임계시간(마감시간)이 가장 근접한 태스크를 최우선으로 수행한다.

### 다중프로세서 스케줄링
다중프로세서 시스템은 프로세서들의 구조적 일치 여부에 따라 이질 시스템과 동질 시스템으로 구분된다. 이질 시스템은 각 프로세서가 고유한 구조 형태를 가져 전용 큐와 자체 스케줄링 알고리즘을 사용하며, 해당 프로세서 전용 명령어로 작성된 프로그램만 실행할 수 있다. 반면 동질 시스템은 프로세서 간 부하 공유(load sharing)를 수행하며, 개별 큐 운영 시 발생할 수 있는 유휴 프로세서 문제를 방지하기 위해 단일 공동 준비 큐를 운영하여 가용한 프로세서에 작업을 할당한다. 스케줄링 동작 방식은 각 프로세서가 공동 준비 큐를 직접 확인하여 작업을 선택하는 자율적 방식과, 특정 프로세서가 전체 스케줄러 역할을 담당하는 주-종 구조(master-slave structure)로 나뉜다.

### FCFS(First-Come-First-Served) 스케줄링
FCFS 스케줄링은 프로세스가 대기 큐에 도착한 순서대로 CPU를 할당받는 가장 단순한 비선점 스케줄링 기법이다. CPU를 한 번 점유한 프로세스는 실행이 완료될 때까지 CPU를 반환하지 않으며, 모든 프로세스가 공평하게 취급되어 작업 완료 시간의 예측이 용이하고 응답시간 차이가 적다. 그러나 긴 수행 시간을 가진 프로세스가 먼저 도착할 경우 후속 프로세스들이 지나치게 오래 대기하게 되는 호위 효과(convoy effect)가 발생할 수 있다. 호위 효과가 나타나면 시스템 전체의 평균 대기시간이 대폭 증가하고 CPU 및 장치 이용률이 크게 저하되는 단점이 있다.

### SJF(Shortest Job First) 스케줄링
SJF 스케줄링은 대기 중인 프로세스 중에서 CPU 버스트 시간이 가장 짧은 프로세스에 CPU를 먼저 할당하는 비선점 스케줄링 기법이다. 이 방식은 FCFS 방식에 비해 시스템의 평균 대기시간을 대폭 감소시켜 대기시간을 최소화하는 최적의 효과를 제공한다. 그러나 프로세스의 정확한 실행 시간을 사전에 파악하기 어렵고, 적절한 응답시간이 필수적인 시분할 시스템에는 적합하지 않다는 한계가 있다. 실행 시간 예측을 사용자에게 의존하는 경우 규칙적인 실행 환경에서는 예측이 가능하나, 개발 중인 프로그램 환경에서는 정확한 소요 시간을 예측하기 힘들다.

### 우선순위(Priority) 스케줄링
우선순위 스케줄링은 각 프로세스에 우선순위를 부여하고 가장 높은 우선순위를 가진 프로세스에게 CPU를 먼저 할당하는 방식으로, 선점형 또는 비선점형으로 구현될 수 있다. 동일한 우선순위를 가진 프로세스들 사이에서는 FCFS 순서로 스케줄링이 이루어진다. 우선순위는 제한시간, 메모리 요구량, 개방 파일 수, 평균 입출력 버스트 비율 등을 기준으로 계산하는 '내부적 우선순위'와 프로세스 중요성, 이용 자금, 지원 부서, 정책적 요인 등을 반영하는 '외부적 우선순위'로 결정된다. 우선순위 알고리즘의 주요 문제점은 낮은 우선순위 작업이 무한정 대기하는 무한 대기(indefinite blocking) 및 기아 현상(starvation)이며, 이를 해결하기 위해 대기 시간이 길어질수록 우선순위를 점진적으로 높여주는 에이징(aging) 기법을 적용한다.

### 라운드로빈(Round-Robin) 스케줄링
라운드로빈 스케줄링은 FCFS 방식으로 나열된 프로세스들에게 동일한 크기의 CPU 할당시간(time quantum)을 부여하는 시분할 시스템 전용 선점 스케줄링이다. 할당시간이 만료되면 CPU는 주기적으로 선점되어 대기 큐의 다음 프로세스로 넘어가며, 효율적인 문맥교환과 충분한 주기억장치 확보를 통해 선점 오버헤드를 최소화할 수 있다. 할당시간의 크기(통상 10~100ms)는 시스템 성능에 절대적인 영향을 미쳐 크기가 지나치게 크면 FCFS와 동일해지고, 지나치게 작으면 빈번한 문맥교환으로 인한 오버헤드가 증가하여 시스템 성능이 저하된다. 대화식 시스템에서는 프로세스가 I/O 요청을 발생시키거나 작업을 완료할 수 있도록 충분한 크기의 할당시간을 설정하여 적절한 응답시간을 보장한다.

### SRT(Shortest Remaining Time) 스케줄링
SRT 스케줄링은 SJF 기법에 선점 방식을 도입한 알고리즘으로, 시분할 시스템에 유용하게 적용된다. 새로 도착한 프로세스를 포함하여 처리가 완료될 때까지 남은 실행 시간이 가장 짧다고 판단되는 프로세스에게 CPU를 할당하며, 더 짧은 잔여 시간을 가진 프로세스가 도착하면 실행 중인 프로세스를 선점한다. 이론적으로 대기시간을 최소화할 수 있지만, 각 프로세스의 잔여 실행 시간을 추적 및 보유해야 하고 잦은 선점이 발생하여 SJF보다 더 많은 오버헤드와 비용이 발생한다. 실행 완료가 임박한 프로세스가 불필요하게 선점되는 비효율을 방지하기 위해 잔여 시간이 특정 임계치(threshold value)보다 적으면 선점 없이 작업을 완수하도록 제어할 수 있다.

### 다단계 큐(Multilevel Queue) 스케줄링
다단계 큐 스케줄링은 단일 준비 큐를 기억장치 요구량, 우선순위, 프로세스 유형 등 고유 특성에 따라 다수의 별개 큐로 분할하여 운영하는 방식이다. 분할된 각 큐는 고유한 스케줄링 알고리즘을 독립적으로 적용하며, 통상 전면 작업(foreground, 대화식) 큐에는 라운드로빈 방식을, 후면 작업(background, 일괄처리) 큐에는 선입선출(FCFS) 방식을 적용한다. 큐 간에는 고정된 우선순위 선점식 스케줄링이 적용되어 상위 우선순위 큐가 비어 있지 않으면 하위 우선순위 큐의 프로세스는 CPU를 할당받을 수 없는 절대적인 우선순위 체계를 가진다.

### 다단계 큐(Multilevel Queue) 스케줄링 간 시간 분할
다단계 큐 스케줄링에서는 우선순위가 다른 여러 큐 사이에 중앙처리장치(CPU) 실행 시간을 나누어 배분할 수 있다. 각 큐는 중앙처리장치 시간의 일정량을 할당받아 해당 큐 내부에 적합한 고유의 스케줄링 방식을 적용한다. 예를 들어 전면 작업 큐와 후면 작업 큐로 구성된 시스템의 경우, 전면 작업 큐에는 라운드로빈(RR) 스케줄링을 위해 전체 CPU 시간의 80%를 할당하고, 후면 작업 큐에는 선입선처리(FCFS) 방식으로 처리되도록 20%를 할당하여 운영할 수 있다. 또한 일괄처리 프로세스가 실행 중이더라도 대화식 프로세스가 준비 큐에 들어오면 일괄처리 프로세스가 선점된다.

### 다단계 피드백 큐(Multilevel Feedback Queue) 스케줄링
다단계 피드백 큐는 프로세스의 정확한 중앙처리장치 요구량을 사전에 알지 못할 때 시스템의 동적 변화에 적응(adaptive)하여 프로세스를 분류하는 기법이다. 짧은 작업에 유리하고 입출력(I/O) 위주 작업에 우선권을 부여하며, 작업의 특성을 빠르게 파악하여 스케줄링하는 것을 목적으로 한다. 새로운 프로세스는 1단계 큐의 뒤쪽에 진입하여 FCFS 방식으로 처리되며, 할당된 시간 내에 완료되지 못하면 다음 하위 단계의 큐로 이동되어 재배치된다. 큐의 단계가 낮아질수록 할당 시간은 증가하며, 마지막 단계의 큐에서는 작업이 완료될 때까지 라운드로빈 방식으로 순환된다. 상위 단계의 모든 큐가 비어 있지 않으면 하위 큐의 프로세스는 수행될 수 없고, 수행 중인 프로세스라도 더 높은 큐의 프로세스에 의해 선점될 수 있다. 반대로 할당 시간이 만료되기 전 자진해서 중앙처리장치를 양도하는 프로세스는 피드백 네트워크를 통해 한 단계 높은 큐로 올라가도록 설정할 수 있다.

### HRN(High Response ratio Next) 스케줄링
HRN 스케줄링은 최단 작업 우선(SJF) 기법의 약점인 긴 작업과 짧은 작업 간의 지나친 불평등을 보완하기 위해 대기시간을 고려하여 우선순위를 결정하는 비선점형 스케줄링 기법이다. 우선순위 결정 계산식은 `(대기시간 + 버스트시간) / 버스트시간`이며, 이 계산을 통해 얻은 시스템 응답시간(Response ratio) 값이 클수록 높은 우선순위를 부여받는다. 따라서 실행 시간이 긴 작업이라도 큐에서 오래 대기하여 대기시간이 커지면 우선순위가 높아지므로 기아 상태를 완화한다. 예를 들어 P1(대기시간 16, 버스트시간 4), P2(대기시간 10, 버스트시간 5), P3(대기시간 7, 버스트시간 7), P4(대기시간 18, 버스트시간 6)가 있을 때, 계산된 응답시간은 각각 P1=5, P4=4, P2=3, P3=2가 되어 P1, P4, P2, P3 순으로 중앙처리장치를 할당받는다.

### 스레드(Thread)의 정의 및 특징
스레드는 프로세스보다 작고 독립적으로 스케줄링이 가능한 프로그램 단위이자 중앙처리장치에 보내져 실행되는 기본 실행 단위이다. 각 스레드는 서로 독립적이어서 실행 및 종료 순서를 예측할 수 없으며, 프로그램 외부에서는 독립된 단위로 보이지 않는다. 각 스레드는 고유의 프로그램 카운터(PC), 레지스터, 스택을 가지지만, 자신이 속한 프로세스의 코드, 정적(static) 데이터, 힙(heap) 영역 및 주소 공간, 전역 변수, 개방된 파일, 자식 스레드, 시그널, 세마포어 등을 공유한다. 한 스레드가 취한 행동은 프로세스 내의 다른 스레드에 영향을 미칠 수 있으며, 프로세스가 exit() 시스템 호출을 통해 종료되면 그 프로세스에 속한 모든 스레드 역시 함께 종료된다.

### 단일 스레드와 다중 스레드(다중 스레딩)
다중 스레딩(Multithreading)은 하나의 프로세스 내에 다수의 실행 단위를 두어 하나의 프로그램을 동시에 처리하는 방식이다. 프로세스 내의 스레드들은 힙, 정적 영역, 코드를 서로 공유하면서도 각자 독립된 스택과 레지스터 집합을 유지한다. 자원을 공유하기 때문에 다수의 독립 프로세스를 생성할 때 발생하는 자원의 중복 생성 및 관리 오버헤드를 최소화할 수 있다. 예를 들어 다수의 클라이언트가 단일 웹 서버에 접속할 때, 단일 스레드 기반 프로세스 방식은 이전 사용자의 요청 처리가 끝날 때까지 대기해야 하지만, 다중 스레드 방식을 활용하면 긴 대기 없이 동시에 서비스를 처리할 수 있다.

### 중량 프로세스(HWP)와 경량 프로세스(LWP)
중량 프로세스(Heavy Weight Process)는 오직 하나의 스레드만을 가진 전통적인 프로세스를 의미한다. 프로세스는 내부에 스레드가 최소 하나 이상 존재해야만 실행될 수 있다. 반면 경량 프로세스(Light Weight Process)는 프로세스 내에 두 개 이상의 스레드를 포함하고 있을 때 그 각각의 스레드를 의미한다. 경량 프로세스들은 동일한 프로그램 코드, 데이터, 시스템 자원을 공유하며, 개별적으로 프로그램 카운터, 레지스터, 스택을 독립적으로 할당받아 단일 프로세서의 메모리나 다중 프로세서의 단일 공유 메모리 상에서 실행된다.

### 디스크의 물리적 구조
디스크는 프로그램이나 데이터와 같은 정보를 저장하기 위한 온라인 기억 매체이다. 디스크의 물리적 구조는 부채꼴 모양으로 나뉜 구역인 섹터(sector)와 중심축을 둘러싼 동심원 형태의 트랙(track)으로 구성된다. 섹터와 트랙의 교차점으로 둘러싸인 각각의 구역은 블록(block)이라 부르며, 보통 몇 개의 섹터를 모아 하나의 블록을 형성한다. 실린더(cylinder)는 디스크팩에서 동일한 인덱스 번호를 가진 트랙의 모임으로, 헤드가 한 번에 판독하거나 기록할 수 있는 원통형의 트랙군을 의미한다. 플래터(platter)는 접시 형태의 데이터를 기록하는 둥근 원판으로, 다른 종류의 디스크와 구별하기 위해 하드디스크 드라이브(HDD) 속의 디스크를 지칭한다.

### 디스크 접근 시간의 구성
디스크로부터 데이터를 접근하는 데 소요되는 총 디스크 접근 시간은 '탐색 시간 + 회전 지연 시간 + 전송 시간'의 합으로 계산된다. 탐색 시간(seek time)은 여러 실린더 중에서 실제 원하는 실린더를 찾는 데 헤드가 이동하며 소요되는 시간이다. 회전 지연 시간(latency time)은 해당 실린더에 헤드가 위치한 후 원판이 회전하여 처리할 데이터가 있는 섹터 위치까지 도달하는 데 걸리는 시간이다. 전송 시간(transmission time)은 판독된 데이터를 주기억장치로 전달하는 데 소요되는 시간이다. 기계적 지연 요소 중 일반적으로 탐색 시간이 회전 지연 시간보다 크다.

### 광저장매체(CD-ROM)의 구조와 회전 방식 비교
CD-ROM은 레이저를 이용한 재생 방식을 적용하며 650MB 이상의 데이터 용량을 제공하고, DVD-ROM은 4.7GB 이상의 용량을 지원한다. 하드디스크가 동심원 형태의 트랙을 사용하는 반면, CD는 안쪽에서 시작하여 바깥쪽으로 연속되는 나선형 트랙 구조를 가지며 데이터 밀도가 일정하다. 하드디스크는 디스크 회전 속도가 일정한 CAV(Constant Angular Velocity) 방식을 사용하여 바깥쪽 트랙을 읽을 때 데이터 전송 속도가 빠르다. 반면 CD는 데이터 전송 속도를 일정하게 유지하는 CLV(Constant Linear Velocity) 방식을 사용하여 헤드 위치에 따라 모터 회전 속도를 변경한다. CLV는 CAV에 비해 기록 용량이 크지만, 광헤드가 이동할 때마다 회전 속도를 변경해야 하므로 액세스 시간이 길어지며 나선형 트랙 구조와 함께 접근 속도를 느리게 만드는 원인이 된다.

### FCFS 및 SSTF 디스크 스케줄링
디스크 스케줄링은 대기 중인 디스크 접근 요청들을 검토하여 기계적 이동을 최소화하도록 요청 큐를 재배열하는 기법이다. FCFS(First Come First Served) 스케줄링은 요청이 들어온 순서대로 처리하는 방식으로 공평성이 보장되고 구현이 간단하지만, 탐색 패턴의 최적화가 없어 효율이 낮다. SSTF(Shortest Seek Time First) 스케줄링은 현재 헤드 위치에서 탐색 시간이 가장 짧은(트랙 거리가 가장 가까운) 요청을 먼저 서비스한다. SSTF는 FCFS보다 처리율이 높고 평균 응답 시간이 짧으나, 최단 작업 우선(SJF) 형태이므로 바깥쪽 요청에 대한 기근(starvation) 현상이 발생할 수 있으며 안쪽과 바깥쪽보다 가운데 트랙이 더 많은 서비스를 받아 응답 시간 편차가 크다.

### SCAN 및 C-SCAN 디스크 스케줄링 계열
SCAN 알고리즘은 진행 방향 상에서 가장 짧은 거리에 있는 요청을 서비스하는 방식으로, 엘리베이터 알고리즘으로도 불린다. 헤드가 한쪽 끝에서 반대편 끝까지 왕복 이동하며 도중의 요청을 처리하므로 SSTF의 편차 문제를 개선하지만, 가장자리 트랙이 가운데 트랙보다 서비스를 적게 받는 문제가 남는다. LOOK 알고리즘은 SCAN과 동일하게 동작하되 끝까지 가지 않고 진행 방향의 마지막 요청 트랙까지만 이동한다. C-SCAN(Circular SCAN)은 안쪽과 바깥쪽 트랙을 환형(circular)으로 연결하듯 한쪽 방향으로만 서비스를 수행하며, 반대쪽 끝에 다다르면 서비스를 제공하지 않고 처음 시작 방향으로 되돌아간 뒤 다시 이동한다. 이를 통해 가장자리 트랙의 불공정한 대기 시간을 개선하고 응답 편차를 크게 줄인다. C-LOOK 알고리즘은 C-SCAN의 동작 방식에서 양 끝 트랙 대신 마지막 요청 트랙까지만 헤드를 이동시키는 기법이다.

### 보안 취약점과 보안위협의 상관관계
보안 취약점은 특정 자산이 내포하고 있는 보안 관점의 약점으로, 자산의 존재 및 활용 도중 물리적·논리적 손실을 가져올 수 있는 특성이며 모든 자산에는 고유의 취약점이 존재합니다. 보안위협은 이러한 특정 자산의 약점을 이용하여 해당 자산을 불법 점유하거나 악용하고자 하는 비인가된 행위를 의미합니다. 보안사고는 특정 자산의 보안 취약점을 이용한 보안위협의 실행으로 인해 발생합니다.

### 정보보호 전략의 개념 및 구성
정보보호 전략은 조직이나 개인의 상황을 바탕으로 정보보호 목표를 달성하기 위해 적용되는 제한된 방법이자 개별적인 특성을 의미합니다. 정보보호 목표는 경영목표에 종속되며, 정보보호 전략은 이러한 정보보호 목표에 종속되는 관계를 가집니다. 또한 정보보호 전략은 ‘적용 영역’, ‘적용 방법’, ‘특성’의 세 가지 요소로 구성됩니다. 실무에서는 정보보호 정책서나 시행지침 등을 통해 목표 달성 전략을 확인하고, 영역과 수단/방법 및 요구사항인 특성을 도출하여 분석합니다.

### 정보자산 식별 및 보안등급 설정 시 유의사항
정보자산의 보안등급은 조직의 규모, 정보자산 취급 담당자의 직무 및 업무 범위, 권한에 따라 상이하게 결정될 수 있습니다. 특정 사용자에 따라 등급이 달라질 수 있으나, 해당 정보자산의 전체 이해관계자 관점에서 보안등급을 각각 평가한 후 가장 높은 등급을 해당 정보자산의 최종 보안등급으로 설정해야 합니다. 또한 정확한 취약점과 위협을 판단하기 위해서는 전체 이해관계자, 취급 과정, Life-Cycle에 대한 조사가 필수적입니다. 아울러 정보자산의 특성에 따라 적용되는 솔루션과 보안 기술이 달라질 수 있으며, 도입된 솔루션이나 기술의 초기 수립된 Life-Cycle은 사회적·기술적·경제적·정치적 환경 변화에 의해 수정되거나 변경될 수 있습니다.

### 운영보안 목적 확인 및 정보자산 조사 절차
보안체계 운영을 위해서는 먼저 정보보호 정책서와 시행지침을 조사하여 정보보호 목표와 전략, 구체적인 운영보안 목적을 도출해야 합니다. 이어서 조직에서 취급하는 정보 유형과 각 항목별 취급 프로세스를 조사합니다. 도출된 운영보안 목적에 맞추어 정보자산을 분류해 목록화하고, 중요도에 따라 보안등급을 설정합니다. 마지막으로 분류된 정보자산별로 기밀성, 무결성 등의 보안요구사항과 이에 연계된 보안위협 및 취약점을 파악하여 관리 체계를 구축합니다.

### 정보보호 자산의 결정 및 도입절차 수립
분류된 정보자산의 보안위협과 취약점을 고려하여 이에 적합한 정보보호 솔루션 및 보안 기술을 결정하고 해당 자산의 Life-Cycle을 도출해야 합니다. 정보보호 자산의 도입절차를 수립할 때에는 우선 자산 도입 시의 고려사항을 명확히 결정합니다. 다음으로 결정된 도입 고려사항에 따른 이해관계자를 조사하고, 이들로부터 합의해야 할 내용을 도출합니다. 최종적으로 도출된 합의 내용과 실제 요구사항을 반영하여 정보보호 자산의 도입 절차를 체계적으로 수립합니다.

### 정보보호 자산의 변경 절차 수립
도출된 정보보호 자산이 수명주기(Life-Cycle)에 도달했을 때를 대비하여 체계적인 변경 절차를 수립해야 합니다. 이를 위해 먼저 정보보호 자산의 Life-Cycle 도달 판정 기준과 판정 방법을 수립하고, 이에 따른 이해관계자를 조사하여 합의해야 할 내용을 도출한 후 실제 자산 변경을 위한 절차를 마련합니다. 예를 들어 문서보안(DRM)의 경우 라이선스 한계치 도달 여부 등을 판정 기준으로 삼아 현황 분석과 실태 조사를 수행하고, 판정 이후에는 도입 절차와 동일한 과정을 거쳐 변경을 진행하게 됩니다. 아울러 정보보호 목표 달성을 위한 전략은 조직, 기업, 기관의 특성에 따라 다양한 방식으로 기술, 표현, 전달, 보관될 수 있습니다.

### 정보보호 요구사항
정보보호 요구사항은 조직이나 개인이 운영하는 자산에 요구되는 보안적인 특성으로, 특정 자산이 유실되거나 훼손되었을 때 발생할 수 있는 부정적인 효과에 대비하기 위해 마련됩니다. 이러한 요구사항은 일반적으로 기밀성, 무결성, 인증, 가용성, 부인방지, 추적의 6가지 항목으로 구분됩니다. 기밀성은 자산이 외부에 유출되는 것을 방지하는 특성이며, 무결성은 인가되지 않은 상태에서 자산이 변경되는 것을 방지하는 특성입니다. 또한 인증은 사용자의 식별과 접근 권한을 검증하는 것이고, 가용성은 적시에 자산 활용 가능성을 유지하는 것이며, 부인방지는 특정 행위의 부인을 사전에 방지하고 추적은 사건 이력을 확인할 수 있는 가능성을 뜻합니다.

### 접근통제의 개념 및 유형
접근통제는 특정 객체에 대한 주체의 식별과 주체가 가진 권한에 대한 검증을 수행하는 일체의 행위이며, 일반적으로 주체와 객체의 보안적 특성을 비교하여 검증을 진행합니다. 접근통제 유형은 강제적 접근통제(MAC), 임의적 접근통제(DAC), 역할기반 접근통제(RBAC)의 3가지 방식을 기본으로 하며, 복합 및 응용형으로도 적용할 수 있습니다. 강제적 접근통제(MAC)는 주체와 객체의 보안등급이나 보안 그룹 등의 보안 특성을 비교한 후 정해진 접근통제 원칙에 적용하여 허용 여부를 결정합니다. 이에 반해 임의적 접근통제(DAC)는 주체의 객체에 대한 접근 권한을 정책으로 직접 설정하여 허용 또는 차단을 결정하며, RBAC는 사용자의 역할에 따라 접근 권한을 관리합니다.

### 역할기반 접근통제(RBAC)의 개념 및 동작

역할기반 접근통제(RBAC)는 강제적 접근통제(MAC)와 임의적 접근통제(DAC)를 혼합한 방식으로, 주체에 대해 특정 역할을 부여하고 해당 역할별로 객체에 대한 접근 권한을 정책으로 설정하여 허용 여부를 결정합니다. 예를 들어 직원 A에게 ‘팀장’ 역할을, 직원 B에게 ‘팀원’ 역할을 부여하고 특정 문서의 접근 정책을 ‘팀원’ 역할에 대해서만 읽기 및 쓰기를 허용하도록 설정할 수 있습니다. 이 경우 해당 정책에 따라 팀원 역할을 가진 직원 B는 읽기와 쓰기가 가능하지만, 팀장 역할을 가진 직원 A는 문서에 대한 접근이 차단됩니다.

### 침해사고 대응절차 수립 시 안전 및 유의 사항

침해사고 대응절차를 수립할 때 적용되는 정보보안 솔루션 및 보안 기술은 조직의 규모와 업무 분야에 따라 다를 수 있으며, 서비스에서 요구되는 성능 및 용량 또한 IT 정보 서비스의 운영 목표와 정보자산의 중요도 및 용량 등에 따라 상이할 수 있습니다. 여기서 “장애관리”는 정보자산 및 정보시스템의 장애뿐만 아니라 무결성 위배, 정보자산 유출 등 포괄적인 비정상 운영상태를 나타냅니다. 정보자산 이동 및 배포를 위한 저장매체 활용은 정보자산 식별을 통해 통제되므로 접근통제정책을 설정하기 전에 정보자산 및 정보시스템 자산의 식별과 통제가 우선적으로 적용되어야 합니다. 아울러 침해사고 모니터링은 기본적으로 외부 침입 여부를 감지하기 위해 수행되지만 조직의 목표와 보안환경에 따라 내부 모니터링도 수행될 수 있습니다.

### 정보시스템의 성능 및 용량관리 절차 수립

정보시스템의 가용성을 보장하기 위해 성능 및 용량관리 절차를 체계적으로 수립해야 합니다. 우선 정보시스템 자산을 목록화하고 자산별 가용성 만족을 위한 성능 및 용량관리 항목을 도출하여 자산별 가용성 만족 수준을 확인합니다. 이어서 도출된 항목별로 허용 가능한 만족 기준과 이를 평가하기 위한 방법을 결정합니다. 마지막으로 성능과 용량을 검사할 담당자를 임명하고 검사 주기를 설정하며, 성능 및 용량이 기준치에 미달할 경우 가용성 만족을 위해 조치하는 절차를 수립하여 관리합니다.

### 보안사고 대응을 위한 장애관리 절차 수립

침해사고를 포함한 보안사고에 대응하기 위해서는 단계별 장애관리 절차를 마련해야 합니다. 첫 번째로 조직에서 적용 중인 자산을 확인하고 과거 침해사고 및 정보보호 시사 정보를 바탕으로 예상 보안사고 유형을 조사합니다. 두 번째로 전체 자산에 대해 발생 가능한 보안사고를 확인하고 보안사고 발생 시 이를 판정할 수 있는 기준을 수립합니다. 끝으로 분석된 예상 장애 상황에 대비하여 각 자산의 복구 목표를 결정하고 해당 목표를 달성하기 위한 구체적인 장애 대응 절차를 마련합니다.

### 데이터 무결성 및 가용성 유지를 위한 백업 절차 수립

데이터의 무결성과 정보시스템의 가용성을 지속적으로 유지하기 위한 백업 절차의 초기 단계로 자산 조사를 수행합니다. 먼저 데이터 무결성을 유지해야 하는 대상 정보자산을 명확히 조사합니다. 이후 조사된 정보자산을 실제로 저장 및 관리하고 있는 정보시스템이 무엇인지 확인하는 과정을 거칩니다.

### 정보자산 백업 및 복구 절차 수립
확인된 정보시스템 내 정보자산의 위치를 파악한 후, 백업 위치와 주기 및 백업 방법을 결정하여 백업 절차를 수립한다. 아울러 무결성이 훼손되는 상황에 대비하여 백업 데이터를 기반으로 정보자산을 복원할 수 있는 복구 절차를 마련해야 한다. 실무적으로는 그룹웨어의 SAN 실시간 백업 및 수동 복구(SAN Recover), 인사정보 시스템의 일일 자동 백업 및 수동 복구(HDD 복원)와 같이 자산별 백업 위치와 세부 절차를 구체화하여 운용한다.

### 정보자산 접근통제정책 수립
정보보호의 기밀성을 확보하기 위해 분류된 정보자산의 등급과 속성에 맞추어 접근통제정책을 수립한다. 기업 내 전체 정보자산 중 중요 자산을 판별하고 업무 프로세스 및 보안 속성을 고려해 보안등급과 접근통제 모델(DAC, MAC 등)을 도출한다. 이후 보안이 적용될 업무 시점과 지점을 파악하여 적합한 보안 솔루션이나 기술을 조사·결정하며, 수립된 정책을 DRM Server나 방화벽(Firewall) 등의 솔루션 및 기술에 반영하여 적용한다.

### 정보시스템 저장 매체관리 체계 및 절차 수립
정보시스템 저장 매체 관리를 위해 중요 정보가 유통되는 저장매체(CD, USB 토큰 등)와 유출 경로가 되는 연결 인터페이스(CD-Rom, USB IF 등)를 조사한다. 이후 정보 유출을 통제하기 위한 업무 프로세스와 이를 관리·감독할 업무 담당자를 지정하여 운영 만족 기준을 마련한다. 업무 담당자가 수행할 불시 점검 및 비인가 매체 수거 등의 절차를 수립하고, 필요한 지원 시스템을 구축한 후 이에 대한 사용 계획과 방법을 공지하여 체계를 운영한다.

### 외부 침해시도 모니터링 체계 및 절차 수립
외부 침해시도를 상시 감시하기 위해 예상되는 보안사고 유형별 침해 기법과 사고 발생 인지 방법을 조사한다. 인지 방법에 따라 전문 모니터링 조직(관제팀, 정보 책임자 등), 대상, 기법(ESM 모니터링, 무결성 검사 등)을 규정하고, 인지 후 보고·통지·신고로 이어지는 침해사고 대응 절차를 수립한다. 이러한 침해사고 대응 체계 및 절차는 조직의 규모, 분야, 운영 수준, 자산의 중요성 등에 따라 다양하게 구성될 수 있다.

### 정보자산 식별 및 도입

### 침해사고 평가 방법 및 피드백
평가는 문제해결 시나리오, 서술형 시험, 구두 발표 등의 방법으로 나누어 실시합니다. 문제해결 시나리오와 서술형 시험에서는 침해사고 유형별 보고, 법적 통지, 신고 대상 도출 및 대응절차에 따른 처리와 복구 수행·방법을 평가 항목으로 둡니다. 구두 발표에서는 침해사고 원인 분석 및 재발방지대책 수립 사례 분석, 종결 이후 대응체계 변경사항 도출 사례 및 절차를 평가하며, 문제해결 시나리오 수행 후에는 도출된 문제 해결 과정 및 결과의 오류나 미흡한 점을 지적하고 보완 설명하는 피드백을 제공합니다.

### 업무영향분석(BIA)의 개념 및 유형
업무영향분석(BIA: Business Impact Analysis)은 특정 자산의 손실, 훼손, 분실로 인해 조직이 입는 피해 정도를 조사하고 분석하여 자산의 중요도를 판정하는 업무로, 업무 연속성 계획(BCP) 수립의 초석이 됩니다. BIA의 시행 유형은 직접적 분석과 간접적 분석으로 구분됩니다. 직접적 분석은 물리적·논리적 자산의 손실에 따른 기회비용과 정량적인 자산 복구비용을 도출하는 방식으로 시스템 복구비용이나 행정서류 재구비 비용 등이 해당합니다. 반면 간접적 분석은 장기간 축적된 무형적 자산을 대상으로 정성적인 복구비용을 도출하는 방식이며 조직의 브랜드 이미지나 기업 명성가치 등이 대표적인 분석 대상입니다.

### 회전 지연 시간 최적화 기법 (에션바흐 기법 및 SLTF)
에션바흐(Eschenbach) 기법은 탐색 시간뿐만 아니라 회전 지연 시간까지 함께 최적화하려는 최초의 시도로, 부하가 매우 큰 항공 예약 시스템을 위해 개발되었다. 헤드는 C-SCAN처럼 이동하며 모든 실린더는 요청 유무와 무관하게 한 바퀴 회전하는 동안 서비스를 받고, 한 실린더 내의 회전 방향과 위치를 고려하여 요청 큐를 재배열한다. SLTF(Shortest Latency Time First) 스케줄링은 섹터 큐잉(sector queuing)으로도 불리며, 특정 실린더에 도착했을 때 여러 트랙의 요청을 섹터 위치에 따라 정렬하여 가장 가까운 섹터부터 우선 서비스한다. 이 기법은 탐색 시간이 없어 회전 시간만이 지연 요소가 되는 고정 헤드 장치(예: 드럼)나 헤드 이동이 거의 없는 경우의 스케줄링에 주로 적용된다.

### 디스크 스케줄링 알고리즘 선택 및 파일 시스템 구조
디스크 스케줄링 성능은 요청의 형태와 수, 파일 할당 방법에 따라 크게 좌우된다. 연속 할당된 파일은 레코드들이 디스크상에 인접해 헤드 움직임 영향이 적으나, 링크된 파일이나 색인화된 파일은 레코드가 디스크 전반에 산재하여 헤드 이동을 고려한 스케줄링이 필수적이다. 또한 파일을 오픈할 때 디렉터리 구조를 탐색하므로, 디렉터리와 색인 블록을 디스크 끝단보다 중간 부분에 배치해야 헤드 이동 거리를 줄일 수 있다. 파일 시스템은 실제 파일들의 집합체와 디렉터리 구조로 구성된다. 데이터의 계층 구조는 '비트 → 바이트 → 문자 세트 → 필드(상호 관련 문자의 집합) → 레코드(관련 필드의 집합) → 파일(관련 레코드의 집합) → 데이터베이스(관련 파일의 집합)' 순으로 정의되며, 레코드 구분을 위해 고유 식별 제어 필드인 레코드 키가 사용된다.

### 논리적 레코드와 물리적 레코드
논리적 레코드(logical record)는 사용자의 관점에서 취급되는 자료 집단의 단위이며, 물리적 레코드는 장치로부터 입·출력되는 실제 정보의 단위이다. 물리적 레코드가 단 하나의 논리적 레코드로 구성된 파일을 블로킹되지 않은 레코드(unblocked record) 파일이라 하고, 여러 개의 논리적 레코드가 모여 하나의 물리적 레코드를 구성한 파일을 블로킹된 레코드(blocked record) 파일이라 부른다. 고정길이 레코드 파일은 모든 레코드의 길이가 동일하며 블록의 크기는 일반적으로 레코드 크기의 정수배를 가진다. 반면 가변길이 레코드 파일은 레코드 길이가 다양하게 나타나며 최대 크기는 블록의 크기와 동일할 수 있다.

### 파일 시스템의 주요 기능
파일 시스템은 사용자가 파일을 생성, 수정, 삭제할 수 있도록 지원하며, 다른 사용자와 파일을 공동으로 사용할 수 있는 적절한 제어 방법을 제공한다. 파일 공유를 위해 판독 접근, 기록 접근, 수행 접근 및 이들의 조합 등 다양한 접근 제어 방식을 운용한다. 사용자와 장치 간의 독립성을 유지하기 위해 물리적 장치 이름 대신 기호화된 이름을 사용하여 파일을 참조하도록 지원한다. 또한 고의적이거나 우발적인 정보 손실 및 파괴를 방지하기 위한 백업과 복구 기능을 제공하며, 정보 보호와 비밀 보장을 위해 암호화 및 복호화 기능을 수행한다. 파일 시스템은 데이터의 물리적 구조가 아닌 논리적 구조를 제공함으로써 사용자가 데이터의 저장 장치, 기억 형태, 전송 방식에 관여하지 않도록 하는 사용자 친숙 인터페이스를 갖춘다.

### 순차 파일(Sequential File)
순차 파일은 논리적인 레코드를 물리적인 순서에 맞추어 연속적으로 저장하고 검색하는 구조이다. 주로 자기 테이프, 디스크, 프린터 출력과 같이 순차적 특성을 지닌 기억 매체에 사용되며, 순차접근 기억장치(SASD)에 저장되어 일괄 처리에 널리 활용된다. 물리적 순서대로 정렬되어 있으므로 다음 레코드에 빠르게 접근할 수 있다는 장점이 있다. 그러나 파일에 저장된 레코드의 순서와 다른 순서로 접근을 시도할 경우 프로그램의 접근 속도가 크게 저하되는 단점이 있다.

### 색인된 순차 파일(Indexed Sequential File)
색인된 순차 파일은 순차 파일과 직접 파일을 결합한 형태로, 순차 접근과 직접 접근을 모두 지원하는 구조이다. 각 레코드는 고유한 키값에 따라 논리적 순서로 배열되어 디스크와 같은 직접접근 기억장치(DASD)에 저장된다. 키값 순서에 따라 레코드를 순차 검색하거나, 인덱스를 활용하여 원하는 레코드를 직접 검색할 수 있어 일괄 처리 및 대화형 처리에 모두 적합하다. 파일 구조의 융통성이 높고 검색 성능이 우수하지만, 필드 배열, 키 필드, 레코드 삽입, 파일 구현 방식 등 시스템 설계 시 고려해야 할 요소가 많다.

### 직접 파일(Direct File)
직접 파일은 다른 레코드를 거치지 않고 보조기억장치의 물리적 주소를 통해 임의의 레코드에 직접 접근할 수 있는 파일 구조이다. 대화형 처리에 유용하며 디스크와 같은 직접접근 기억장치(DASD)에 파일이 저장된다. 특정 레코드를 신속하게 검색하기 위해서는 레코드의 키값을 보조기억장치의 실제 물리 주소로 사상(mapping)시키는 별도의 사상 함수가 요구된다. 다른 레코드에 영향을 주지 않고 특정 레코드의 검색, 삽입, 수정, 삭제가 용이한 장점이 있으나, 키값 순서에 따라 레코드를 차례대로 읽어내는 순차 검색이 어렵다는 단점이 있다.

### 자유 공간 관리 기법: 비트 벡터
비트 벡터는 비트맵 또는 비트 테이블로도 불리며, 디스크의 각 블록마다 하나의 비트를 대응시켜 자유 공간을 관리하는 방식이다. $i$번째 비트는 시스템의 $i$번째 블록을 나타내며, 해당 블록이 비어 있는 자유 공간이면 1, 이미 파일에 할당된 공간이면 0으로 표현한다. 연속된 1의 개수는 곧 연속된 가용 블록의 개수를 의미하므로, 자유 블록이나 연속된 자유 블록을 탐색하기 쉽다는 장점이 있다. 일반적으로 주 메모리에 상주하여 관리되며 리눅스 운영체제의 자유 공간 관리에 사용된다.

### 파일 공간 할당 기법: 연속 할당과 불연속 할당
연속 할당은 파일에 속한 블록들을 보조기억장치 내에 연속적으로 인접한 공간에 배정하는 방식이다. 논리적 블록들이 물리적으로 붙어 있어 접근 속도가 빠르지만, 파일 생성 시 필요한 크기를 미리 명시해야 하며 단편화가 발생하여 주기적인 집약이 요구된다. 불연속 할당 중 연결 리스트 기법은 동일 파일의 섹터들이 포인터를 통해 분산 연결되는 방식이다. 디렉터리에 시작 및 마지막 주소 포인터를 유지하여 구현하지만, 분산된 블록으로 인해 탐색 시간이 길어지고 포인터 저장으로 인한 가용 공간 감소 및 산재 문제가 발생한다. 또 다른 불연속 할당인 색인 블록 기법은 각 파일마다 색인 블록을 두고 산재된 데이터 블록들의 주소 포인터를 모아 관리하는 방식이며, 고정된 수의 항목(블록 식별자, 블록 포인터)을 관리하므로 연결 리스트에 비해 기억장소 낭비가 더 발생할 수 있다.

### 파일 보호 기법
파일 보호는 무단 접근이나 물리적 손상으로부터 파일을 지키는 기법으로 파일 이름, 암호, 접근 제어 방식이 사용된다. 파일 이름 기법은 사용자가 파일의 이름을 알지 못하는 경우 접근 대상에서 제외시키는 초보적인 보호 방식이다. 암호 방식은 사용자마다 암호를 부여하여 이를 통과한 경우에만 접근을 허용하는 방법으로 적은 기억공간을 소모하지만, 보호 정보 노출 시 보안이 취약해질 수 있다. 접근 제어는 운영체제가 사용자의 권한과 허용된 작업을 대조하여 파일 접근을 통제하는 방식이다. 유닉스(UNIX) 시스템의 경우 판독(r), 기록(w), 실행(x)의 3가지 접근 유형과 파일 소유자, 그룹 사용자, 모든 사용자의 3가지 사용자 유형을 조합하여 총 9개의 접근 제어 비트를 통해 권한을 제어한다.

### 디렉터리 구조: 일단계, 이단계, 트리 구조
일단계 디렉터리는 모든 파일이 하나의 디렉터리 내에 존재하는 가장 단순한 구조로, 파일 수가 많아지거나 다중 사용자 환경이 될 때 파일 이름의 중복을 허용하지 않아 제약이 크다. 이단계 디렉터리는 중앙의 마스터 파일 디렉터리(MFD) 아래에 각 사용자별 사용자 파일 디렉터리(UFD)를 두어 사용자 간 파일 이름 충돌을 해결한 구조이나 사용자 간의 파일 공유와 협업에는 제약이 따른다. 트리 구조 디렉터리는 이단계 구조를 일반화하여 사용자가 임의의 깊이로 서브디렉터리를 생성할 수 있도록 확장한 구조이다. 하나의 디렉터리나 서브디렉터리 내부에 파일뿐만 아니라 하위 서브디렉터리를 포함할 수 있으며 모든 디렉터리는 내부적으로 동일한 형식을 유지한다.

### 트리 구조 디렉터리와 경로 이름
트리 구조 디렉터리는 루트 디렉터리를 정점으로 하며, 시스템 내의 모든 파일이 루트로부터 서브디렉터리를 거쳐 지정된 파일에 이르는 유일한 경로 이름을 가진다. 사용자가 현재 작업 중인 파일이 위치하는 디렉터리를 현재 디렉터리(current directory)라 부른다. 경로 이름은 두 가지로 구분되는데, 루트에서 시작하여 목표 파일이나 서브디렉터리에 이르는 경로 상의 모든 디렉터리 이름을 정의하는 '절대 경로 이름'과 현재 디렉터리를 기준으로 경로를 정의하는 '상대 경로 이름'이 있다. 디렉터리 삭제 방식에 있어 MS-DOS는 디렉터리가 비어 있지 않으면 삭제하지 않는 반면, UNIX의 rm 명령은 디렉터리 내부의 모든 파일과 서브디렉터리를 함께 제거해야 한다는 조건하에서 삭제를 수행한다.

### 비순환(비주기) 구조 디렉터리
비순환 그래프(acyclic graph) 디렉터리 구조는 트리 구조 디렉터리가 파일이나 디렉터리의 공유를 금지하는 것과 달리, 디렉터리 간 서브디렉터리나 파일의 공유를 허용하면서 순환(cycle)은 허용하지 않는 방식이다. 파일 및 서브디렉터리의 공유는 링크(link)를 이용하거나 공유 파일에 대한 모든 정보를 그대로 복사하는 방식으로 구현된다. 정보를 복사하여 공유할 경우에는 파일 수정 시 복사된 디렉터리 항목 간 일관성(consistency)을 유지하는 문제가 발생한다. 또한 하나의 파일이 여러 경로 이름을 가질 수 있어 구조가 복잡하며, 공유 파일 삭제 시 할당된 기억장소의 해제 시점 문제와 더불어 이미 존재하지 않는 파일에 대한 불필요한 포인터가 남는 문제가 발생할 수 있다.

### 일반적 그래프 구조 디렉터리
기존의 트리 구조 디렉터리에 새로운 파일이나 서브디렉터리를 첨가하는 것은 트리를 유지하지만, 링크를 첨가하면 트리가 파괴되어 순환을 허용하는 일반적 그래프 구조가 된다. 순환이 허용됨으로써 그래프 탐색 알고리즘이 간단해지고 원하는 파일로의 접근이 용이해지는 장점이 있다. 반면 디렉터리 시스템 내 순환으로 인해 파일을 찾을 때 무한 순환(infinite loop)에 빠질 수 있으므로 전역 탐색 시 신중을 기해야 한다. 아울러 불필요한 파일을 시스템에서 제거하기 위해 각 디렉터리마다 쓰레기 수거(garbage collection)를 수행해야 한다.

### 파일 시스템의 유형 (FAT, NTFS, UFS)
FAT(File Allocation Table)는 MS-DOS 3.0까지 지원하던 FAT12 구조가 있으며, FAT32는 최대 2TB 용량과 256문자의 파일 이름을 지원하여 Windows 95, 98, Me에서 제공되었다. NTFS(New Technology File System)는 마이크로소프트가 개발 당시부터 서버를 위해 개발한 파일 시스템으로, 대용량 파일 표현, EPS(Encrypting File System) 암호 기능, 시스템 고장 및 디스크 손상을 복구하는 데이터 복구 기능을 제공하며 Windows NT, XP, Vista, 7 등에서 쓰인다. UFS(Unix File System)는 유닉스 계열 운영체제의 기본 파일 시스템으로 부트 블록, 슈퍼블록, 아이노드(inode), 데이터 블록으로 구성된다. UFS는 블록을 기본 단위로 필요할 때 동적으로 할당하므로 파일 블록들이 하드디스크 상에 연속적으로 배치될 필요가 없으며, Open BSD, Sun 솔라리스, Apple의 OS X, HP-UX 등에서 변형되어 사용된다.

### Ext 파일 시스템
Ext(Extended File System)는 리눅스의 기본적인 파일 시스템이다. Ext2는 최대 파일 시스템 크기 4TB, 최대 파일 크기 2GB를 지원하며 확장성과 가변 블록 크기 기능을 지원한다. Ext3은 Ext2에 저널링(journaling) 기능이 추가된 것으로, 저널링이란 데이터베이스 백업 기법처럼 파일 쓰기 작업 시 '저널'이라는 로그 영역에 기록한 후 실제 데이터 영역에 기록하는 방식이다. 2010년 4월에 발표된 Ext4는 저널링 기능을 지속적으로 제공하며 지원 가능한 최대 파일의 크기가 16TB로 확장되었다.

### 분산 파일 시스템 (GFS, HDFS)
GFS(Google File System)는 구글이 대규모 클라우드 서비스 제공을 위해 개발한 파일 시스템으로 클라이언트, 마스터, 다수의 청크(chunk) 서버로 구성된다. GFS는 기본 청크 크기인 64MB 단위의 고정 크기로 파일을 분할하여 청크 서버에 분산 저장하며, 클라이언트가 마스터에 파일 접근을 요청하면 마스터로부터 가장 가까운 청크 서버 정보를 받아 해당 서버와 직접 통신한다. HDFS(Hadoop Distributed File System)는 오픈소스 프로젝트 하둡에서 분산 컴퓨팅 프레임워크 지원을 위해 개발한 파일 시스템이다. HDFS는 네임노드 서버, 보조 네임노드 서버, 다수의 데이터노드 서버로 구성되어 데이터를 여러 데이터노드 서버에 분산 저장하며, 아마존, IBM, 야후 등 클라우드 컴퓨팅 플랫폼에서 널리 활용된다.

## kocw_os_c_01

### 운영체제의 개념 및 역할
운영체제(Operating System)는 컴퓨터 하드웨어(프로세서, 메모리, 디스크, 입출력장치 등)를 관리하여 시스템 성능을 높이고 사용자에게 편의성을 제공하는 제어 프로그램(Control program)이다. 정부가 직접 모든 일을 하지는 않지만 자원 관리자 및 자원 할당자로서 국토·인력·예산을 분배하듯, 운영체제 역시 프로세스, 메모리, 입출력장치, 파일 시스템 등을 총괄 배분하는 자원 관리자(Resource manager/allocator) 역할을 수행한다. 컴퓨터 계층 구조상 하드웨어와 애플리케이션 사이에 위치하며, 핵심 관리 기능을 담당하는 커널(Kernel)과 사용자의 입력을 전달받는 명령해석기(Shell, Command interpreter)로 구분된다.

### 부팅 과정과 시스템 초기화
컴퓨터의 전원이 켜지면 프로세서는 ROM에 저장된 POST(Power-On Self-Test)를 실행하여 장치 이상 유무를 점검한다. 이후 부트로더(Boot loader)가 디스크에 저장되어 있는 운영체제 커널 코드를 메인 메모리(RAM)로 읽어 들이는 부팅(Booting) 과정을 거친다. 휘발성 메모리를 사용하는 하드웨어를 안정적으로 구동시키기 위해 운영체제는 부팅을 통해 메모리에 상주(Resident)하게 되며, 부팅이 완료되면 외부 사건(Event)을 수신 대기하는 상태로 전환된다.

### 운영체제 발전 과정
초기 컴퓨터 시스템은 카드 리더, 메모리, 프로세싱, 라인 프린터 중심의 구조에서 상주 모니터를 기반으로 작업을 모아 처리하는 일괄처리 시스템(Batch processing system)으로 출발하였다. 이후 상대적으로 빠른 CPU와 느린 I/O 속도 차이를 극복하기 위해 메모리에 여러 작업(Job)을 동시에 올리는 다중프로그래밍 시스템(Multiprogramming system)이 등장하였으며, 이를 계기로 CPU 스케줄링, 메모리 관리, 보호 기술이 요구되었다. 이어서 다중 사용자와의 상호작용을 위해 시간 단위로 강제 절환(Switching)을 수행하는 대화형(Interactive) 구조의 시공유 시스템(Time-sharing system)으로 발전하였고, 가상 메모리, 프로세스 간 통신, 동기화 개념이 정립되었다.

### 고등 운영체제의 분류
컴퓨터 아키텍처 발전에 따라 등장한 고등 운영체제는 다중프로세서 시스템, 분산 시스템, 실시간 시스템으로 구분된다. 다중프로세서 시스템(Multiprocessor system)은 여러 개의 프로세서를 결합한 병렬 시스템이자 강결합 시스템(Tightly-coupled system)으로, 성능 향상, 비용 절감, 신뢰성 증대라는 3대 장점을 갖는다. 분산 시스템(Distributed system)은 다중 컴퓨터 시스템이자 소결합 시스템(Loosely-coupled system)을 의미하며 분산 운영체제를 통해 제어된다. 실시간 시스템(Real-time system)은 공장자동화(FA), 군사, 항공, 우주 분야와 같이 정해진 기한(Deadline) 내에 처리가 완료되어야 하는 시간 제약 조건을 만족하기 위해 RTOS(Real-time OS)를 사용한다.
