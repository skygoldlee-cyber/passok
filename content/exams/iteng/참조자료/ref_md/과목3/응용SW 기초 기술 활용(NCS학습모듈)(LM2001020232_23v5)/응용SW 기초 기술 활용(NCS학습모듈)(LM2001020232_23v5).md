(cid:49684) 네트워크 계층 구조
어느 컴퓨터에서 보낸 메시지(신호)가 목적지까지 전달되기 위해서는 다른 네트워크 환경
과 다양한 네트워크 장비를 거치게 된다. 이때 컴퓨터 및 네트워크 장비는 네트워크 계층
구조에 따른 역할을 수행하게 된다.
1. 프토토콜(protocol)
(1) 프로토콜의 개념
프로토콜이란 원래 외교 용어로서 국가와 국가 간의 교류를 원활하게 하기 위해 외
교에 관한 의례나 국가 간의 약속을 정한 의정서이다. 네트워크 프로토콜은 통신을
통제하는 규칙들을 모아 놓은 것으로, 무엇을 통신할 것이며, 어떻게 그리고 언제
통신할지를 정의한다. 통신 프로토콜의 주요 요소는 구문, 의미 그리고 타이밍이다.
(가) 구문(syntax)
구문은 데이터 구조나 형식을 의미하는 것으로 발신지에서 데이터를 생성하는
규칙이다. 클라이언트나 서버 간에 주고받는 데이터를 이해하기 위해서는 반드시
그 구조나 형식이 사전에 정해져야 한다.
(나) 의미(semantics)
주고받는 데이터 내에 영역(바이트)별로 갖는 의미가 있다. 송신기는 정해진 구
문에서 부분별로 값을 넣고, 수신기는 그 의미를 해석하여 동작한다. 구문은
전체적인 구조를 의미한다면, 의미는 구조 안에서 차지하는 각 부분의 의미를
말한다.
(다) 타이밍(timing)
타이밍은 언제 데이터를 전송해야 할 것인가와 얼마나 빨리 전송할 것인가의
두 가지 특성을 말한다. 온라인에서 물건을 택배 주문하면 언제, 얼마나 빨리 오
는지 매번 상황이 다르다. 데이터 통신에서 데이터를 주고받는 것은 송수신기 간
에 타이밍을 정하지 않으면 대부분의 데이터는 유실될 것이다.
(2) 프로토콜의 기능
프토코콜은 구문, 의미, 타이밍을 위해 다중화, 주소 설정, 메시지 단편화 및 재조
립, 캡슐화, 순서제어, 오류제어, 흐름제어 등을 정한다. 이를 위해 다양한 프로토콜
이 존재하며 프로토콜마다 그 역할이 다르다.
<표 1-1> 프로토콜의 기능
기능 특징
- 하나의 통신선로를 여러 시스템이 동시에 이용할 수 있는 기법
- 다중화가 가능하기 위해서는 정해진 방법으로 데이터의 크기를 나누거나 형
다중화
태를 변환해야 한다.
- 다중화를 위해 단편화 및 재조립, 순서제어가 필요해졌다.
주소 - 특정 송신지와 목적지를 주소로 표현한다.
설정 - 사용되는 주소 개념으로 포트 번호, IP 주소, MAC 주소 등이 있다.
- 데이터가 원하는 목적지에 제대로 도착하기 위해 여러 가지 정보를 추가하
는 작업을 말한다.
캡슐화 - 데이터 앞에 포함되는 부가 정보를 헤더(Header)라고 한다.
- 출발지에서는 캡슐화(Encapsulation)가 진행이 되고, 목적지에서는 역캡슐
화(De-encapsulation)가 진행이 된다.
- 단편화(fragmentation)는 다중화가 가능하기 위해 데이터를 미리 정한 크
단편화/ 기 단위(세그먼트)로 나누는 작업을 말한다
재조립 - 재조립은 단편화된 메시지를 순서대로 조립하는 과정을 말한다.
- 단편화는 송신지, 재조립은 수신지에서 주로 일어난다.
- 단편화된 메시지를 보내기 전에 헤더에 순서를 기입한다.
순서제어 - 목적지에서 받은 데이터들을 원래 순서대로 정렬하거나, 손실된 데이터를
발견하기도 한다.
- 오류제어(Error Control)는 주고받는 데이터에 오류가 있음을 발견하여, 그
오류를 어떻게 대처할 것인가를 정의한다.
오류제어
- 대체로 오류가 있는 데이터 이후의 데이터들을 재전송 요청하여 다시 받음
으로써 오류를 해결한다.
- 흐름제어(Flow Control)는 송수신지 간에 속도를 조절하는 것을 말한다.
흐름제어 - 흐름제어는 대부분 수신자 측의 요구에 의해 송신자가 데이터의 전송 속도
를 조절하는 것이다.

[그림 1-3] 패킷의 헤더 구조
[그림 1-3]의 패킷은 최초 출발지에서 최종 목적지까지 데이터를 전달하기 위해 사
용된다. 패킷에서 사용되는 주소는 IP 주소이며, 출발지 및 목적지의 고유한 네트워
크 주소이다. 따라서 데이터 송수신 과정에 있는 네트워크 장비 중 라우터(Router)
는 수신된 패킷의 목적지 IP 주소를 보고 다음 라우터로 패킷을 전달하게 된다. 라
우터가 패킷의 경로를 결정하는 과정을 라우팅(Routing)이라고 하며, 라우터들의 라
우팅을 통해 패킷은 목적지까지 전달된다. 패킷의 주요 헤더 정보는 다음과 같다.
(1) TTL(Time To Live): 패킷의 수명으로 라우터를 거칠 때마다 –1 되며, TTL이 0인
패킷을 받은 라우터는 패킷을 삭제(Drop)하게 된다.
(2) Protocol: Data에 대한 정보(1.ICMP 6.TCP 17.UDP 등)
(3) Source/Destination IP Address: 출발지 또는 목적지의 IP주소
(라) 네트워크 접근 계층(데이터링크 계층)
네트워크 접근 계층은 컴퓨터나 장비와 연결된 물리적인 속성이 유선(UTP, 동축케
이블, 광케이블 등) 또는 무선(WI-FI 등) 상황에 구애받지 않고 패킷을 온전히 목적
지까지 전달해 주는 역할을 한다. 가장 흔히 LAN을 유선으로 연결하는 방법으로
UTP-8로 연결된 네트워크를 이더넷(Ethernet, IEEE 802.3)이라고 부른다. 이더넷
에서는 프래임(Frame)이라는 데이터 단위 속에 패킷을 넣는다.

(3) 동적 라우팅(Dynamic Routing)
동적 라우팅은 인접한 라우터들끼리 자신들의 라우팅 테이블을 공유하면서 자신의

종류 특징
RIP • 내부 게이트웨이 라우팅 프로토콜의 종류이며, 거리 벡터 라

OSPF • 내부 게이트웨이 라우팅 프로토콜이며, 링크 상태 라우팅 프
(Open Shortest Path 로토콜로서 링크 속도 등을 활용하여 최적의 경로를 계산
First) • RIP보다 대규모 네트워크에 적합

(가) RIPv2(Routing Information Protocol version 2)
RIP에서는 패킷이 출발지에서 목적지까지 도착하기 위해 거쳐 가는 라우터를 홉
(hop)이라 부르고, 홉 수(hop count)는 거쳐 가는 홉의 개수를 의미한다. RIP

(가) 웹 브라우저에서 웹 서버로 데이터 조회 요청(Request) 처리를 확인한다.

웹 서버는 HttpRequest를 웹 컨테이너로 전달한다.
(다) 웹 컨테이너가 스레드(Thread)를 생성하여 데이터베이스와 커넥션을 맺고 데이터를
조회하는 서블릿(Servlet)을 실행하는 과정을 확인한다. 이때 컨테이너에 서블릿이
생성되지 않은 경우 서블릿을 먼저 생성 및 초기화하고 실행하는 것을 확인한다.
웹 컨테이너는 효율적으로 자원을 관리하기 위하여 서블릿을 컨테이너당 한 개
만 생성하여 관리하며 스레드를 스레드 풀(Thread Pool)을 이용해 적정량만 생
성하여 관리한다. 웹 서버에서 전달받은 HttpRequest 객체는 서블릿이 이해할
수 있도록 HttpServletRequest로 변환하고 HttpServletResponse를 생성하여
서블릿에 전달한다.
(라) 서블릿이 데이터베이스를 조회하고 결과를 컨테이너에 전달하는 처리를 확인한다.
서블릿은 HttpServletRequest의 요청 내용을 이용하여 데이터베이스를 조회하
고, 조회 결과는 HttpServletResponse에 담아서 웹 컨테이너에 전송한다.
(마) 웹 컨테이너가 처리 결과를 웹 서버에 전송하는 과정을 확인한다.
웹 컨테이너는 HttpServletResponse를 HttpResponse로 변환하여 웹 서버에
전송한다.
(바) 웹 서버가 웹 브라우저로 처리 결과를 전달하는 과정을 확인한다.
웹 서버는 HttpResponse를 웹 브라우저로 전달한다.

(cid:49685) Scouter
1. Scouter 개념
Scouter는 오픈소스 소프트웨어로 공개된 애플리케이션 성능 관리(APM: Application
Performance Management) 도구로, 주로 Java 기반 웹 애플리케이션의 성능 모니터
링에 사용된다. Naver에서 개발되었으며, 현재는 오픈소스로 공개되어 다양한 기업과
개발자들이 사용하고 있다.
(1) Scouter 주요 기능
- 실시간 서버 모니터링 (CPU, 메모리, 트랜잭션 상태)
- SQL 쿼리 분석 (Slow Query 탐지)
- 트랜잭션 추적 (요청당 응답 시간 및 병목 구간 확인)
- 웹 애플리케이션 성능 모니터링 (Spring Boot, Tomcat 등 지원)
- 가벼운 설치 및 빠른 설정 가능 (Docker/Kubernetes 지원)
2. Scouter 구성
Scouter는 Agent, Collector(Server), Viewer로 구성된다.
<표 2-11> Scouter 구성 요소
구분 설명
- 서버에 설치

- Scouter의 서버 역할을 수행
- Agent로부터 수집한 데이터를 받아 저장

- 사용자에게 실시간 모니터링 데이터를 시각화하여 제공
Viewer

(cid:49685) 트랜잭션(Transaction)
1. 트랜잭션의 개념
트랜잭션이란 데이터베이스 관리시스템에서 저장된 데이터의 상태를 바꾸기 위해 수행하
는 작업의 논리적인 단위이다. 논리적인 단위의 의미는 여러 개의 작업을 하나로 묶어서
‘전부 성공시키거나, 하나라도 실패하면 전부 실패시키는’ 것을 의미한다. 이를 ‘All or
Nothing’ 원칙이라고 한다.
2. 트랜잭션의 특징
트랜잭션의 원칙을 준수하기 위해서는 <표 3-5>와 같이 ACID가 준수되어야 한다.
<표 3-5> 트랜잭션의 ACID 특징
특징 설명
Atomicity(원자성) - 데이터베이스에 트랜잭션은 모두 반영되거나 전혀 반영되지 않아야 함
- 트랜잭션이 성공적으로 완료되면, 데이터베이스는 항상 일관된 상태를
Consistency(일관성)
유지해야 함
- 하나의 트랜잭션이 실행 중일 때는 다른 트랜잭션이 끼어들어 영향을
Isolation(고립성)
줄 수 없으며, 각 트랜잭션은 독립적으로 실행되는 것처럼 보여야 함
- 성공적으로 완료된 트랜잭션의 결과는 시스템에 문제가 생겨도 영구적
Durability(지속성)
으로 저장되어야 함
트랜잭션과 ACID 원칙은 여러 사용자가 동시에 접근하는 데이터베이스 환경에서 데이터
가 항상 정확하고 신뢰할 수 있도록 만드는 핵심적인 개념이다.
3. 트랜잭션의 고립화 수준(Transaction Isolation Level)
트랜잭션을 동시에 처리되는 과정에서 트랜잭션 간에 Read, Write에 대해 허용하는
수준을 SQL 표준에서 네 가지로 정의한다. 데이터베이스 관리시스템들은 이러한 수준
을 제어할 수 있는 기능을 제공한다.
<표 3-6> 트랜잭션 고립화 수준
Isolation Level 설명
- 가장 낮은 수준의 고립 단계
- 다른 트랜잭션이 커밋 하지 않은 데이터도 읽는 것을 허용
Read Uncommitted
- 발생 가능한 문제: 더티 리드, 반복 불가능한 읽기, 유령 읽기
- 정합성에 문제가 많아 거의 사용되지 않음
- 대부분의 상용 DBMS가 기본으로 채택하는 수준
(e.g., Oracle, PostgreSQL)
Read Committed - 커밋이 완료된 데이터만 읽는 것을 허용
- 해결되는 문제: 더티 리드
- 여전히 발생하는 문제: 반복 불가능한 읽기, 유령 읽기
- MySQL의 InnoDB 스토리지 엔진이 기본으로 채택하는 수준
- 트랜잭션이 시작되기 전에 커밋 된 내용만 조회할 수 있으며, 트랜잭션
Repeatable Read 내에서 한 번 읽은 데이터는 다른 트랜잭션이 수정 불가
- 해결되는 문제: 더티 리드, 반복 불가능한 읽기
- 여전히 발생하는 문제: 유령 읽기
- 가장 엄격한 최고 수준의 고립 단계
- 트랜잭션을 순서대로 하나씩 실행하는 것처럼 동작하여, 동시에 여러
Serializable 트랜잭션이 같은 데이터에 접근 불가
- 해결되는 문제: 더티 리드, 반복 불가능한 읽기, 유령 읽기
- 데이터 일관성은 완벽하지만, 동시 처리 성능 저하로 사용되지 않음

DB 관리자(DBA)가 사용하는 명령어이지만, 개발자가 개발 환경에서 필요한 권한을 부
여받으면 필요한 DB 설정이나 응용프로그램과의 연동을 위해서도 권한을 부여할 필요
가 있다.
(1) 주요 DCL 명령어
- GRANT: 권한 부여
- REVOKE: 권한 회수
(2) DCL 사용 예
권한 부여 dev_user에게 MEMBER 테이블 조회 및 데이터 추가 권한 부여
GRANT GRANT SELECT, INSERT ON MEMBER TO dev_user;
권한 회수
REVOKE INSERT ON MEMBER FROM dev_user;
REVOKE

(cid:49684) SQL(Structured Query Language) 개요
1. SQL 개념
SQL은 데이터베이스를 조작하기 위한 구조화된 질의어로 사용자가 처리 결과를 얻기
위한 질의어를 데이터베이스 관리시스템에 전달하면, 데이터베이스 관리시스템이 최적
화 과정을 통해 처리 절차 및 방법을 수립하여 처리한다. 즉, 사용자가 처리 과정을 직
접적으로 고려할 필요 없는 비절차적 언어이다.
2. SQL 표준
SQL은 ANSI(American National Standard Institute)와 ISO/IEC(International
Standard Organization/International Electrotechnical Commission)에서 공동으
로 표준화하여 대부분의 데이터베이스 관리시스템은 표준 SQL을 지원한다. 하지만 데
이터베이스 관리시스템 솔루션들은 표준 SQL과 호환되지 않는 내장 함수 등을 제공하
기 때문에 각 솔루션 고유의 SQL 문법을 고려하여 응용소프트웨어를 개발해야 한다.

SQL 표준에서는 SQL 구문을 DDL(Data Definition Language, 데이터 정의어), DML
(Data Manipulation Language, 데이터 조작어), DCL(Data Control Language, 데이
터 제어어)의 세 가지 유형으로 정의하고 있다.
1. DDL(Data Definition Language, 데이터 정의어)
데이터를 정의하는 언어로 데이터베이스 스키마 구조를 변경하는 목적으로 데이터베이
스 관리자나 설계자가 주로 사용한다.
<표 3-21> DDL(Data Definition Language) 종류
종류 설명
CREATE Database, Table, View, Index 등 생성
ALTER Table의 속성(Attribute), 도메인(Domain), 제약조건(Constraint) 등 변경
DROP Database, Table, View, Index 등 삭제
TRUNCATE Table의 모든 행 삭제
출처: 교육부(2021). 응용SW 기초 기술 활용(LM2001020232_19v4). 한국직업능력연구원. p.84.
2. DML(Data Manipulation Language, 데이터 조작어)
데이터를 조작하는 언어로 데이터를 조회하거나 입력, 수정, 삭제하기 위한 목적으로
데이터베이스 관리자나 응용소프트웨어 개발자가 주로 사용한다.
<표 3-22> DML(Data Manipulation Language) 종류
종류 설명
SELECT Table, View의 특정 조건 데이터 조회
INSERT Table에 특정 조건의 데이터 입력
UPDATE Table의 특정 조건 데이터 수정
MERGE Table에 특정 조건에 따라 데이터를 입력(INSERT)하거나 수정(UPDATE)
DELETE Table의 특정 조건의 데이터 삭제
출처: 교육부(2021). 응용SW 기초 기술 활용(LM2001020232_19v4). 한국직업능력연구원. p.84.
3. DCL(Data Control Language, 데이터 제어어)
데이터를 제어하는 언어로 데이터베이스 접근을 위한 권한을 부여하거나 회수하는 목적
으로 데이터베이스 관리자가 주로 사용한다.
<표 3-23> DCL(Data Control Language) 종류
종류 설명
GRANT 특정 사용자에게 특정 객체에 대한 특정 작업 수행 권한 부여
REVOKE 특정 사용자에게 부여된 권한 회수

• 작성된 E-R 다이어그램을 E-R 다이어그램 도구를 이용하여 테이블 정의서와 DDL 쿼
리로 자동 변경하는 실습을 하여 능숙한 도구 활용의 효율성을 체험할 수 있도록 지도
한다.
• SQL 표준에 대해 설명하고 다양한 DBMS 솔루션들의 SQL 표준 호환성을 이해하고 실
습할 수 있도록 지도한다.
• DDL과 DML의 차이를 설명하고 학습자 스스로 SQL 구문을 작성할 수 있도록 SQL의
기본 구조를 설명한다.
학습 방법
• 데이터베이스 특성에 대해 정확히 파악하고 이를 토대로 데이터베이스 특징을 정리한다.
• 데이터 모델링을 사전에 학습하고 데이터 모델링의 산출물인 E-R 다이어그램을 파악한다.
• E-R 다이어그램 도구를 이용해 테이블 정의서 작성 및 DDL 쿼리를 자동으로 변환시키
는 과정을 실습한다.
• SQL 표준에 대해 학습하여 다양한 DBMS 솔루션들의 SQL 표준 호환성을 이해하고 솔
루션 고유의 SQL 구문이 필요한 경우에는 추가로 조사하여 실습에 활용한다.
• DDL과 DML의 차이를 파악하고 SQL의 기본 구조를 이해하여 스스로 다양한 SQL 구
문을 작성한다.
