1. 데이블의 생성
테이블의 생성에는 일정한 형식이 사용된다. 따라서 테이블의 생성에서는 테이블에 입력
될 데이터를 정의하고 유형을 선언한다.
(1) 데이터 형식(Data Type)
테이블에 자료가 입력될 때 필요한 공간과 형식을 규정하는 기준이다. 즉 칼럼을 정의
하며 규정된 데이터 형식은 이후 해당 칼럼에 입력되는 데이터의 종류와 크기를 제한
하며, 그 외 종류의 데이터나 큰 데이터가 입력되면 에러가 나타난다.
데이터의 유형은 크게 숫자형, 문자형, 날짜 등의 유형으로 나눌 수 있으며, 구체적인
형식은 NUMBERRIC, CHARACTER, VARCHAR, DATETIME 등이 있으나, 실제 사용하
는 SQL 문에 따라 사용되는 표현은 조금씩 달라질 수 있다.

(2) 테이블 생성(CREATE TABLE)의 주의 사항
(가) 테이블의 데이터 식별과 테이블간 관계 설정
1) 테이블의 데이터는 유니크한 식별이 가능해야 함.
2) 유니크한 데이터가 입력되는 단일 칼럼 또는 복수 칼럼의 조합으로 기본 키
(PRIMARY KEY)를 설정해야함.
3) 테이블 간의 관계는 칼럼에 대한 기본 키(PRIMARY KEY)와 외래 키(FOREIGN KEY)
의 설정을 통해 구성함.
(나) 테이블/ 칼럼명 작성시 주의 사항
1) 테이블명은 객체를 나타낼 수 있는 이름을 사용함
2) 테이블명은 사용자의 다른 테이블명과 중복되지 않아야함
3) 테이블 내 칼럼명은 중복되지 않아야함
4) 테이블 및 칼럼명은 문자로 시작해야함
5) 밴더별 예약어(reserved word)는 테이블 및 칼럼명으로 적절하지 않음
(다) 기타 주의 사항
1) DATETIME 데이터 유형의 크기는 별도로 지정하지 않음
2) 문자 데이터 유형의 경우 입력 데이터를 고려하여 최대 길이를 표시해야함.
3) 칼럼 간 구분은 ‘,’로 하지만 단일 칼럼이나 마지막 칼럼의 경우 표시하지 않
음
4) 테이블명을 지정하고 각 칼럼은 괄호 ‘( )’를 사용 묶어 지정함.
5) 칼럼의 제약 조건은 CONSTRAINT를 이용하여 추가할 수 있음.

2. 제약 조건(CONSTRAINT)의 생성
제약 조건은 칼럼별 입력 데이터를 사용자 요구에 맞게 유지하기 위한 방법이다. 테이블
생성 시 제약 조건을 선언할 수 있으나, 필수는 아니며 이후 ALTER TABLE을 이용하여
추가 및 수정할 수 있다. 그러나 칼럼별 데이터 입력 후 제약 조건 추가에는 부가적인 처
리과정이 필요하므로 테이블 생성 시 제약 조건을 선언하는 것이 효과적이다.
주요 제약 조건에는 UNIQUE KEY, PRIMARY KEY, FOREIGN KEY, NOT NULL, CHECK
등이 있다.

• 테이블과 제약 조건의 변경(ALTER TABLE)
테이블 구조는 생성 후 유지되는 것이 가장 좋으나, 시스템의 운영상의 사정 등으로 변경
될 수 있다.
1. 칼럼의 추가(ADD COLUMN)
추가되는 칼럼은 테이블에서 위치를 지정할 수 없으며 가장 마지막 위치에 추가된다.
ex: ALTER TABLE(테이블명) ADD(추가 칼럼명)(데이터 유형) ;
2. 칼럼의 삭제(DROP COLUMN)
ex: ALTER TABLE(테이블명) DROP COLUMN(삭제 대상 칼럼 명) ;
3. 칼럼의 변경(MODIFY COLUMN)
ex: ALTER TABLE(테이블명) MODIFY(( 칼럼명1)(데이터 유형)(DEFAULT 식)(NOT NULL),(
칼럼명2)(데이터 유형) …) ;
- Oracle의 경우 MODIFY 사용(ex: ALTER TABLE 대상 테이블 MODIFY( 대상 칼럼 데이
터 유형)(DEFAULT 식)(NOT NULL),(반복 가능: 복수 칼럼 변경 가능) ; )
- SQL Server의 경우(ex: ALTER TABLE 대상 테이블 ALTER( 대상 칼럼 데이터 유
형)(DEFAULT 식)(NOT NULL),(반복 가능: 복수 칼럼 변경 가능) ; )
(1) 칼럼 변경의 유의사항
- 기존 데이터 훼손 방지를 위해 칼럼 크기는 늘리기만 가능(NULL값이나 해당 설정이
없는 경우 줄이기 가능)
- NULL값만 가진 칼럼의 경우 데이터 유형 변경가능
- 칼럼의 DEFAULT값 변경시 이후 삽입에만 반영가능
- NOT NULL 제약 조건은 칼럼에 NULL값이 없을 경우에만 추가가능.
4. 칼럼 이름의 변경(RENAME COLUMN)
부득이하게 생성 시 부여된 칼럼의 이름을 변경해야할 경우 RENAME COLUMN을 활용할
수 있다.
- Oracle의 경우(ex: ALTER TABLE(테이블명) RENAME COLUMN(변경 대상 칼럼명) TO
(변경 칼럼명) ;)
- SQL Server의 경우(ex: sp_rename 'dbo.(테이블명).(변경 대상 칼럼명)', '(변경 칼럼명)',
'COLUMN' ;)
- 모든 데이터베이스가 RENAME 기능을 제공하지는 않음으로 사전에 확인 필요
5. 제약 조건의 변경
(1) 테이블 생성 시 제약 조건이 미적용된 경우 제약 조건 추가
- ALTER TABLE( 대상 테이블) ADD CONSTRAINT(제약 조견명)(제약 조건)((대상 칼럼)) ;
(2) 기존 제약 조건의 삭제
- ALTER TABLE( 대상 테이블) DROP CONSTRAINT(제약 조견명) ;
- 참조 무결성 옵션에 따라 외래 키의 설정을 통해 실수로 필요한 테이블과 데이터의
삭제를 방지할 수 있음
(3) 참조 관계 제약 조건 삭제
- Oracle의 경우 CASCADE CONSTRAINT 사용(DROP TABLE( 대상 테이블명) CASCADE
CONSTRAINT ;
- SQL Server의 경우 참조 제약 조건 또는 참조 테이블 먼저 삭제
6. 테이블의 삭제
(1) 테이블의 모든 데이터(행) 삭제(TRUNCATE TABLE )
TRUNCATE TABLE을 활용 테이블의 구조를 유지하며 모든 내용을 삭제할 수 있다.
- TRUNCATE TABLE( 대상 테이블명) ;
- 테이블의 구조는 유지되며 공간만 확보
- TRUNCATE TABLE의 경우 복원 불가능
(2) 테이블 삭제하기
참조 관계 테이블의 삭제 시 CASCADE CONSTRAINT 옵션을 통해 테이블 구조를 모두
삭제할 수 있다.
- DROP TABLE( 대상 테이블명) ;

필요 지식 /
• 트랜잭션(Transaction)
트랜잭션이란 작업의 기본 단위로 데이터 일관성을 보장하는 최소 단위다.
트랜잭션은 밀접히 관련되어 분리될 수 없는 한개 이상의 데이터베이스 조작을 가리키며,
하나의 트랜잭션에는 하나 이상의 SQL 문장이 포함된다. 트랜잭션은 분할할 수 없는 최소
단위이기 때문에 전부 적용하거나 전부 취소된다.
1. 트랜잭션의 특성과 대상
트랜잭션의 특성에는 원자성과 일관성, 고립성, 지속성 등이 있다.
<표 1-14> 트랜잭션의 특성

| 특성 | 설명 |
| --- | --- |

Ÿ 트랜잭션에서 정의된 연산의 경우 전체 실행 또는 전체 실행 안됨의
원자성(Atomicity)
경우만 가능하다.
Ÿ 실행 전 데이터베이스에 문제가 없다면, 실행 후 에도 문제가 없어야
일관성(Consistency)
한다.
고립성(Isolation) Ÿ 실행 중 타 트랜잭션에 영향으로 결과에 문제가 발생해서는 않된다.
Ÿ 성공적으로 수행되면 해당 트랜잭션으로 갱신한 데이터베이스의 내용
지속성(Durability)
은 지속적으로 저장된다.
- SQL 문 중 트랜잭션 대상은 데이터를 수정하는 DML문으로 INSERT, UPDATE, DELETE
등이 해당됨
- SELECT 문장은 직접적인 트랜잭션의 대상이 아니지만, SELECT FOR UPDATE 등 배타
적 Lock을요구하는 SELECT 문장은 트랜잭션의 대상이 될 수 있음.
2. 트랜잭션 제어문
트랜잭션의 제어문에는 COMMIT, ROLLBACK, SAVEPOINT 등이 있다.
- COMMIT: 변경 사항을 확정시키고 트랜잭션을 종료
- ROLLBACK: 변경 사항을 취소시키고 트랜잭션을 종료
- SAVEPOINT: 현재의 트랜잭션 중에서 ROLLBACK 시킬 위치를 지정
• 트랜잭션의 완료 및 취소
1. 트랜잭션의 완료(COMMIT)
COMMIT 명령은 올바르게 변경한 데이터를 데이터베이스에 반영한다.
툴에 따라(대다수) 자동기능(AUTO COMMIT)을 제공한다.
(1) Oracle에서 트랜잭션 완료
- ex: COMMIT ;
- 데이터의 입력, 수정, 삭제 등 작업 완료 후 COMMIT;을 실행하여 트랜잭션을 완료.
(2) SQL Server에서 트랜잭션 완료
- 기본적으로 AUTO COMMIT이 적용됨
- DML 문이 성공하면 AUTO COMMIT 작용
- 속성창 설정을 통해 트랜잭션의 완료(암시적 트랜잭션) 또는 시작 및 완료 모두(명시
적 트랜잭션) 사용자가 지정할 수 있음.
2. 변경사항의 취소(ROLLBACK)
변경사항의 취소(ROLLBACK) 명령은 변경한 데이터를 트랜잭션 시작 이전으로 되돌린다.
(1) Oracle에서 변경사항 취소
- ex: ROLLBACK ;
- COMMIT 실행 전 변경 이전 데이터로 취소하기 위해 변경사항의 취소(ROLLBACK)
를 실행.
(2) SQL Server에서 변경사항 취소
- 기본적으로 AUTO COMMIT이므로 DML 문이 실패하면 자동으로 변경사항의 취소
(ROLLBACK) 적용.
- 사용자가 임의로 변경사항의 취소(ROLLBACK)를 지정하기 위해서는 명시적 트랜잭
션으로 설정을 변경해야 함
3. 임의의 저장점 설정(SAVEPOINT)
임의의 저장점 설정(SAVEPOINT) 명령은 데이터 변경을 사전에 지정한 임의의 저장점
(SAVEPOINT)까지만 변경사항을 취소(ROLLBACK)하라는 의미이다.

- Primary key, Unique constraint 정의 시 자동으로 인덱스 생성.
- 테이블의 데이터를 갱신하면 자동으로 인덱스의 내용도 갱신.
- 인덱스가 많으면 검색시 유리하지만 갱신 시 성능 저하.
- 적당한 인덱스 생성이 중요
1. 인덱스 생성 기준
- WHERE 절(검색 조건), Join 에 자주 사용되는 칼럼
- 칼럼의값이 다양한 경우(남/여 등의 성별 구분 칼럼에는 생성하지 않는다)
- 둘 이상의 칼럼이 검색 조건이나 Join 에 자주 사용되는 경우
- 테이블이 크고 전체행의 10~15% 이내의 검색이 대부분인 경우
2. 인덱스를 생성하지 않는 경우
- 테이블이 작은 경우
- 대부분의 검색 결과가 전체행의 10~15% 이상인 경우
- 갱신이 자주 발생하는 테이블

(1) 인덱스 생성 및 삭제 등의 작업 결과 확인
- 인덱스명 및 Unique 여부 확인 뷰(ex: USER_INDEXES Dictionary)
- 인덱스 명, 테이블명, 칼럼명 확인 뷰(ex: USER_IND_COLUMNS)

• 뷰(View)
뷰는 테이블이나 다른 뷰에서 만들어진 논리적인 테이블이다.
뷰는 기존에 생성된 테이블 또는 다른 뷰에서 접근할 수 있는 전체 데이터 중에서 일부만
접근할 수 있도록 제한하기 위한 기법이다.
- 뷰를 통한 데이터 조회시 SQL 실행 순간 테이블의 상태 그대로 조회.
- 테이블은 디스크 공간이 할당, 데이터를 저장 하지만, 뷰는 data dictionary 에 뷰에 대한
정의만 저장 디스크 저장 공간이 할당되지 않음
- 사용자는 SQL 문을 사용 테이블에 저장된 데이터를 조회/조작하듯 뷰를 사용가능함.
1. 뷰의 장점과 특성
뷰의 장점을 요약하면 보안성, 편의성이라고할 수 있다.
- 뷰 사용시 데이터에 영향을 미치지 않으므로 주요한 데이터를 보호하기 위한 보안(Security)
목적 및 사용자에 편의성(Flexibility)을 제공하기 위한 목적을 달성할 수 있음.
- 데이터베이스 일부 부분만 선택적으로 보여 주므로 데이터베이스의 접근을 제한할 수
있음.
- 사용자는 복잡한 조회를 간단하게할 수 있음.
- 성능을 고려한 SQL 문을 뷰로 만들어 놓고 애플리케이션에서 사용할 수 있음.
- 사용자에게 데이터의 독립성을 제공할 수 있음.
- 복수 테이블의 자료를 Join 해서 조회 가능.
- 사용자는 필요한 자료만 조회 가능.
- 일반 테이블과 같이 SELECT 가능함.
- INSERT, UPDATE, DELETE는 약간의 제한이 있지만 가능함.
- 조인도 사용 가능함.
- 뷰를 정의한 기본 테이블의 데이터가 변경되면 뷰에 반영됨.
2. 뷰의 생성 및 삭제
(1) 뷰 생성 및 변경
- 해당 테이블의 칼럼의 속성을 상속하는 단순 뷰(Simple VIEW) 생성
- 함수나 표현식으로 정의되는 칼럼을 포함하는 뷰 생성
- SELECT 문장을 사용하여 조인, 그룹, Subquery 등을 포함하는 옵션을 사용하여 뷰
정의
- 복수의 테이블 측면에서 Complex 뷰 생성
- OR REPLACE 옵션을 사용하여 뷰 생성 없이 정의 변경
(2) 단순뷰와 복합뷰
(가) 단순뷰의 조건
- Join, 그룹 함수, GROUP BY, DISTINCT를 포함하면 DELETE 안됨
- 그룹 함수, GROUP BY, DISTINCT 표현식으로 정의된 칼럼을 포함하면 UPDATE
안됨
- 그룹 함수, GROUP BY, DISTINCT 표현식으로 정의된 칼럼 뷰에 의해 선택되지
않은 NOT NULL 칼럼이 기본 테이블에 있을 때 INSERT 안됨

• 집합연산자
집합 연산자는 여러 개의 질의의 결과를 연결하여 하나로 결합하여 나타낸다. 집합 연산자
는 2개 이상의 질의 결과를 하나의 결과로 만들어 준다. 일반적으로 집합 연산자를 사용하
는 상황은 서로 다른 테이블에서 유사한 형태의 결과를 반환하는 것을 하나의 결과로 합치
고자할 때와 동일 테이블에서 서로 다른 질의를 수행하여 결과를 합치고자할 때 사용할 수
있다. 이외에도 튜닝관점에서 실행계획을 분리하고자 하는 목적으로도 사용할 수 있다.

• 순위 함수
함수를 사용하여 그룹내 순위를 부여하는 함수로 RANK, DENSE_RANK, ROW_NUMBER
등이 있다.
1. RANK 함수
RANK 함수는 ORDER BY를 포함한 QUERY 문에서 특정 항목( 칼럼)에 대한 순위를 구하
는 함수이다. 이때 특정 범위(PARTITION) 내에서 순위를 구할 수도 있고 전체 데이터에
대한 순위를 구할 수도 있다. 또한 동일한값에 대해서는 동일한 순위를 부여하게 된다.
(1) RANK 함수의 사용
대상에 순위를 부여한다.
- ex: SELECT(조회 대상, RANK()) OVER(PARTITION BY(그룹기준1) ORDER BY(그룹기
준2))(RANK 칼럼) FROM( 대상 테이블) ;
(2) DENSE_RANK 함수의 사용
비교 대상과 동일값을 하나로 설정하여 순위를 부여한다.
- ex: SELECT(조회 대상, RANK( )) OVER(ORDER BY(그룹기준1)) RANK, DENSE_
RANK( ) OVER(ORDER BY(그룹기준2))(DENSE_RANK 칼럼) FROM(대상 테이블) ;
(3) ROW_NUMBER 함수의 사용
비교 대상과 동일값에 임의의 유니크값을 부여하여 순위를 부여한다..
- ex: SELECT(조회 대상, RANK())OVER(ORDER BY(그룹기준1)) RANK, ROW_NUMBER
( ) OVER(ORDER BY(그룹기준2))(ROW_NUMBER 칼럼) FROM(대상 테이블);
• 집계 함수
그룹내값들에 대한 집계를 구하는 함수로 대표적으로 SUM, MAX, MIN, AVG, COUNT 등
의 함수가 있다.
1. SUM 함수
파티션별 윈도의 합을 구할 수 있다.
- ex: SELECT(조회 대상, SUM((합계 대상)) OVER(PARTITION BY(대상 파티션))(합계 칼럼)
FROM(대상 테이블) ;
- OVER 절에 ORDER BY 절을 사용하여 정렬 후 누적 합계 산출(SQL Server 제외)
2. MAX 함수
파티션별 윈도의 최댓값을 구할 수 있다.
- ex: SELECT(조회 대상, MAX(최댓값 대상) OVER(PARTITION BY(대상 파티션)) as(최댓
값 칼럼) FROM(대상 테이블) ;
(1) INLINE VIEW 를 사용하여 최댓값을 가진 전체 데이터(행) 출력
- ex: SELECT(조회 대상 1) FROM(SELECT(조회 대상 2), MAX(최댓값 대상) OVER(PARTITION
BY(대상 파티션)) as(IV_MAX 칼럼) FROM(대상 테이블)) WHERE(최댓값 대상)
= (IV_MAX 칼럼) ;
3. MIN 함수
파티션별 윈도의 최솟값을 구할 수 있다.
- ex: SELECT(조회 대상, MIN(최솟값 대상)) OVER(PARTITION BY(대상 파티션) ORDER
BY(정렬기준)) as(최솟값 칼럼) FROM(대상 테이블) ;
4. AVG 함수
파티션별 윈도의 평균값을 구할 수 있다.
- ex: SELECT(조회 대상, ROUND(AVG((평균 대상))) OVER(PARTITION BY(대상 파티션)
ORDER BY(정렬기준) ROWS((대상 조건))) as(평균 칼럼) FROM(대상 테이블) ;
5. COUNT 함수
파티션별 윈도의 수를 구할 수 있다.
- ex: SELECT(조회 대상, COUNT((COUNT 대상)) OVER(ORDER BY(정렬기준) RANGE(범
위 조건)) as(COUNT 칼럼) FROM(대상 테이블) ;
• 행 순서 함수
1. FIRST_VALUE 함수
정렬한 대상에서 최초로 나온값을 추출한다.
- ex: SELECT(조회 대상, FIRST_VALUE((추출 대상)) OVER(PARTITION BY(대상 파티션)
ORDER BY(정렬기준) ASC ROWS(추출 범위)) as(추출 칼럼) FROM(대상 테이블);
2. LAST_VALUE 함수
정렬한 대상에서 가장 후에 나온값을 추출한다.
- ex: SELECT(조회 대상, LAST_VALUE((추출 대상)) OVER(PARTITION BY(대상 파티션)
ORDER BY(정렬기준) ROWS(추출 범위)) as(추출결과 칼럼) FROM(대상 테이블) ;
3. LAG 함수
지정된 순서(선행)의 데이터(행)를 추출한다.
(1) 정렬된 대상에 한행 앞선 데이터(행) 추출
- ex: SELECT(조회 대상, LAG((추출 대상)) OVER(ORDER BY(정렬 기준)) as(추출 칼
럼) FROM(대상 테이블) WHERE(대상 조건) ;
(2) 정렬된 대상에 지정 행 앞선 데이터(행)을 추출하되 추출값이 NULL인 경우 처리

DCL(Data Control Language)은 유저를 생성하고 권한을 제어할 수 있는 명령어다.
1. 유저와 권한
데이터의 공유나 데이터베이스에 대한 오픈이 필요할 경우 운영 시스템에서 사용하던 유
저를 오픈하면 데이터의 손실 우려가 커지므로 새로운 유저를 생성하고, 생성한 유저에게
공유할 테이블이나 기타 오브젝트에 대한 접근 권한만을 부여하는 방식으로 권한을 관리
하여 공유에 대한 우려를 줄일 수 있다.
(1) Oracle과 SQL Server의 사용자 권한
(가) Oracle의 사용자 권한
- 유저를 통해 데이터베이스에 접속을 하는 형태
- 아이디와 비밀 번호 방식으로 인스턴스에 접속 하고 해당하는 스키마에 오브젝
트 생성 등의 권한을 부여함.
(나) SQL Server의 사용자 권한
- 인스턴스에 접속하기 위해 로그인이라는 것을 생성
- 인스턴스 내에 존재하는 다수의 데이터베이스에 연결하여 작업하기 위해 유저를
생성한 후 로그인과 유저를 매핑해 주어야 함.
- 지정된 유저는 대상 데이터베이스 내의 특정 스키마에 대해 권한을 부여받을 수
있음.
- SQL Server 로그인 방식
1) Windows 인증 방식
- Windows에 로그인한 정보를 가지고 SQL Server에 접속하는 방식
- Microsoft Windows 사용자 계정을 통해 연결되면 SQL Server는 운영 체제
의 Windows 보안 주체 토큰을 사용하여 계정 이름과 암호가 유효한지 확
인함.
- Windows 인증은 기본 인증 모드이며 SQL Server 인증보다 훨씬 더 안전함.
- Windows 인증은 Kerberos 보안 프로토콜을 사용하고, 암호 정책을 적용하
여 강력한 암호에 대해 적합한 복잡성 수준을 유지하도록 하며, 계정 잠금
및 암호 만료를 지원함.
- SQL Server가 Windows에서 제공하는 자격 증명을 신뢰하므로 Windows 인
증을 사용한 연결을 트러스트된 연결이라고도 함.
2) 혼합 모드(Windows 인증 또는 SQL 인증) 방식
- 사용자 아이디와 비밀 번호로 SQL Server에 접속하는 방식
- SQL 인증을 사용할 때는 강력한 암호(숫자+문자+특수문자 등을 혼합하여
사용)를 사용해야함.

교수 방법
• 교수자는 학습자의 SQL 에 대한 이해 수준을 사전에 확인한다.
• 사용할 데이터베이스 및 SQL 문의 종류에 대해 파악하고 특성을 고려하여 교육해야한다.
• 작업 횟수 및 규모가 커질수록 절차형 SQL 의 활용 효용이 커진다는 사실을 인지시키며 교육해야
한다.
• 절차형 SQL은 실습시 테이블 및 데이터베이스 등에 영향을 미칠수 있으므로 사전에 사용가능한
데이터베이스의 구조를 확인 및 준비하고 교육해야한다.
• 교수자는 학습자가 각 SQL 명령문 간에 연계되어 활용할 수 있도록 교육해야한다.
• 교육상에 발생하는 실습 과정은 대부분 학습자가 사용하는 프로그램이나 학습자가 속한 조직
및 업무에 따라 조금씩 달라질 수 있다. 따라서 형식보다 각 명령의 내용과 의미, 역할 등을
중심으로 설명한다.
학습 방법
• 기본적인 SQL 언어에 대해 사전 학습을 통해 활용할 수 있어야 한다.
• 절차형 SQL의 개념 및 특성에 대해 이해하고, 규모가 작거나 단편적 실습에서 효용이 낮겠지만
사전에 숙지해야 한다.
• 일부 절차형 SQL은 테이블들 및 데이터에 직접적으로 영향을 미칠수 있음을 인지하고 주의하며
학습해야 한다.
• 발생할 수 있는 오류의 타입과 처리 방안에 대해 이해하고 대응할 수 있어야 한다.
• 학습자는 SQL 학습 효과를 높이기 위해 지속적인 복습과 연계 실습을 통해 실무능력을 향상시킬
수 있어야 한다.
