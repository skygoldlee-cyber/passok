필요 지식 /
① 데이터 전환의 정의
데이터 전환이란 新정보시스템(목적시스템 또는 To-Be 시스템)을 개발함에 있어서 舊정
보시스템(원천시스템 또는 As-Is 시스템)에 축적된 자료를 新정보시스템에서 운용 가능
하도록 변경, 저장하는 작업을 의미한다. 데이터 전환은 데이터 이행(Data Migration)
으로도 표현된다.
데이터 전환은 전환 담당자와 업무 담당자 간의 긴밀한 협조 체제하에 우선순위(타 팀
과 관련된 데이터 우선 이행 등) 등을 고려한 전환 상세 설계, 전환 및 검증 프로그램
개발과 통합 전환을 수행하고, 이행 단계에서는 이행 시간 최적화를 위한 업무 간 병렬
처리 및 전환 시나리오에 따른 일관된 통제 및 관리, 주기적으로 데이터 이행 테스트를
반복하는 등 통합된 체계적 접근이 필요하다.
② 데이터 전환 프로세스
데이터 전환은 원천시스템 데이터를 목적시스템으로 이관하는 프로세스이다. 데이터 전
환 프로세스는 일반적으로 원천시스템의 데이터 분석과 추출, 정제 및 변환, 목적시스템
으로의 데이터 적재 및 검증 단계로 이루어진다.
일반적으로 데이터 전환은 추출, 변환, 적재(ETL: Extraction, Transformation,
Load) 과정이라고 하며, 과거에는 소프트웨어 개발 또는 데이터베이스 쿼리(Query)를
이용하여 많이 이루어졌으나, 현재는 데이터양의 증가 및 전환 효율성 측면을 고려하여
데이터 전환 도구(ETL 도구)들이 광범위하게 사용되고 있다. 전환 작업의 난이도, 분량,
소요시간, 비용 등을 고려하여 데이터 전환 도구의 활용 여부를 결정하면 된다.
1. 추출(Extraction)
전환 대상이 되는 원천시스템의 데이터베이스 데이터를 SAM 파일(Sequential
Access Method File) 형태로 추출하는 과정이다.
2. 정제
추출된 데이터에서 정제(수정)가 필요한 부분을 정비하는 과정이다. 개발, 테스트 단
계 중 발견된 정제 요건은 사전에 정비함을 기본으로 한다. 사전에 정비할 수 없는
경우에는 정비 요건을 추출하고 전환 프로그램에 반영하여 정비 작업을 수행한다.
3. 변환(Transformation)
원천시스템에서 추출한 데이터 SAM 파일을 목적시스템 SAM 파일로 변환하는 과정이다.
원천시스템 DB와 목적시스템 DB 간 매핑정의에 의해 데이터의 변환 작업을 진행하고
원천시스템 코드와 목적시스템 코드 간 매핑정의에 의해 변환 작업을 수행한다.
4. 적재(Load)
목적시스템 SAM 파일을 목적시스템의 DB에 적재하는 과정이다.
5. 검증
추출, 변환, 적재 단계별로 데이터 전환 작업이 정상적으로 이루어졌는지 검증하는
단계이다. 추출, 변환, 적재 단계별로 검증 프로그램이 검증 자료를 생성하고, 단계
별로 생성된 자료를 통합하여 결과를 판정하는데, 별도로 전환 도구에서 수행한 프
로그램별 로그 기록을 확인한다.

① 원천시스템(As-Is) 환경 분석을 위한 자료 목록
환경 분석은 원천시스템을 구성하고 있는 서브시스템들의 상세한 운영 현황을 조사하여
목적시스템으로의 데이터 전환 시 활용하기 위한 기초 자료로 쓰인다. 환경 분석의 결
과는 원천시스템인 현 시스템의 목록서이다.
시스템 목록서에는 시스템명, 서브시스템명, 개요, 개발 방법, 운영 환경, 운영 개시일,
프로그램 본수, 환경 분석 시 발견된 주요 현안 등을 포함해야 한다. 원천시스템 환경
분석을 위한 대부분의 자료 목록은 다음 내용을 포함한다.
- 현행 시스템 상세 현황
- 응용시스템 HW 구성도
- 응용시스템 NW 구성도
- 응용시스템 모형도
- 응용시스템 운영 환경
- 장비 사양
- 원천시스템 데이터베이스 현황
- 원천시스템 데이터 용량 분석
② 목적시스템(To-Be) 환경 분석을 위한 자료 목록

환경 구성과 SW 구성도 등이 필요하며, 향후 데이터 전환 환경 구축 및 전환 계획서 작성
시 활용하게 된다. 목적시스템 환경 분석을 위한 대부분의 자료 목록은 다음 내용을 포함한다.
- 목적시스템 환경 구성
- SW 구성도

필요하다. 개발 시스템 환경 분석을 위한 대부분의 자료 목록은 다음 내용을 포함한다.
- 개발 환경 구성도
- 전환 작업용 서버 및 단말기
- 전환 도구
- 전환 작업 모니터링 및 부하 모니터링 도구

필요 지식 /
① 데이터 전환 흐름 설계
데이터 전환 흐름 설계(Logical Mapping)는 원천시스템의 데이터가 목적시스템의 데
이터로 전환되어 적재되는 과정을 흐름도로 설계하는 것이다. 일반적인 테이블 대 테이
블 이행은 단순히 코드 전환 과정만 설계하지만, 실제 목적시스템의 구축 목적은 단순
테이블 코드값의 변경 차원을 벗어나 업무 비즈니스의 변경 흐름까지 반영되어야 한다.
데이터 매핑 흐름도에는 목표 데이터를 기준으로 하여 소스 데이터의 추출, 전환 및 가
공, 적재의 흐름과 업무에 따른 비즈니스 흐름이 충분히 반영되어야 한다.
② 데이터 관계 설계[데이터(테이블, 컬럼, 코드) 매핑]
분석 단계에서 분석한 데이터를 기반으로 한 소스 데이터와 목표 데이터를 데이터 표준
에 맞게 정의(테이블, 컬럼, 코드, 파일 등)하고 해당 데이터들의 매핑(Data Mapping)
관계를 기술해야 한다. 데이터 관계 매핑의 정확성을 보장하기 위해서는 데이터 표준화
작업이 선행되어야 한다.
1. 신구 데이터 관계 매핑 작업 순서
(1) 소스 데이터 정의
소스 데이터는 원천시스템의 테이블, 플랫 파일, 스프레드시트 등과 같은 다양한
종류가 될 수 있으며, 해당 데이터가 목적 테이블과 1:1 또는 M:1, 1:M의 관
계를 가질 수 있다.
(2) 목적 테이블 데이터와의 관계 정의
데이터 전환에서 대부분의 데이터 관계는 1:1의 단순 이동(Move)으로 표현할
수도 있으나, 표준화 변경에 의한 코드 전환 및 데이터 변경, 파일 이행 등이 발
생할 수도 있다. 이러한 신구 데이터들의 관계를 데이터 이행 작업 이전에 명확
히 명시하여야 효율적인 데이터 전환이 될 수 있다.
2. 데이터 매핑 방법
데이터 전환에서는 목적시스템에 맞게 코드 데이터가 변경되며, 코드 전환을 표현할
때에는 사용 코드의 데이터 관리 지점을 표현해 주어야 한다. 코드 데이터의 전환
관리란 현행 시스템에서 사용하는 코드와 목적시스템에서 전환된 코드의 매핑 정보
이며, 코드 매핑 데이터는 데이터 표준화에 의해 관리된다. 코드 전환 데이터들은 데
이터 전환의 효율성을 위하여 별도의 테이블에서 관리해야 하며, 매핑 관계 기술 시
해당 관리 지점을 표현해 주어야 한다. 비정형 데이터의 경우 별도의 비정형 데이터
정보 관리 테이블을 구성하여 데이터를 전환해야 한다.

① 데이터 전환 검증
데이터 전환 검증은 전환 절차 중 원천시스템 데이터를 목적시스템 데이터로 생성하는
과정의 정상 수행 여부를 검증하는 과정을 말한다. 데이터 전환 검증은 검증 방법, 검
증 단계별로 분류할 수 있다.
1. 검증 방법에 따른 분류
(1) 로그 검증
전환 시 수행되는 추출․적재 로그를 작성하여 데이터 전환 정합성을 검증한다.
(2) 기본 항목 검증
로그 검증 외에 응용 파트의 별도 검증 요청 항목을 기준으로 검증 프로그램을
작성하여 파일 또는 DB 등을 이용하여 검증한다.
(3) 응용 프로그램 검증
응용 애플리케이션을 통한 데이터 전환 정합성을 검증한다.
(4) 응용 데이터 검증
사전에 정의된 업무 규칙을 통하여 데이터 전환의 정합성 검증을 수행한다.
(5) 값 검증
전환 후 숫자 항목의 합계 검증, 코드 데이터의 범위 검증, 속성(타입, 자릿수)
변경에 따른 값 검증을 수행한다.
2. 검증 단계에 따른 분류
