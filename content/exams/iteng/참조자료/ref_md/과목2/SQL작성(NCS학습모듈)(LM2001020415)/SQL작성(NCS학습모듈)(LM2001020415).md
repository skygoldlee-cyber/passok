① 데이터 사전(Data Dictionary)
1. 데이터 사전의 개념
데이터베이스에 포함된 객체와 사용자에 관한 모든 정보를 읽기 전용으로 제공하는
시스템 테이블 및 뷰들의 집합이다. SQL이 실행될 때마다 데이터 사전을 참조하여,
객체의 존재 여부와 사용자의 접근 권한 유무를 확인한다. 또한 데이터 사전은
DBMS에 의해 데이터베이스 구조 및 사용자 권한, 데이터 등의 변경 내역을 지속적
으로 갱신한다. 데이터베이스의 중요 정보를 담고 있는 만큼 임의로 입력, 변경, 삭
제할 수 없도록 뷰 형태로 제공되어 데이터 사전을 데이터 사전 뷰(Data
Dictionary View)라고도 한다. 다음은 오*의 DBMS 제품에서 제공하는 데이터 사
전의 구성을 나타내는 개념도이다.

![이미지](images/page014_img00.webp)

2. 데이터 사전의 특징
데이터 사전의 특징은 다음과 같다.
(1) 데이터베이스의 시스템 권한 스키마는 데이터 사전의 모든 기본 테이블과 뷰(View)를
소유한다.
(2) 데이터 정의어(DDL, Data Definition Language) 명령이 실행될 때마다 데이터 사
전을 Access 한다.
(3) 데이터베이스의 전반적인 정보를 데이터베이스 모든 사용자에게 제공한다.
(4) DBMS는 SQL 실행 전에 데이터 사전을 먼저 참조하여 객체 존재 여부 및 사용자에게
적합한 접근 권한이 허용되어 있는지 확인한다.
(5) 데이터 사전을 지속적으로 갱신함으로써 데이터베이스의 변경사항(구조, 감사, 사용자
권한, 데이터 등)을 반영한다.
3. 데이터 사전의 내용
데이터 사전에 저장되는 내용은 다음과 같다.
(1) 데이터베이스의 사용자 정보
(2) 데이터베이스의 권한과 롤 정보
(3) 데이터베이스 스키마 객체 정보
(4) 무결성 제약 조건에 관한 정보
(5) 데이터베이스의 물리적 구조와 객체의 논리적 구조
(6) 스키마 객체에 할당된 공간의 크기와 사용 중인 공간의 크기 정보
(7) 객체 접근 및 갱신에 대한 감사 정보
(8) 데이터베이스 이름, 버전, 생성 날짜, 시작 모드, 인스턴스 이름 정보
4. 데이터 사전 용도
사용자에게 데이터 사전은 단순 조회의 대상일 뿐이다. 하지만 데이터베이스에서
SQL 처리를 위한 Parser, Optimizer 등과 같은 구성 요소에서 데이터 사전은 작업
을 수행하는 데 반드시 필요한 참조 정보를 제공한다. SQL 수행 과정에서 데이터
사전의 위치와 역할은 다음과 같다.

② 데이터 사전의 유형
O*사의 DBMS와 M*사의 DBMS는 대표적인 상용 제품으로 제품별로 데이터 사전
을 제공하는 방식이나 유형에는 큰 차이가 있다.
1. 오**의 DBMS에서 제공하는 데이터 사전
(1) 정적 데이터 사전 뷰(Static Data Dictionary View)
데이터베이스에 저장된 정보를 보여주므로 데이터베이스가 DB구조 변경이나 복구
작업이 가능한 mount 단계 또는 전체 작업이 가능한 open 단계로 기동되어 있어야만
접근이 가능한 데이터 사전이다. 접근할 수 있는 범위에 따라‘USER_’, ‘ALL_’, ‘DBA_’의
영역으로 구분된다.

![이미지](images/page016_img01.webp)

출처: 집필진 제작(2021)
[그림 1-3] 데이터 사전의 종류
(가) ‘USER_’로 시작하는 데이터 사전은 특정 사용자가 소유하며, 그 사용자에게 종속된
객체에 대한 정보를 제공하는 데이터 사전이다.
<표 1-1> USER_ 데이터 사전의 주요 정보
데이터 사전 제공 정보
USER_CATALOG 사용자가 소유한 테이블, 뷰, 동의어, 시퀀스 등의 정보
USER_CONSTRAINTS 사용자가 소유한 테이블에 설정된 제약 조건의 정보
USER_INDEXS 인덱스의 이름 및 고유한 정보
USER_OBJECTS 현재 사용자가 소유한 객체에 대한 정보
USER_SOURCE 사용자가 생성한 프로시저, 함수, 패키지의 Source 내용
USER_TAB_COLUMNS 테이블, 뷰, 클러스트들의 칼럼 정보
USER_TAB_PRIVS 타 사용자에게 접근이 허용된 테이블 정보
USER_TABLES 사용자에게 종속된 전체 테이블 정보
USER_TAB_COMMENTS 사용자가 테이블의 설명 또는 주석 정보
USER_VIEWS 데이터베이스에 생성된 전체 뷰 정보
출처: 투씨에스지 블로그. https://tocsg.tistory.com/78에서 2021. 06. 03. 검색.
(나) ‘ALL_’로 시작하는 데이터 사전은 특정 사용자에게 권한이 있는 모든 객체 정보를
조회할 수 있는 데이터 사전이다. 다른 사용자가 생성한 객체라도 그 객체의 접
근 권한을 부여받은 경우 ‘ALL_’로 시작하는 데이터 사전으로 조회가 가능하다.
<표 1-2> ALL_ 데이터 사전의 주요 정보
데이터 사전 제공 정보
데이터베이스 내 정의된 모든 테이블, 뷰, 동의어, 시퀀스 등의
ALL_CATALOG
정보
ALL_CONSTRAINTS 사용자가 접근할 수 있는 CONSTRAINT 정보
ALL_INDEXS 테이블에 정의된 인덱스 정보
데이터베이스 내 생성된 모든 객체(테이블, 뷰, 동의어, 프로시
ALL_OBJECTS
저 등)의 정보
ALL_SOURCE 사용자가 생성한 프로시저, 함수, 패키지의 Source 정보
ALL_TAB_COLUMNS 테이블, 뷰, 클러스트들의 칼럼 정보
ALL_TAB_PRIVS 테이블에 허용된 권한 정보
ALL_TABLES 권한 있는 모든 테이블의 목록 정보
ALL_TAB_COMMENTS 권한 있는 테이블의 설명 또는 주석 정보
ALL_VIEWS 데이터베이스에 생성된 전체 뷰 정보
ALL_USERS 모든 사용자에 관한 정보
출처: 투씨에스지 블로그. https://tocsg.tistory.com/78에서 2021. 06. 03. 검색.
(다) ‘DBA_’로 시작하는 데이터 사전은 데이터베이스 관리자 권한을 가진 사용자만 조회할
수 있는 데이터 사전이다. 데이터베이스 내 모든 객체에 대한 정보에 접근할 수 있다.
<표 1-3> DBA_ 데이터 사전의 주요 정보
데이터 사전 제공 정보
데이터베이스 내 정의된 모든 테이블, 뷰, 동의어, 시퀀스 등
DBA_CATALOG
의 정보
DBA_CONSTRAINTS 데이터베이스에 정의된 모든 제약 조건에 대한 정보
DBA_INDEXS 데이터베이스에 정의된 모든 인덱스에 대한 칼럼 정보
데이터베이스 내 생성된 모든 객체(테이블, 뷰, 동의어, 프로
DBA_OBJECTS
시저 등)의 정보
DBA_SOURCE 사용자가 만든 프로시저, 함수, 패키지의 Source 내용
DBA_TAB_COLUMNS 테이블, 뷰, 클러스트들의 칼럼 정보
DBA_TAB_PRIVS 테이블에 주어진 권한에 대한 정보
DBA_TABLES 데이터베이스 내의 모든 테이블의 목록 정보
DBA_TAB_COMMENTS 데이터베이스 내의 모든 테이블의 설명 또는 주석 정보
DBA_VIEWS 현재 데이터베이스에 생성된 전체 뷰 정보

SELECT EMPNO, ENAME, SAL AS “현재 급여”, SAL*1.3 AS “30% 인상” FROM EMP;
2. 합성 연산자
칼럼과 문자의 연결이 필요한 경우, 합성(CONCATENATION) 연산자를 사용한다면
별도의 프로그램 없이 SQL 문장만으로도 필요한 출력 형태를 만들 수 있다. 합성
연산자의 특징은 다음과 같다.
(1) 2개의 수직 바(||)를 사용한다. (문자1 || 문자2)
(2) CONCAT(문자1, 문자2) 함수를 사용할 수 있다.
(3) 칼럼과 문자 또는 다른 칼럼의 연결에도 적용이 가능하다.
(4) 합성 연산 결과는 새로운 가상의 칼럼으로 생성된다.
다음은 EMP(사원) 테이블에서 ‘이승기 사원의 급여는 800달러입니다’와 같은 출력
형태를 작성한 예시이다.
SELECT ENAME||' '|| JOB ||'의 급여는 '|| SAL ||'달러입니다.' FROM EMP;

(가) SIMPLE_CASE_EXPRESSION
CASE 다음에 조건으로 사용되는 칼럼이나 표현식을 표시하고, 다음 WHEN
절에서 앞에서 정의한 칼럼이나 표현식과 같은지 판단하는 문장으로 동등(=)조
건만 사용하는 경우에 주로 사용한다. 다음은 부서가 속한 도시에 따라 구역
을 표현하는 예시이다.
SELECT DNAME, LOC,
CASE LOC
WHEN '서울' THEN 'EAST'
WHEN '부산' THEN 'CENTER'
WHEN ‘SAN FRANCISCO' THEN 'WEST’
ELSE 'ETC’
END as AREA
FROM DEPT;
(나) SEARCHED_CASE_EXPRESSION
CASE 다음에는 칼럼이나 표현식을 표시하지 않고, 다음 WHEN절에서 동등
(=)조건 및 여러 조건(>, >=, <, <=)을 이용한 조건절을 사용할 수 있기 때문
에 SIMPLE CASE EXPRESSION보다 다양한 조건을 적용할 수 있다. 다음은
사원의 급여 규모에 따라 급여 등급을 표현하는 예시이다.
SELECT ENAME 이름, SAL 급여,
CASE WHEN SAL >= 2500 THEN 'HIGH'
WHEN SAL >= 1300 THEN 'MID'
ELSE 'LOW'
END AS 급여 등급
FROM EMP;
3. 다중 행 함수
다수의 행을 인자(arguments)로 받아들여 한 개의 값으로 결과를 반환(return)하는
함수이며 대표적으로 집계 함수가 있다.
(1) 집계 함수(Aggregate Function)
여러 행들이 특정 칼럼으로 그룹핑된 경우, 그룹별로 하나의 결과를 반환한다.
집계 함수는 그룹에 대한 연산 정보를 제공하므로 주로 숫자 유형에 사용되고
있지만, MAX, MIN, COUNT 함수는 문자, 날짜 유형에도 적용이 가능하다.

SELECT절, HAVING절, ORDER BY절에서 사용 가능하고, 테이블 전체 집계를
구하기 위해서 GROUP BY절을 생략하고 집계 함수를 사용할 수 있다. 집계 함
수의 문법은 다음과 같다.
SELECT column, 집계 함수(column)
FROM table
[WHERE condition]
[GROUP BY group_by_expression]
[HAVING condition]
[ORDER BY column];
(2) GROUP BY와 HAVING절
GROUP BY절을 통해 선언된 칼럼이나 그룹핑 기준을 정한 후, SELECT절에 집
계 함수를 사용한다. 집계 함수의 통계 정보는 NULL값을 가진 행을 제외하고 수
행한다. GROUP BY절의 그룹핑 기준에 의해 계산된 집계 함수의 결과는
HAVING절을 통해 추출 조건을 표시할 수 있다. 집계 함수는 WHERE절에는 사
용할 수 없으며, GROUP BY절에 의한 소그룹별로 만들어진 집계 데이터 중,
HAVING절에서 제한 조건을 두어 조건을 만족하는 내용만 출력한다.
(가) GROUP BY절
GROUP BY절은 SQL문에서 FROM절과 WHERE절 뒤에 위치하며, 테이블
내의 행들을 소규모로 그룹화하여 합계, 평균, 최대, 최소 등을 계산할 수 있
다. HAVING절에 조건문을 사용할 수 있으며, ORDER BY절도 사용할 수 있
다. GROUP BY절에서는 별칭(ALIAS)명을 사용할 수 없다. 아래는 부서별 인
원수와 급여의 최소, 최대, 평균값을 구하는 예시이다.
SELECT DEPTNO 부서, COUNT(*)인원수,
MIN(SAL) 최소급여, MAX(SAL) 최대급여, ROUND(AVG(SAL)) 평균급여
FROM EMP
GROUP BY DEPTNO;
(나) HAVING절
HAVING절은 WHERE절과 유사하지만 GROUP BY절에 의해 만들어진 소그
룹을 대상으로 조건이 적용된다는 점에서 차이가 있다. HAVING절은
SELECT절에 명시되지 않은 칼럼이나 집계 함수가 아니더라도 GROUP BY
절의 기준 항목이나 GROUP BY절의 기준 항목의 집계 함수를 조건으로 표
시할 수 있다. 다음은 부서별 인원수가 4명 이상인 부서의 인원수와 급여의
최소, 최대, 평균값을 구하는 예시이다.
SELECT DEPTNO 부서, COUNT(*)인원수,
MIN(SAL) 최소급여, MAX(SAL) 최대급여, ROUND(AVG(SAL)) 평균급여
FROM EMP
GROUP BY DEPTNO
HAVING COUNT(*) >= 4;
④ 조인(JOIN) SQL 작성
1. 조인(JOIN)의 개념
분산된 여러 테이블로부터 특정 조건을 만족하는 데이터들을 조회하기 위해서는 테
이블 간에 논리적인 연관 관계를 통해 다양한 칼럼 및 데이터들을 조회할 수 있다.
이런 논리적인 관계를 성립시켜주는 것이 JOIN이다.
2. 조인(JOIN)의 유형
실제 업무에서 테이블 간의 JOIN에 자주 사용하는 유형은 다음과 같다.
<표 1-23> 조인 유형(세분류)
조인 유형 내용
두 테이블에 공통으로 존재하는 칼럼을 이용하여 테이블 간
내부 조인(INNER JOIN)
의 연관 관계를 제공하는 조인 방식(공통 칼럼 기반)
동등 조인(EQUI JOIN) 조인 대상 칼럼의 값이 같은 경우를 추출
비동등 조인(Non-EQUI JOIN) 조인 대상 칼럼의 값이 같지 않은 경우를 추출
두 테이블 간에 조인 없이 모든 데이터의 조합을 추출
교차 조인(CROSS JOIN)
카티전 조인(CARTESIAN JOIN)이라고도 함
조인 기준 테이블의 모든 열에 대해, 조인 참여 테이블과
외부 조인(OUTER JOIN) 조인 조건울 만족하면 값을 리턴하고, 그렇지 않으면 조인
참여 테이블의 열값을 NULL로 리턴하는 조인 방식
왼쪽 외부 조인 왼쪽 테이블의 모든 데이터와 오른쪽 테이블의 동일 데이터
(LEFT OUTER JOIN) 를 추출(불일치 시 오른쪽 테이블 값은 NULL)
오른쪽 외부 조인 오른쪽 테이블의 모든 데이터와 왼쪽 테이블의 동일 데이터
(RIGHT OUTER JOIN) 를 추출(불일치 시 왼쪽 테이블 값은 NULL)
완전 외부 조인 양쪽 테이블의 모든 데이터를 추출
(FULL OUTER JOIN) (불일치 시 오른쪽, 왼쪽 테이블 값은 모두 NULL)

(가) BETWEEN 연산자
숫자, 문자, 날짜 칼럼에 모두 사용 가능하며, 지정된 하한값과 상한값 범위 내의
레코드를 추출할 때 사용한다. BETWEEN은 비교 연산자인 >=, <=로 변경 가능하다.
다음은 급여가 1500 이상 2000 이하인 사원번호와 직위, 급여 칼럼의 레코드를

SELECT EMP_NO 사원번호, JOB 직위, SAL 급여
FROM EMP
WHERE SAL BETWEEN 1500 AND 2000 ;

(나) IN 연산자
비교 칼럼이 단일값이 아닌, 지정된 리스트에 포함된 값들과 일치하는 레
코드를 추출할 때 사용한다. IN은 논리 연산자인 OR를 이용하여 변경 가
능하다. 다음은 부서번호(DEPTNO)가 10, 20인 사원번호와 직위, 급여
칼럼의 레코드를 출력하는 예시이다.
1) IN 연산자 이용 사례
SELECT EMP_NO 사원번호, JOB 직위, SAL 급여
FROM EMP
WHERE DEPTNO IN (‘10’,‘20);
2) 논리 연산자 이용 사례
SELECT EMP_NO 사원번호, JOB 직위, SAL 급여
FROM EMP
WHERE DEPTNO = ‘10’ OR DEPTNO = ‘20’ ;
(다) LIKE 연산자
검색 기준의 철자가 불확실한 경우, 데이터 조회 시 와일드카드 검색에 사용
한다. 문자열에만 사용 가능하며 2개의 와일드카드 문자인 퍼센트(%)와 밑줄(
_ )이 사용된다.
<표 1-30> LIKE 연산자에 사용되는 와일드카드 종류
와일드카드 의미 예시
% 0개 이상의 문자열과 일치 ‘%A%’: A를 포함하는 문자열
_ 특정 위치의 1개의 문자와 일치 ‘_A%’: 두 번째 위치에 A가 들어가는 문자열
다음은 LIKE 연산자에 와일드카드를 적용한 예시이다.
1) 이름이 J로 시작되는 레코드 추출

FROM EMP
WHERE ENAME LIKE ‘이%’;

SELECT ENAME 사원이름, DEPTNO 부서번호, JOB 직위
FROM EMP
WHERE ENAME LIKE ‘_현%';
(라) IS NULL 연산자
NULL이란 아직 정의되지 않은 미지의 값, 또는 현재 알 수 없는 값을 의미한
다. 공백이나 0과는 다른 값이다. NULL값의 수치 연산 결과는 NULL이며,
특정 값보다 작거나 크다는 비교 표현을 할 수 없다. NULL값의 비교 연산은
IS NULL, IS NOT NULL이라는 SQL 연산자를 사용해야 정확한 결과를 얻
을 수 있다.(ANSI 기준)
1) NULL의 잘못된 사용 예제
SELECT ENAME 사원이름, DEPTNO 소속, JOB 직위, SAL 급여, COMM 보너스,
SAL+COMM 총급여
FROM EMP
WHERE COMM = NULL; -- NULL은 비교 연산이 불가하므로 출력 레코드는 없음
2) NULL의 잘못된 사용 예제
SELECT ENAME 사원이름, DEPTNO 소속, JOB 직위, SAL 급여, COMM 보너스,

(나) OR 연산자
2개 이상의 조건 중 하나만 만족해도 True가 되는 연산을 수행한다. 다음은

SELECT ENAME 사원이름, DEPTNO 부서번호, JOB 직위

WHERE SAL >= 2000
OR JOB= ‘차장’ ;

필요 지식 /
① 데이터 삽입 SQL(INSERT) 명령문의 작성
1. 삽입 SQL 명령문의 개념
삽입 SQL 명령문은 테이블에 새로운 레코드를 삽입하는 명령이다. 데이터 삽입 결
과로 하나의 레코드가 추가된다.
2. 삽입 SQL 명령문의 문법
테이블에 데이터를 입력할 때 입력할 대상 칼럼을 명시하거나 명시하지 않고, 정의
된 순서대로 전체 칼럼을 대상으로 입력할 수 있다. 데이터를 삽입하기 위한 명령문
은 다음과 같이 두 가지 형태의 문법을 제공한다.
<표 2-6> 삽입 SQL 명령문 유형
형태 INSERT 명령문
A INSERT INTO table명 (column1, column2, ..) VALUES (value1, value2, ...);
B INSERT INTO table명 VALUES (value1, value2, ...);
입력 대상 칼럼의 데이터 유형이 CHAR나 VARCHAR2 등 문자 유형일 경우, 작은따
옴표(‘ ’)로 입력할 값을 둘러싼다. 숫자일 경우는 작은따옴표를 붙이지 않아도 된다.
(1) 삽입 SQL 명령문의 예시1(A형태)
A형태는 테이블의 칼럼을 명시할 수 있는데, 이때 칼럼의 순서는 테이블의 칼럼
순서와 일치할 필요는 없으며, 정의하지 않은 칼럼에는 NULL값이 입력된다. 단
Primary Key나 Not NULL로 지정된 칼럼은 NULL이 허용되지 않는다. 다음은
부서 테이블(DEPT)에 새로운 레코드에 부서번호와 부서명을 입력하는 예시이다.
부서 테이블은 부서번호(DEPTNO), 부서명(DNAME), 위치(LOC) 칼럼순으로 구
성되어 있다. Primary Key는 부서번호이다.
INSERT INTO DEPT(DEPTNO, DNAME) VALUES (70, '전산팀') ;
Primary Key인 DEPTNO의 값은 반드시 입력해야 한다. 부서 지역(LOC)은 값
을 입력하지 않았으므로, NULL값이 입력된다.
(2) 삽입 SQL 명령문의 예시2(B형태)
B형태는 모든 칼럼에 데이터를 입력하는 경우로, COLUMN_LIST를 언급하지 않
아도 되지만, 칼럼의 순서대로 빠짐없이 데이터를 입력해야 한다. 다음은 부서 테
이블(DEPT)에 부서 전체 데이터를 입력하는 예시이다. 부서 테이블은 부서번호
(DEPTNO), 부서명(DNAME), 위치(LOC)의 칼럼순으로 구성되어 있다. 부서의
위치가 정해지지 않았다면, 위치(LOC) 칼럼에 명시적으로 NULL값을 지정하여
입력해야 한다.
INSERT INTO DEPT VALUES (70, '전산팀', NULL) ;
② 데이터 변경 SQL(UPDATE) 명령문의 작성
1. 변경 SQL 명령문의 개념
변경 SQL 명령문은 테이블에 하나 이상의 레코드를 대상으로, 특정 칼럼의 저장된
값을 변경하는 명령이다.
2. 변경 SQL 명령문의 문법
변경 SQL 명령문은 보통 WHERE절을 통해 어떤 조건이 만족할 경우에만 특정 칼
럼의 값을 수정하는 용도로 많이 사용된다. UPDATE 다음에 수정되어야 할 칼럼을
포함하는 테이블명을 입력하고, SET 다음에 수정할 대상 칼럼명과 해당 칼럼 수정
값으로 변경 SQL 명령문을 작성한다. WHERE절이 생략되는 경우 테이블 내 전체
데이터(레코드)가 수정된다.
UPDATE table명 SET column1 = value1, column2 = value2, ... [WHERE 절] ;
3. 변경 SQL 명령문의 예시
다음은 부서 테이블(DEPT)에서 부서번호가 70인 레코드에서 위치(LOC)를 ‘서울’로
변경하는 예시이다.
UPDATE DEPT SET LOC = ‘서울’ WHERE DEPTNO = 70 ;
③ 데이터 삭제 SQL(DELETE) 명령문의 작성
1. 삭제 SQL 명령문의 개념
삭제 SQL 명령문은 테이블에 하나 이상의 레코드를 대상으로, 삭제하는 명령이다.
2. 삭제 SQL 명령문의 문법
삭제 SQL 명령문은 보통 WHERE절을 통해 어떤 조건이 만족할 경우에만 특정 레
코드를 삭제하는 용도로 사용된다. DELETE FROM 다음에 삭제를 원하는 레코드가
저장되어 있는 테이블명을 입력하고 실행한다. WHERE절이 생략되는 경우, 테이블
내 전체 데이터(레코드)가 삭제된다.
DELETE FROM table명 [WHERE 절] ;
3. 삭제 SQL 명령문의 예시
다음은 부서 테이블(DEPT)에서 부서번호가 70인 레코드를 삭제하는 예시이다.
DELETE FROM DEPT WHERE DEPTNO = 70 ;

• 삽입 명령문 중 형태B의 경우 대상 칼럼을 지정하지 않는 편리한 부분이 있지만, 해당 테이블의
구조가 변경(칼럼 추가 또는 삭제) 시, 삽입 명령문은 더 이상 유효하지 않게 된다. 따라서 칼럼명을
명시적으로 지정하는 형태A로 작성하는 것을 권장한다.

위 E-R 다이어그램에서 부서 테이블은 사원 테이블과 소속 관계를 가지며, 또한
사원 테이블은 부서 테이블에 종속되는 구조를 가진다. 부서 테이블과 사원 테이
블을 생성하기 위해 다음과 같은 SQL문을 사용한다.
CREATE TABLE DEPT
(DEPTNO NUMBER(2) CONSTRAINT PK_DEPT PRIMARY KEY,
DNAME VARCHAR2(20) NOT NULL,
LOC VARCHAR2(13) ) ;
CREATE TABLE EMP
(EMPNO NUMBER(4) CONSTRAINT PK_EMP PRIMARY KEY,
ENAME VARCHAR2(10) NOT NULL,
JOB VARCHAR2(9),
MGR NUMBER(4),
HIREDATE DATE NOT NULL,
SAL NUMBER(7,2),
COMM NUMBER(7,2),
DEPTNO NUMBER(2) CONSTRAINT FK_DEPTNO REFERENCES DEPT);
데이터를 삽입, 변경, 삭제하기 위해 위 테이블 생성문에서 유의하여 확인해야 할
것은 칼럼 이름과 데이터 타입이다. 또한 생성문에 있는 제약 조건의 확인을 통
해 데이터 삽입이나 삭제 과정의 제약 조건을 확인할 수 있다. 여기서는 칼럼의
제약 조건인 NOT NULL과 사원 테이블에 설정된 외래 키(Foreign Key)에 대한
제약 조건이 존재한다.
② 데이터를 삽입한다.
1. 단일 레코드를 삽입한다.
삽입 명령문 유형 가운데 형태A로, 부서 테이블에 하나의 레코드를 추가하는 방법은
다음과 같다.
INSERT INTO DEPT(DEPTNO, DNAME) VALUES (10, '회계팀');
부서 테이블 생성 과정에서 부서 지역(LOC) 칼럼은 NULL 입력이 가능한 제약 조
건을 가지고 있기 때문에 데이터를 삽입할 때 해당 칼럼을 생략하고 INSERT문을
사용하였다. 또 다음과 같이 레코드를 추가해 보자.
INSERT INTO DEPT(DEPTNO, LOC) VALUES (10, '서울');
----------------------------------------------------------------
(결과) “cannot insert NULL” 오류 발생
이 경우, 부서 이름(DNAME) 칼럼이 생략되어 NULL값이 자동 입력되게 된다.
하지만, 부서 테이블 생성 과정에서 부서 이름(DNAME) 칼럼은 NOT NULL 제약
조건을 가지고 있기 때문에 NULL값을 입력할 수 없다는 오류가 발생한다.
이번에는 형태B로 하나의 레코드를 다음과 같이 추가해 보자.
INSERT INTO DEPT VALUES (10, '회계팀');
----------------------------------------------------------------
(결과) "not enough values" 오류 발생
이 경우, 테이블에 정의된 칼럼은 3개(DEPTNO, DNAME, LOC)인데, 입력값은
LOC 칼럼을 제외한 2개뿐이라 수행 중 오류가 발생한다. 하지만 테이블 생성
과정에서 LOC 칼럼에 Default값을 지정하면 오류가 발생하지 않는다. 현재 상
황에서 오류 없이 입력하기 위해서는 다음과 같이 3개의 값을 모두 지정해야
한다.
INSERT INTO DEPT VALUES (10, '회계팀', '서울');
2. 복수 레코드를 삽입한다.
INSERT 명령문으로 복수 개의 레코드를 삽입하는 명령문은 다음과 같다.
INSERT ALL -- 4건 삽입
INTO DEPT VALUES (10, '회계팀', '서울')
INTO DEPT VALUES (20, '마케팅팀', '인천')
INTO DEPT VALUES (30, '영업팀', '부산')
INTO DEPT VALUES (40, '상품정보팀', '대구')
SELECT * FROM DUAL;
하나의 SQL문으로 복수의 레코드를 삽입하려면 ‘INSERT ALL’ 명령어를 사용해야
하며, 각각의 레코드 정보를 ‘INTO 테이블명 VALUES’ 구문과 함께 연속해서 정의
하면 된다. 이번에는 사원 테이블에 복수 개의 레코드를 하나의 SQL문으로 다음과
같이 추가해 보자.
INSERT ALL -- 7건 삽입
INTO EMP VALUES (1001, '이승기', '사원', 1006, TO_DATE('2020-01-01'), 800, NULL,
20)
INTO EMP VALUES (1002, '최경주', '대리', 1004, TO_DATE('2021-03-01'), 1600, 300,
30)
INTO EMP VALUES (1003, '김광현', '대리', 1004, TO_DATE('2021-05-01'), 1250, 500,
30)
INTO EMP VALUES (1004, '양의지', '차장', 1007, TO_DATE('2021-05-01'), 2975, NULL,
20)
INTO EMP VALUES (1005, '이경규', '대리', 1004, TO_DATE('2021-05-01'), 1250, 1400,
30)
INTO EMP VALUES (1006, '이승엽', '차장', 1007, TO_DATE('2021-05-01'), 2850, NULL,
30)
INTO EMP VALUES (1007, '나대표', '사장', NULL, TO_DATE('2021-02-01'), 2450,
NULL, 10)
SELECT * FROM DUAL ;
다음으로 사원 테이블에 하나의 레코드를 아래와 같이 추가해보자.
INSERT INTO EMP VALUES
(1008, '이동국', '대리', 1004, to_date(‘2021-04-01’), 1500,100, 50);
(결과) integrity constraint (NCS.FK_DEPTNO) violated - parent key not found 오류발생
명령문은 형태B로 사원 테이블에 정상적으로 레코드가 추가될 것처럼 보이지만, 부
서번호에 해당하는 제일 마지막에 입력된 값은 부서 테이블에 부서번호가 50번인
레코드가 미리 존재해야 정상적으로 동작한다. 그 이유는 사원 테이블 생성 과정에
서 명시한 외래 키(Foreign Key)에 대한 제약 조건 때문이다.
3. 서브쿼리(Subquery)를 이용하여 데이터를 삽입한다.
하나의 메인쿼리(SQL)에 포함되어 있는 또 다른 SQL문을 서브쿼리라고 하며, 서브
쿼리는 메인쿼리와 종속적인 관계이다. 서브쿼리는 메인쿼리 내에 괄호로 묶여져 있
는 SQL문으로 쉽게 구분할 수 있다.
(1) 일련번호를 채번하는 서브쿼리 활용
사원 테이블의 사원번호는 새로운 레코드가 삽입될 때마다 순차적으로 1씩 증가
된다고 할 때, 다음과 같은 명령문을 통해 하나의 레코드를 추가해 보자.
INSERT INTO EMP
(EMPNO, ENAME , JOB , MGR , HIREDATE , SAL , COMM , DEPTNO )
VALUES
( (SELECT NVL(MAX(EMPNO), 0) + 1 FROM EMP), -- 채번하는 서브쿼리 부분
'유현주' , '부장' , 1006 , TO_DATE('2021-04-19'), 3000 , NULL , 20 );
사원번호의 최대값을 MAX 함수를 활용하여 읽은 후, 1을 증가시켜 새로운 레코
드의 사원번호로 사용한다. 데이터가 많을 때에 MAX 함수를 사용할 경우, 테이
블의 전체 데이터를 읽어야 하는 특성상 성능 저하가 발생할 수 있으므로 주의가
필요하다.
(2) 데이터를 복제하는 서브쿼리 활용
VALUES절 대신에 서브쿼리를 사용하여 한 건 또는 여러 건의 데이터를 삽입하
거나, 복제할 칼럼값들을 조회 후 파라미터로 전달된 값과 합쳐서 삽입할 때 사
용한다.
INSERT INTO EMP
(EMPNO, ENAME , JOB , MGR , HIREDATE , SAL , COMM , DEPTNO )
SELECT 1009 , ENAME , JOB , MGR , HIREDATE , SAL , COMM , DEPTNO
FROM EMP
WHERE EMPNO = 1001;
사원 테이블의 사원번호가 1001인 사원의 데이터를 조회한 후, 사원번호는 1009
로 매칭하여 레코드를 삽입한다. 특정 사원번호를 입력하지 않아도 된다면, 일련
번호를 채번하는 서브쿼리를 활용할 수 있다.
INSERT INTO EMP
(EMPNO, ENAME, JOB , MGR , HIREDATE , SAL , COMM , DEPTNO )
SELECT (SELECT NVL(MAX(EMPNO), 0) + 1 FROM EMP), ENAME, JOB, MGR,
HIREDATE, SAL, COMM, DEPTNO
FROM EMP
WHERE EMPNO = 1001;
③ 데이터를 조회하고 변경한다.
1. 데이터를 조회한다.
삽입한 데이터를 조회하기 위해 다음과 같은 명령문을 사용한다.
SELECT * FROM EMP;
사원 테이블의 모든 칼럼에 대해 아무런 조건 없이 검색하는 기본적인 조회 명령문
이다. 데이터가 많아서 일부 데이터만 조회하기 위해서는 조건절이 필요하다. 또 칼
럼 가운데 일부만을 보고 싶은 경우에는 와일드카드(*) 대신에 특정 칼럼을 명시한
다. 사원번호가 1004인 사원의 급여 테이블 정보를 보기 위해서는 다음과 같이 조
건을 명기한다.
SELECT * FROM EMP WHERE EMPNO = 1004;
사원번호 1004번 사원의 이름, 급여, 부서번호만을 보고 싶은 경우에는 다음과 같이
특정 칼럼만을 명기한다.
SELECT EMPNO 사원번호, ENAME 이름, SAL 급여, DEPTNO 부서번호
FROM EMP
WHERE EMPNO = 1004;
조건절에는 다양한 조건을 사용할 수 있으며, 이는 변경 명령문에서 특정 조건의 레
코드를 변경할 때도 사용할 수 있다. 다음에서는 가장 최근에 입사한 사원을 추출할
수 있다. 데이터 조회는 변경 대상을 사전에 확인해 보기 위해 수행한다.
SELECT * FROM EMP
WHERE HIREDATE = ( SELECT MAX(HIREDATE) FROM EMP);
2. 데이터를 변경한다.
데이터를 변경하려면, WHERE절에 사용될 특정 조건, 변경 대상 칼럼, 변경 대상
칼럼에 대입한 실제 변경값을 결정한다.
(1) 전체 레코드를 변경한다.
WHERE절을 통해 특정 조건의 지정 없이 테이블 내 전체 레코드를 대상으로 지
정된 칼럼의 값을 변경한다. 다음과 같이 사원 테이블에서 전체 사원의 급여
(SAL)를 일괄적으로 20% 인상하는 변경 명령문을 실행한다.
UPDATE EMP SET SAL = SAL * 1.2
(2) 특정 조건의 레코드를 변경한다.
WHERE절을 통해 특정 조건을 만족하는 레코드를 대상으로 지정된 칼럼의 값을
변경한다. 이때 Primary Key 칼럼이 조건으로 사용된 경우는 1개의 레코드가
변경되고, 그 외 칼럼이 조건으로 사용되는 경우는 1개 이상이 변경된다. 다음의
다양한 변경 명령문을 실행해 보고 결과를 확인한다.
(가) 사원번호가 1004인 사원의 급여를 20% 인상하는 명령문
UPDATE EMP SET SAL = SAL * 1.2 WHERE EMPNO = 1004;
(나) 직위가 ‘차장’인 사원들의 급여를 20% 인상하는 명령문
UPDATE EMP SET SAL = SAL * 1.2 WHERE JOB = ‘차장’;
(다) 부서번호가 20번인 사원의 부서번호를 30번으로 변경하는 명령문
UPDATE EMP SET DEPTNO = 30
WHERE DEPTNO = 20;
변경 작업 중 다른 테이블에서 데이터를 조회하여 변경을 해야 하는 경우가
있다. 조인을 사용하면 편리할 것 같지만 변경 명령문(UPDATE)에서 조인은
제약사항이 많기 때문에 서브쿼리를 활용하면 쉽게 해결되는 경우가 많다.
(라) 부서 지역이 ‘부산’인 부서에 소속된 사원들의 급여를 20% 인상하는 명령문
UPDATE EMP SET SAL = SAL * 1.2
WHERE DEPTNO = (SELECT DEPTNO FROM DEPT WHERE LOC ='부산');
(마) 직위가 '사원'인 사원이 소속된 부서의 지역을 ‘대전’으로 변경하는 명령문
UPDATE DEPT
SET LOC =’대전’
WHERE DEPTNO IN (SELECT DEPTNO
FROM EMP
WHERE JOB = '사원')
(3) SET절에 서브쿼리(Subquery)를 활용하여 레코드를 변경한다.
변경 대상의 값을 서브쿼리의 결과값으로 사용할 수 있다. 직위가 ‘부장’인 사원
의 급여를 같은 직위의 최고 급여로 변경하는 예시이다.
UPDATE EMP A
SET A.SAL = (SELECT MAX(B.SAL) FROM EMP B WHERE B.JOB = A.JOB)
WHERE A.JOB = ‘부장’
동일한 서브쿼리를 반복해서 사용해야 하는 경우 칼럼을 묶어서 한 번의 서브쿼
리로 업데이트 값을 입력할 수 있다. 다음은 ‘이승기' 사원의 직위와 급여를 '양
의지’ 차장의 직위와 급여로 동일하게 변경하는 예시이다.
UPDATE EMP
SET (JOB, SAL) = (SELECT JOB, SAL
FROM EMP
WHERE ENAME = '양의지‘)
WHERE ENAME = '이승기';
④ 데이터를 삭제한다.
데이터를 삭제하려면, 전체 레코드 삭제인지 특정 조건만 삭제하는 작업인지 먼저 파악
하고 삭제 명령어를 수행한다.
1. 전체 레코드를 삭제한다.
WHERE절을 통해 특정 조건의 지정 없이 테이블 내 전체 레코드를 대상으로 레코
드를 삭제한다. 다음과 같이 부서 테이블의 전체 레코드를 삭제하는 명령문을 실행
해 보자.
DELETE FROM DEPT;
-----------------------------------------------------------------------
(결과) integrity constraint (NCS.FK_DEPTNO) violated - child record found 오류발생
정상적으로 레코드가 삭제되어야 하지만 부서 테이블의 부서번호를 참조하는 사원
테이블의 데이터가 존재하고 있기 때문에 사원 테이블의 데이터를 삭제 후에 정상적
으로 동작한다. 그 이유는 사원 테이블 생성 과정에서 명시한 외래 키(Foreign
Key)에 대한 제약 조건 때문이다.
2. 특정 조건의 레코드를 변경한다.
WHERE절을 통해 특정 조건을 만족하는 레코드를 대상으로 레코드를 삭제한다. 이
때 Primary Key 칼럼이 조건으로 사용된 경우는 1개의 레코드가 삭제되고, 그 외
칼럼이 조건으로 사용되는 경우는 1개 이상이 삭제된다. 다음의 다양한 삭제 명령문
을 실행해 보고 결과를 확인해 보자.
(가) 사원번호가 1004인 사원을 삭제
DELETE FROM EMP WHERE EMPNO = 1004;
(나) 직위가 ‘차장’인 사원들을 삭제
DELETE FROM EMP WHERE JOB = ‘차장’;
(다) 부서번호가 20번인 사원 레코드들을 삭제
DELETE FROM EMP WHERE DEPTNO = 20;
삭제 명령어도 변경 명령어와 마찬가지로 다른 테이블에서 데이터를 조회하여 삭
제를 해야 하는 경우가 있다. 조인을 사용하면 편리할 것 같지만 삭제 명령문
(DELETE)에서 조인은 제약사항이 많기 때문에 서브 쿼리를 활용하면 쉽게 해결
되는 경우가 많다.
(라) 부서 지역이 '부산’인 부서에 소속된 사원 레코드들을 삭제
DELETE FROM EMP
WHERE DEPTNO = (SELECT DEPTNO FROM DEPT WHERE LOC ='부산');
수행 tip
• 서브쿼리(Subquery)는 변경 명령어의 SET절에 적용하
거나 조건절(WHERE절)에 조건값으로 활용할 수 있으
며 삽입 명령어에도 적용이 가능하다. 특히 변경 명령
어나 삭제 명령어는 다른 테이블의 조건을 조인으로
연계하기가 상당히 복잡하고 어렵다. 이때 서브쿼리를
활용하면 유용하게 처리 가능한 경우가 많다.
• 테이블이 부모-자식 관계의 외래 키 제약 조건(Restrict)
이 있는 경우, 삽입, 변경, 삭제 시 주의해야 한다. 수행
예시처럼 부서 테이블에 없는 부서번호를 신규 사원에
입력할 경우, 제약 조건에 위배가 된다. 유사하게 사원의
부서코드를 부서 테이블에 없는 값으로 변경을 시도할
경우에도 동일한 이유로 오류가 발생한다. 반대로 사원
테이블에서 참조하고 있는 부서번호를 부서 테이블에서
삭제할 경우, 제약 조건 위배로 오류가 발생한다.
• 삽입 명령문(INSERT) 중 형태B의 경우 대상 칼럼을 지정하지
않고 입력이 가능하지만, 해당 테이블의 칼럼이 추가 또는
삭제되어 구조가 변경되는 경우, 칼럼을 지정하지 않은
INSERT문은 더 이상 유효하지 않게 된다. 따라서 칼럼명을
명시적으로 지정하는 형태A로 작성하는 것을 권장한다.

1. 입력 SQL 명령문의 실행 결과 확인
입력 SQL 명령문 수행 시 테이블의 Primary key 칼럼에 입력한 값을 이용하여 조

작성한다. 조회 결과가 입력 SQL 명령문으로 입력한 레코드와 일치하면 성공적으로
실행된 것이다.
INSERT INTO table명 (Primary Key 칼럼명 , 입력칼럼명1 , 입력칼럼명2)
VALUES (value1, value2, value3);
(1)테이블의 전체 칼럼을 조회
SELECT * FROM table명 WHERE Primary Key 칼럼명 = value1;
(2)입력한 칼럼만 조회
SELECT 입력칼럼명1, 입력칼럼명2 FROM table명 WHERE Primary Key 칼럼명 = value1;
2. 변경 SQL 명령문의 실행 결과 확인
변경 SQL 명령문 수행 시 WHERE절에 명시했던 특정 조건을 동일하게 수정 대상
테이블에 데이터 조회 조건으로 적용한다. 조회된 데이터 중 변경 대상 칼럼의 값을
확인한다. 이때 전체 칼럼을 조회할 수도 있고, UPDATE SET로 변경했던 칼럼만
지정해서 확인할 수도 있다. 조회된 레코드의 변경 대상 칼럼값이 모두 동일하게 변
경되어 있다면 성공적으로 실행된 것이다.
UPDATE table명 SET 변경 대상 칼럼명1 = value1 WHERE 칼럼명2 = value2 ;
(1) 테이블의 전체 칼럼을 조회
SELECT * FROM table명 WHERE 칼럼명2 = value2 ;
(2) 변경 대상 칼럼만 조회
SELECT 변경 대상 칼럼명 FROM table명 WHERE 칼럼명2= value2 ;
3. 삭제 SQL 명령문의 실행 결과 확인
삭제 SQL 명령문 수행 시 WHERE절에 명시했던 특정 조건을 동일하게 삭제 대상
테이블에 데이터 조회 조건으로 적용한다. 데이터 조회 결과에 레코드가 1건도 없으
면 성공적으로 삭제된 것이고, 레코드가 1건 이상 조회된다면 삭제 SQL 명령문이
비정상적으로 실행된 것이다.
DELETE FROM table명 WHERE 칼럼명1 = value1;
(1) 테이블의 전체 칼럼을 조회
SELECT * FROM table명 WHERE 칼럼명1 = value1;
(2) 테이블의 전체 칼럼을 조회
SELECT 임의로 선택한 칼럼명 FROM table명 WHERE 칼럼명1 = value1;
② 레코드 건수를 통한 확인
1. 입력 SQL 명령문의 실행 결과 확인
입력 SQL 명령문 수행 시 테이블의 Primary key 칼럼에 입력한 값을 이용하여 조
회 조건으로 사용한다. Primary key가 2개 이상이면 모두 포함하여 조회 조건을
작성한다. 조회 결과가 입력 SQL 명령문으로 입력한 레코드 개수와 일치하면 성공
적으로 실행된 것이다.
INSERT INTO table명 (Primary Key칼럼명, 입력칼럼명1, 입력칼럼명2)
VALUES (value1, value2, value3); /*1건 입력*/
SELECT COUNT(*) FROM table명 WHERE Primary Key 칼럼명 = value1; /*1건 조회*/
2. 변경 SQL 명령문의 실행 결과 확인
변경 SQL 명령문 수행 시 WHERE절에 명시했던 특정 조건과 변경 칼럼명과 변경
값을 수정 대상 테이블에 데이터 조회 조건으로 적용한다. 조회 결과가 변경 SQL
명령문으로 입력한 레코드 개수와 일치하면 성공적으로 실행된 것이다.
UPDATE table명 SET 변경칼럼명1 = value1 WHERE 칼럼명2 = value2 ; /*5건 변경*/
SELECT COUNT(*) FROM table명
WHERE 칼럼명2 = value2 and 변경칼럼명1 = value1 ; /*5건 조회*/
3. 삭제 SQL 명령문의 실행 결과 확인
삭제 SQL 명령문 수행 시 WHERE절에 명시했던 특정 조건을 동일하게 삭제 대상
테이블에 데이터 조회 조건으로 적용한다. 데이터 조회 결과에 레코드 건수가 0이면
성공적으로 삭제된 것이고, 1건 이상 조회된다면 삭제 SQL 명령문이 비정상적으로
실행된 것이다.
DELETE FROM table명 WHERE 칼럼명1 = value1; /*10건 삭제*/
SELECT COUNT(*) FROM table명 WHERE 칼럼명1 = value1; /*0건 조회*/
③ 실행 결과의 오류 확인
1. 삽입 SQL의 실행 시 오류
(1) Primary Key에 중복된 값을 입력할 경우, unique constraint 위반으로 오류가 발
생한다.
(2) 칼럼의 제약 조건(Not Null, Check, Type, Size 등)의 위배 시 오류 메시지를 확인
하여 조치한다.
2. 변경 SQL의 실행 시 오류
(1) 변경 SQL 명령문으로 Primary Key값을 변경할 경우, 변경하려는 Key값이 이미 존
재한다면 unique constraint 위반으로 오류가 발생한다.
(2 칼럼의 제약 조건(Not Null, Check, Type, Size 등)의 위배 시 오류 메시지를 확인
하여 조치한다.
3. 삭제 SQL의 실행 시 오류
(1) 테이블 간의 참조 관계 설정을 위배할 경우 오류가 발생한다.
(2) 참조 관계에 있는 자식 테이블을 먼저 삭제하지 않고 부모 테이블을 삭제할 경우, 오
류가 발생하므로 삭제 순서를 확인하여 조치한다.
