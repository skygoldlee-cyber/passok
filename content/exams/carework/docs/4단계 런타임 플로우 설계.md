# carework 4단계 런타임 플로우 설계 — care-flow 뷰 정본

> **문서 ID**: DOC-USR-24
> **범위**: exam:carework · 판본: none
> **선행 문서**: 요양보호사 4단계 학습 흐름 설계(DOC-USR-20 계열), CAREWORK_PRACTICE_TOOL_DESIGN.md

## 1. 목적·스코프

시나리오 자산(concepts.json 22개념·scenario_items.json 15문·bank_tags.json 43문)과 이야기형 교재·웹툰 렌더를 **학습 흐름 뷰 `care-flow`**로 연결한다. 개념 단위 4단계 사이클: ① 미리풀기 → ② 이야기·웹툰 → ③ 요약 → ④ 시나리오.

## 2. 화면 상태머신

```
home(개념 선택) → pre(선행 문항 1~2개) → story(서사/웹툰 읽기)
   → summary(핵심 요약+확인) → scenario(시나리오 문항 1~3개)
   → result(채점·보기별 해설) → complete(마스터리 반영) → home
```

- 한 화면 한 상태 — `data-step` 속성으로 전환, 이전/다음 버튼 + 단계 진행바
- story 단계는 표준형 서사 텍스트·웹툰 버블 두 표시를 토글 (webtoon-render.js 재사용)

## 3. 데이터 흐름

| 단계 | 소스 | 역할 |
|---|---|---|
| pre | bank_tags review 문항 (미제시 1~2개) | 선행 진단 — 틀리면 story 힌트 강조 |
| story | 이야기형 MD story:start 슬롯 | 개념 서사 — conceptId↔슬롯 매핑은 concepts.json `storySlots` |
| summary | concepts.json `summary` 필드 | 3~5줄 핵심 (추가 필요 시 개념 레지스트리 확장) |
| scenario | scenario_items role=scenario/review | 5지선다 + per-option rationale |

## 4. 상태·영속화

- `storage.js` scopedKey — `flow_progress_<subj>`: `{ conceptId: { stage, preOk, attempts, mastered, lastSeen } }`
- 마스터리: 기존 `study/fsrs.js` — 정답 시 FSRS 후보 전이, 오답은 review 큐
- `attempts`: `flow_attempts` — `{ conceptId, itemId, choice, correct, ts }` (분석용)
- 미완료 진입 시 stage 이어하기 — 마지막 단계로 자동 복귀

## 5. 등록·게이트

- `practice-registry.js` `careFlow` 핸들러 + `exams.json`/`manifest.json` `careFlow` feature + nav-item `care-flow`
- `html/exams/carework/care-flow.html` 파셜 + `src/exams/carework/views/care-flow.js`
- `tools/check/check_scenario_items.js`에 progress 스키마 필드 검증 추가는 불필요 — 런타임 저장이므로 스키마 아님
- `@spec none` 태그, 도메인 맵·AGENTS·COMMANDS·TRACE 등록 필수

## 6. 구현 순서

1. `concepts.json` — `storySlots`(슬롯 인덱스)·`summary` 필드 보강
2. `care-flow.html` 파셜 + `care-flow.js` 상태머신 + 스텝 렌더
3. story 단계 = loadStoryMd + parseStorySlots 재사용, 웹툰 토글 내장
4. registry·manifest·nav·domain-map·tests·빌드·게이트
